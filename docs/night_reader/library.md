# 圖書館 (library)

## Responsibility
- 擁有書架（Bookshelf）作為已收藏書籍的唯一集合入口：以 `lib/features/bookshelf/bookshelf_provider.dart:18` 的 `BookshelfProvider`（`BookshelfProviderBase + BookshelfLogicMixin + BookshelfUpdateMixin + BookshelfImportMixin`）為狀態根，透過 `lib/core/database/dao/book_dao.dart` 的 `getInBookshelf` / `upsert` / `deleteByUrl` 管理 `isInBookshelf` 生命週期，並以 `lib/core/services/book_storage_service.dart:40` `discardBook` 作為刪除書籍的級聯清理工廠（`ReaderChapterContentDao` / `BookmarkDao` / `DownloadDao` / `ChapterDao` / `BookCoverStorageService`），對外提供排序、拖曳重排、批次下載/補齊/檢查更新、本地匯入與書架匯入/匯出能力。
- 擁有搜尋（Search）作為多書源聯邦搜尋的唯一引擎：以 `lib/features/search/search_provider.dart:47` 的 `SearchProvider` 為 UI 狀態層、`lib/features/search/search_model.dart:63` 的 `SearchModel` 為純邏輯並行引擎、`lib/features/search/models/search_scope.dart:13` 的 `SearchScope` 為範圍契約，串接 `lib/core/engine/web_book/web_book_service.dart:24` 的 `WebBook.searchBookAwait`，完成「關鍵字正規化 → 範圍解析 → 有界並發抓取 → 同源去重 → 跨源重算式合併 → 三級相關度排序 → 結果篩選/排序」全鏈路，並透過 `lib/core/database/dao/search_keyword_dao.dart` / `search_book_dao.dart` 持久化歷史與快取。
- 擁有發現（Explore）作為書源分類瀏覽的容器：以 `lib/features/explore/explore_provider.dart:20` 的 `ExploreProvider` 管理「書源列表 → 展開分類標籤」互動（訂閱 `BookSourceDao.watchDiscoveryPart`），以 `lib/core/engine/explore_url_parser.dart:12` 的 `ExploreUrlParser.parseAsync` 解析分類，以 `lib/features/explore/explore_show_provider.dart:24` 的 `ExploreShowProvider` 管理單分類的分頁書單（`WebBook.exploreBookAwait` + `BookshelfStateTracker`），對外串起 `explore_page.dart` / `explore_show_page.dart` 與搜尋的單源直達。
- 擁有書籍詳情（Book Detail）作為單書資訊中樞：以 `lib/features/book_detail/book_detail_provider.dart:115` 的 `BookDetailProvider` 為聚合根，整合書源狀態判定、書籍資訊/目錄拉取、封面落地（`BookCoverStorageService`）、換源（`SourceSwitchService`）、預下載（`DownloadService`）、匯出（`ExportBookService`）、快取統計/清理與資料編輯，支撐 `lib/features/book_detail/book_detail_page.dart:26` 的詳情頁與 `lib/features/book_detail/source/book_detail_change_source_provider.dart:14` / `lib/features/book_detail/change_cover_provider.dart:12` 兩個專用子域。
- 擁有本地書與書架交換的檔案系統邊界：以 `lib/core/services/local_book_service.dart:21` 的 `LocalBookService` 負責 `TXT` 位移映射（`TxtParser.splitChapters`）與章節按需 `RandomAccessFile` 讀取，以 `lib/core/services/bookshelf_exchange_service.dart:32` 負責 `night_reader.bookshelf` JSON 的匯入/匯出/分享，以 `lib/core/services/export_book_service.dart:13` 負責已快取正文的 `TXT` 匯出，以 `lib/core/services/resource_service.dart:11` / `book_cover_storage_service.dart:14` 負責封面與 `memory://` 資源的落地。
- 擁有圖書領域模型與呈現契約：以 `lib/core/models/book/book_base.dart:3` 的 `BookBase`（36 欄位 + `ReadConfig`，另 2 transient `infoHtml/tocHtml` 不落庫）與 `lib/core/models/search_book.dart:8` 的 `SearchBook`（含 `origins` / `sourceLabels` / `aggregate:56` 合併卡）為記憶體語意，`lib/core/models/search_keyword.dart:3` 的 `SearchKeyword` 為歷史最小單元，三者透過 `lib/core/database/tables/app_tables.dart` 的 Drift 定義與 `lib/core/models/book/book_serialization.dart:28` 的序列化橋接持久化。
- 未來凡涉及：新增書架排序/篩選、調整搜尋合併或範圍策略、變更發現分類解析、修改詳情頁下載/換源/匯出邏輯、新增本地格式、變更封面快取或書架匯出結構，皆由此模組發起。

## Known Risks
- **書架與詳情的狀態雙寫與事件鬆耦合**：`BookshelfProvider:24` 在建構子訂閱 `AppEventBus.upBookshelf` 自動 `loadBooks`，而 `BookDetailProvider:513` 的 `changeSource/setInBookshelf/checkForUpdates`、`BookshelfProviderBase` 的 `reorderBooks` 均 `fire(upBookshelf)`，`BookshelfStateTracker:83` 另訂閱同事件刷新 `Set`；`AppEventBus` 為字串字面量 `EventBus` 無型別負載與去重，若 `BookDao.upsert` 批次匯入（`BookshelfExchangeService:181` 序列 `upsert`）連續觸發多個 `upBookshelf`，`BookshelfProvider.loadBooks` 與 `BookshelfStateTracker.refresh` 會併發多次 `getInBookshelf` 全量查詢，且 `BookshelfStateTracker._initializeGeneration/_refreshGeneration` 的世代號僅在 Tracker 內防競態，不跨 Provider 去抖。
- **`SharedPreferences` 讀寫與 `getIt` 註冊時序**：`BookshelfLogicMixin.loadUiPreferences:8` 直接 `getIt<SharedPreferences>()` 同步讀，而 `setGridView:21` 以 `SharedPreferences.getInstance().then(setBool)` 延遲寫，`SearchScope:149` 的 `_save/load` 與 `SearchProvider._loadPrecisionPreference:270` 的 `precision_search` 亦走 `getInstance()` 每次新實例；若 `injection.dart` 未在 `main.dart:_startApp` 前完成 `SharedPreferences` 單例註冊，首幀 `loadUiPreferences` 拋 `NotRegistered`，但 `BookshelfPage` 與 `SearchPage` 均無降級 UI，僅顯示 `isLoading` 轉圈。
- **有界並發的 `thread_count` 全域共享**：`SearchModel:134` 與 `ChangeCoverProvider:124` 同以 `SharedPreferences thread_count(預設8)` 建 `Pool`，`BookDetailChangeSourceProvider:32` 另以硬編 `6` 建池，三者併發上游皆為 `WebBook.searchBookAwait` 的 `Dio` 請求；`thread_count` 由 `features/settings` 的執行緒數設定頁寫入，無範圍校驗，若被設為 `0` 則 `Pool(0)` 在 `pool.withResource` 拋 `RangeError`，若干書源 `concurrentRate` 與全域 `thread_count` 疊加可能使單站點 `RateLimiter` 限流失效而被封禁。
- **重算式合併的作者缺失語意脆弱**：`SearchModel._rebuild:249` 的三分支（`=1/0/≥2`）依賴 `normalizeSearchText`（全半角+去空白+小寫）後的 `nameKey/authorKey`，對 `author` 為 `null/''` 與 `'未知'` 在不同書源不一致時，`authorlessByName` 的安置會在每輪 `_mergeItems` 後重算而抖動（唯一作者時併入、出現第二作者時退出成作者不詳卡），`SearchBookDao.insertList` 持久化的原始書若含 `author=''` 與 `author='某某'` 的混合同名書，結果卡數會在增量到達順序下非確定性跳變。
- **同源去重的鍵漂移**：`SearchModel._isSameSourceDuplicate:40` 以 `origin` 相同 + `bookUrl` 小寫去空白相等判定，否則回退 `name+author` 正規化；`BookDetailChangeSourceProvider._resultKey:271` 另以 `origin\nbookUrl` 大小寫敏感判定，兩處不一致；`SearchBook.bookUrl` 在 `WebBook` 側已 `getAbsoluteURL` 正規化，但大小寫/尾 `/`/`?` 差異仍視為不同鍵，同一書源分頁重複會產生重複原始條目，進而在 `_rebuild` 中同組多計 `origins.length`。
- **搜尋的取消與超時分層**：`SearchModel.cancelSearch:369` 僅 `cancelToken.cancel` 並置 `_isCancelled=true`，但 `Pool.withResource` 已排入的 `Future` 仍會在 `_searchSingleSource:144` 的 `if(_isCancelled) return` 後早退，而 `WebBook.searchBookAwait` 內的 `Dio` 請求已取消卻仍在 `timeout(30s)` 競態中，`SearchProvider.stopSearch:358` 將 `_isSearching=false` 且 `currentSource='已停止'`，但 `onSearchProgress` 的後續回調仍可能以舊 `currentSourceName` 覆蓋狀態。
- **探索的世代號與快取鍵分離**：`ExploreProvider:32` 以 `_kindsRequestGeneration` + `_latestKindsRequestByCacheKey` + `_cacheKeyForSource(url\nexploreUrl)` 三層防競態，`_reloadFromSnapshot:95` 在快照重建時若舊展開源的 `cacheKey` 變化（`exploreUrl` 被書源編輯改寫）則刪舊進新並重載；但 `ExploreUrlParser` 另有 `AppCache('explore')` 以 `md5(jsonEncode([bookSourceUrl, exploreUrl]))` 為 key 的第二層快取，兩層 key 派生一致但生命週期分離（Provider 記憶體 vs 磁碟快取），`refreshKindsCache:269` 的 `clearCache` 與 `kindsCache.remove` 需雙清，漏清任一層會使舊分類幽靈命中。
- **詳情的閱讀進度保留清單漂移**：`BookDetailProvider.checkForUpdates:718` 與 `BookshelfUpdateMixin.checkBookUpdate:98` 均手寫「保留 `group/order/readerAnchorJson/visualOffsetPx/charOffset/chapterIndex/durChapterTitle/canUpdate/customCover/customIntro`」等 10+ 欄位的白名單，兩處不一致（`checkBookUpdate` 另保留 `syncTime/chapterIndex/charOffset/visualOffsetPx/readerAnchorJson`，`checkForUpdates` 另保留 `readConfig/customTag`），若 `BookBase` 新增 `syncTime/order` 以外的進度欄位（`readerAnchorJson` 已在 `BookDao.updateProgress:97` 被限幅 `[-120,120]` 而 `book_serialization:23` 為 `[-80,120]`），新欄位會在更新後被 `getBookInfo` 回來的空值覆蓋而丟失。
- **封面落地的雙路徑與 key 分叉**：`BookCoverStorageService:73` 的 `bookStorageKey=sha1(origin\nbookUrl)` 與 `ResourceService:42` 的 `base64Url(key)` 為兩套鍵派生，`ensureBookCoverStored:22` 與 `ChangeCoverProvider.search:159` 的 `searchBooks(name)` 按書名搜尋而非按 `bookUrl`，搜到的 `coverUrl` 以 `sha1(source)` 另算檔名；`BookBase.getDisplayCover:33` 以 `customCoverLocalPath > customCoverUrl > coverLocalPath > coverUrl` 四級回退，`BookDetailProvider.updateCover:631` 先 `ensureDisplayCoverStored` 再 `upsert`，但 `BookStorageService.discardBook:46` 以 `bookStorageKey` 刪整目錄，若 `origin` 在換源後改變而舊 `bookUrl` 未變，舊目錄將孤兒化且 `getBookAssetSize:68` 仍按新 `key` 統計而顯示為 0。
- **本地書的單例 `RandomAccessFile` 與 `compute` 隔離**：`LocalBookService:26` 的 `_txtAccessFile/_txtAccessFilePath/_txtReadChain` 為單例狀態，`importBook:31` 以 `compute(TxtParser.splitChapters)` 在背景 isolate 解析，而 `getContent:72` 的 `_queueTxtRead` 以 `Completer` 鏈序列化讀切片，兩者共享 `_txtAccessFile` 卻在不同 isolate（`compute` 為獨立 isolate）不共享 `RandomAccessFile` 句柄，`_getTxtAccessFile:118` 僅在主 isolate 緩存，若連續對不同 `path` 的書 `getContent`，中途 `close` 舊句柄可能與排隊中的 `read` 競態，`start/end` 的 `file.length` 校驗（`local_book_service.dart:85`）與 `TxtParser._buildByteOffsets` 的 `bomLength` 偏移若不一致會拋 `本地 TXT 索引無效`。
- **匯出與下載的正文鍵不一致**：`ExportBookService:39` 的 `contentKey=sha1(origin\nbookUrl\nchapterUrl)` 與 `BookDetailProvider._refreshCacheStatus:825` 的 `getEntriesByBookUrls→origin==book.origin && isReady && hasDisplayContent` 過濾一致，但 `DownloadService` 的 `DownloadDao` 以 `bookUrl+chapterIndex` 為鍵，三處鍵空間不同（`chapterUrl` vs `index`），`BookDetailProvider.queueDownloadMissing:376` 以 `storedChapterIndices` 的 `Set<int>` 判缺章，而 `ExportBookService.fetchMissingRemote:29` 以 `ReaderChapterContentDao.getEntry(contentKey)` 判缺正文，索引與 URL 的缺口不一致會使「下載完整」與「匯出完整」顯示分歧。
- **書架交換的無版本化與冪等假設**：`BookshelfExchangeService:62` 的 `payload version:1` 僅為提示，`importFromText:110` 對 `Map` 取 `books/chapters/sources/chapterContents` 四段時以 `jsonDecode` 全量入記憶體，超大匯出（千本×萬章）在低端機 `readAsString+JsonEncoder.withIndent` 可能 OOM，`_parseChapters:213` 將 `content` 置 `null` 避免誤寫正文，但 `chapterContents` 的 `ReaderChapterContentEntry` 以 `contentKey` 為主鍵，`upsertEntry` 會覆蓋同 `origin+bookUrl+chapterUrl` 的已快取正文且無 `updatedAt` 衝突檢測。
- **測試覆蓋的缺口**：此模組僅 `SearchBook.aggregate/migrateTo/TxtParser` 有直接單測，`SearchModel._rebuild` 的三分支與 `BookshelfProvider._sortBooks` 的 `addedTime/updateTime` 回退鏈、`ExploreProvider` 的世代號競態、`BookDetailProvider` 的 `_storeDisplayCover` 非同步副作用無對應 `Widget` 測試，`SearchScope` 的分組退回全量與 `BookshelfStateTracker` 的 `AppEventBus` 訂閱在 `flutter test` 中需手動 `getIt` 樁 `BookDao/SearchBookDao`，否則 `getIt<BookDao>()` 拋 `NotRegistered`。

## Boundaries
- **書架以 `BookDao.getInBookshelf` 為唯一集合**：`books` 以 `isInBookshelf==true` 過濾並按 `BookshelfSortMode` 記憶體排序，`order` 僅在 `custom` 模式可拖曳寫回，禁止在 DAO 層以 `GROUP BY name,author` 合併落盤，否則每源獨立的 `origin/originName/variable/tocUrl` 與 `Book.group` 位元分組同時丟失；`BookStorageService.discardBook:40` 的六表級聯為硬性契約，刪除書籍禁止僅 `bookDao.deleteByUrl` 而不清理 `ReaderChapterContent/Download/Bookmark/Chapter/Cover`。
- **`SearchBook` 的合併僅在呈現層**：`SearchModel._rawBooks` 保留每源原始條目，`_searchBooks` 為 `SearchBook.aggregate` 生成的代表卡（`late final Set origins` + `Map originNames`），`SearchBookDao` 持久化的仍是原始條目，禁止將合併卡以 `SearchBook` 寫回 `search_books` 表（`aggregate` 的 `origins` 為記憶體聚合，無對應欄位），否則 `BookDetailChangeSourceProvider` 的 `getSearchBooks(name,author)` 快取初顯會讀到污染的聚合卡。
- **Drift 主鍵與 `EmptyStringConverter` 為相容性邊界**：`Books.bookUrl` / `Chapters.url`（`app_tables.dart:163`）為 `primaryKey`，`Books.tocUrl/origin/author` 等為 `nullable().map(EmptyStringConverter)` 使 Dart 層永非空而 SQLite 層為 `NULL`，`Book.fromJson:80` 的 `??''` 與 `BookSerialization.toInt/toVisualOffsetPx` 寬鬆解析為匯入容錯，禁止將其收緊為 `text().withDefault('')` 非空，否則舊備份 `BookshelfExchangeService.importFromText` 的缺欄 JSON 會拋 `NOT NULL constraint failed`。
- **`SharedPreferences` 的 key 字面量為跨版本契約**：`PreferKey.bookshelfSort` / `bookshelf_is_grid` / `search_scope` / `thread_count` / `precision_search` 與 `SearchScope:16` 的 `_prefKey='search_scope'` 均為持久化契約，重命名需提供 `prefs.getString(oldKey)`→`setString(newKey)` 遷移，`SearchScope.updateAll/removeGroup` 與 `BookshelfLogicMixin.setGridView/setSortMode` 的寫入必須與讀取端同 `getInstance()` 作用域，避免多 `SharedPreferences` 實例的寫入丟失。
- **書源能力以 `isSearchEnabledByRuntime/isReadingEnabledByRuntime/canParticipateInDiscovery` 三判定為閘**：`SearchScope.getBookSources:83` 與 `BookDetailChangeSourceProvider._loadEnabledSources:216` 依 `isSearchEnabledByRuntime` + `bookSourceUrl!=origin` 過濾，`ExploreProvider._reloadFromSnapshot:105` 依 `canParticipateInDiscovery` 過濾，`BookDetailProvider._loadBookInfo/_loadChapters/_prepareStorageDownloadQueue` 依 `isReadingEnabledByRuntime` 阻斷網路；禁止在呼叫側繞過此三判定直調 `WebBook`，否則停用或 `loginCheckJs` 失敗的書源會污染搜尋結果與目錄。
- **發現的快取雙層不可單清**：`ExploreProvider._kindsCache`（記憶體）與 `ExploreUrlParser` 的 `AppCache('explore')`（磁碟，`md5(bookSourceUrl+exploreUrl)`）為兩層快取，`refreshKindsCache:269` 必須 `kindsCache.remove` + `ExploreUrlParser.clearCache` 雙清，且 `bookSourceGroup/customOrder/exploreUrl` 變動後 `SearchScope`/`ExploreProvider.groups` 的 `split([,，])` 需同步更新，禁止僅清一層而使舊分類在另一層幽靈命中。
- **換源與遷移的進度對齊為顯式策略**：`BookLogic.migrateTo:14` 的 `_getDurChapter` 僅對章標題同名 / `第N章` 序號 / 百分比估算三策略，`SourceSwitchService` 的 `resolveSwitch` 在 `BookDetailProvider.changeSource:487` 被呼叫時傳 `targetChapterIndex/Title` 與 `validateTargetContent=true`，`checkForUpdates` 的章節重編號（`book_detail_provider.dart:711`）與 `BookshelfUpdateMixin.checkBookUpdate:88` 的 `index` 重寫為硬性契約，禁止在外層自行 `book.chapterIndex = newIndex` 而不經 `migrateTo` 或 `resolveSwitch`，否則 `reader_v2` 的 `visualOffsetPx/readerAnchorJson` 錨點失配。
- **本地書的位移以 `start/end` 物理位元組為準**：`TxtParser` 的 `start/end` 含 `bomLength`，`LocalBookService.getContent:82` 以 `RandomAccessFile.setPosition(start).read(end-start)` 切片並 `decodeWithCharset(charset)`，`Book.charset` 為該書後續讀取的唯一依據，改 `charset` 必須重跑 `splitChapters` 重建 `Chapters.start/end`，禁止僅改 `Book.charset` 而不重建位移，否則 `getContent` 在 `BIG5/GBK` 下亂碼或 `start>=fileLength` 判無效。
- **下載與正文的鍵空間分離**：`ReaderChapterContentDao.contentKey=sha1(origin\nbookUrl\nchapterUrl)` 為正文唯一鍵（`reader_chapter_content.dart:16`），`ChapterDao` 以 `bookUrl+index` 索引章節，`DownloadDao` 以 `bookUrl` 關聯任務，三者 `contentKey`/`bookUrl+index`/`bookUrl` 不可互換；`BookDetailProvider._storedChapterIndices:799` 的 `storedChapterIndices(book)` 與 `ExportBookService` 的 `getEntry(contentKey)` 均以 `origin==book.origin && isReady && hasDisplayContent` 為有效快取，換源後 `origin` 改變即視為快取失效，禁止將舊源正文誤判為新源可用。
- **資源與封面的落地路徑為硬約束**：`AppStoragePaths.bookAssetDir(sha1(origin\nbookUrl))/shareExportDir/resource_cache` 三目錄經 `path_provider` 與 `_validatePathComponent` 防穿越，`BookCoverStorageService.bookStorageKey:73` 與 `ResourceService._resourceFile:42` 的鍵派生不可隨意改為 `bookUrl` 明文，改鍵需提供舊目錄 `delete(recursive:true)` 遷移，否則舊封面與 `memory://` 資源永久孤兒化；`AppCache` 的 `maxSize 50MB/maxCount 1M` 與 `WebBook` 的 `_maxTocPages=100/_maxContentPages=20/_pageConcurrency=4` 為熔斷器，調大需評估 `Dio` 超時與 `ChapterDao` 批量寫入壓力。
