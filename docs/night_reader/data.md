# 資料持久化 (data)

## Responsibility
- 擁有全應用結構化資料的唯一真相來源：以 `lib/core/database/app_database.dart:95` 的 `AppDatabase extends _$AppDatabase` 為單例根，透過 Drift ORM 管理 SQLite 檔案 `databases/night_reader.db`（`AppDatabase.getDatabasePath:229`），對外暴露 20 張表與 20 個 DAO 的一致查詢/寫入契約，並以 `schemaVersion:102` 與 `MigrationStrategy:105` 負責建表、效能索引與版本遷移（含 `inkpage_reader.db → night_reader.db` 一次性重命名 `app_database.dart:244`）。
- 擁有領域模型與儲存結構的映射權：`lib/core/models/*`（`book.dart` / `chapter.dart` / `book_source.dart` / `bookmark.dart` / `replace_rule.dart` / `search_book.dart` 等）定義記憶體語意，`lib/core/database/tables/app_tables.dart:164` 的 `@UseRowClass` Table 定義決定落盤欄位、主鍵、預設值與 `TypeConverter`（`EmptyStringConverter` / `ReadConfigConverter` / `SearchRuleConverter` 等 8 個轉換器），兩者透過 `*.g.dart` 生成程式碼綁定。
- 擁有本地書與快取的檔案系統持久化：`lib/core/local_book/txt_parser.dart:24` 的 `TxtParser.splitChapters` 負責 TXT 實體位移映射與章節切塊；`lib/core/storage/app_cache.dart:14` 的 `AppCache` 提供磁碟快取（50 MB / 1M 檔）與 TTL 過期；`lib/core/storage/app_storage_paths.dart:8` 的 `AppStoragePaths` 集中所有 `documentsDir / temporaryDir` 下的子路徑；`lib/core/constant/prefer_key.dart:2` 的 `PreferKey` 集中 `SharedPreferences` 字串契約（227 行、195 key）。
- 未來凡涉及：新增/修改表結構、DAO 查詢、模型欄位、本地書格式支援、快取或檔案路徑、全域偏好 key，皆由此模組發起。

## Known Risks
- **Schema 版本與遷移單薄**：`AppDatabase.schemaVersion:102` 僅 `2`，`onUpgrade` 只有 `if(from<2) _createPerformanceIndexes`，無 `m.addColumn/migrate` 的欄位級遷移；新增非空欄位若未給 `withDefault`，舊庫 `m.createAll` 外的增量升級會因 `NOT NULL` 失敗。`_performanceIndexStatements:126` 的 25 個索引僅在 `onCreate/onUpgrade` 執行，已落盤庫若在中途版本跳過 `from<2` 分支需手動補 `CREATE INDEX IF NOT EXISTS`，否則 `database_optimization_test.dart:12` 的熱查詢（`isInBookshelf+durChapterTime` / `bookUrl+index` / `origin+bookUrl+status`）退化為全表掃描。
- **生成程式碼與 Drift 版本耦合**：`app_database.g.dart` / `dao/*.g.dart` 由 `drift_dev` 生成，`pubspec.yaml:27` 的 `drift ^2.34.3` 與 `drift_dev ^2.34.5` 小版本不一致已可致 `BuildStep` 報 `Mismatched drift version`；手改 `*.g.dart` 會在下次 `build_runner` 被覆蓋，且 `AppDatabase.forTesting:99` 的 `QueryExecutor` 簽名隨 Drift 大版本變更而破壞測試。
- **空字串與 null 的語意混淆**：`EmptyStringConverter:25` 的 `fromSql:28` 回 `''`、`toSql:30` 在 `value.isEmpty` 時回 `null`，使 `Books.tocUrl/origin/author` 等 `text().nullable().map(EmptyStringConverter)` 欄位在 Dart 層永為非空 `String`，但 SQLite 層為 `NULL`；`Book.fromJson:83` 以 `json['tocUrl']??''` 與 `BookSerialization.toInt` / `toVisualOffsetPx` 做寬鬆容錯，導致「缺欄」與「空字串」在匯入/匯出（`BookshelfExchangeService`）中不可區分，備份還原可能把有意清空的 `customIntro` 還原為 `null` 並被轉為 `''`。
- **位元組位移的編碼陷阱**：`TxtParser._buildExactByteOffsets:159` 僅精確支援 `UTF-8/UTF-16LE/BE/GBK/GB2312/GB18030`（`normalized:166`），其餘編碼（`BIG5/EUC-KR/Shift_JIS`）回退 `encodeWithCharset(substring).length` 逐段累加，對含 surrogate pair（emoji）的文本以 `codeUnits` 計長（`_safeChunkEnd:346` 僅保切塊邊界不撕裂 pair，不保中段 emoji 的 4 位元組對應），`visualOffsetPx` 限幅在 `BookDao:97` 為 `[-120,120]` 而 `book_serialization.dart:21` 為 `[-80,120]`，兩處不一致會使同一書籍在進度同步時 `copyWith` 後寫庫被二次 clamp。
- **AppCache 的併發與配額風險**：`AppCache._trimCache:154` 以 `listSync().whereType<File>()` 同步列舉 + `await file.stat()` 異步統計，若 `maxSize=50MB` 的快取目錄含大量小檔（`maxCount=1M`），單次 `put` 可能觸發數千次 `stat` 與排序，阻塞 UI isolate；`_isTrimming` + `_trimCompleted` 的 `while(_isTrimming) await future` 僅在 Dart 層串列化，若多個 `AppCache` 實例（不同 `cacheName`）指向同一 `temporaryDir` 子路徑，跨實例併發 `put` 仍可能交錯 `delete` 同一檔。`_isDueBytes:108` 以 `int.parse(info[0])` 解析 `saveTime`，若檔首 13 字元被使用者或備份工具改寫會 `catch` 後視為不過期而永久駐留。
- **PreferKey 字面量契約無型別保護**：`PreferKey:2` 的 195 個 `static const String` 僅為字串常量，`SharedPreferences.getString(PreferKey.foo)` 的讀寫無編譯期型別或版本化遷移；`app_config.dart` 與 `SettingsProvider` 僅 `_migrateLegacySettings:206` 處理 `ttsSource` 單例外，其餘 key 更名即孤兒化（如 `cPrimary='colorPrimary'` 與 `cNPrimary='colorPrimaryNight'` 的明/暗兩套）。`ReaderSettingKeys` 與 `PreferKey.reader*` 並存，混用易寫入錯誤命名空間。
- **書架分組的位元遮罩隱式契約**：`Book.group` 為 `int` 位元遮罩，`BookGroup.idAll=-1`（`0xFFFFFFFF`）在 `BookDao.getInGroup:63` 特判為全量，`idRoot=-100/idLocal=-2` 等負值若被誤傳入 `bitwiseAnd` 會因符號擴展匹配非預期書籍；`group==0` 另分支為「無分組」，與 `group` 的 `0` 位同時表示「未分組」與「分組 0」，語意重疊。`BookGroup` 的 `order` 欄位與 `Books.order/originOrder` 同名但分屬不同表，索引 `idx_book_groups_order` 與 `idx_books_bookshelf_recent` 需分開維護。
- **正文狀態機的沉默失敗**：`ReaderChapterContentDao.saveFailure:186` 將失敗訊息同時寫入 `content` 與 `failureMessage`，`hasReadyContent:113` 以 `content IS NOT NULL AND content!=''` 判存活，若上游 `WebBook` 以空字串表示「暫無正文」會被誤判為未快取而重複抓取；`getTotalContentSize:222` 僅統計 `status=1` 的 `LENGTH(content)`，`failed` 條目的錯誤訊息不計入配額，可能使儲存用量顯示偏小。

## Boundaries
- **不替 User 合併正文，不改書源去重語意**：`ReaderChapterContents` 以 `(origin, bookUrl, chapterUrl)` 三元組為鍵，`contentKey` 的 `sha1` 派生禁止改為僅 `bookUrl+index`，否則換源同索引章節會互覆；`SearchBook.origins:30` 的 `Set<String>` 與 `aggregate:56` 的「有封面優先 + originOrder 最小」代表卡規則為呈現層唯一去重，禁止在 DAO 層以 `GROUP BY name,author` 合併落盤，否則每源獨立的 `variable/tocUrl` 會丟失。
- **Drift 表的 nullable 與預設值不可隨意收緊**：`Books.tocUrl/origin:167` 等 `nullable().map(EmptyStringConverter)` 與 `Books.type/group:187` 的 `withDefault(0)` 為舊備份相容而設，改為 `text()` 非空或移除 `withDefault` 會使 `Book.fromJson` 的寬鬆匯入在 `insertAllOnConflictUpdate` 時拋 `NOT NULL constraint failed`；`Chapters.url:234` 為主鍵，禁止改為自增 `id`，否則 `Chapter.getFileName:140` 的 `index+md5(title)` 檔名契約與 `DownloadTask` 的 `bookUrl+chapterIndex` 關聯同時失效。
- **索引與 LRU 上限為硬約束**：`_performanceIndexStatements:126` 的 25 個 `IF NOT EXISTS` 索引與 `AppCache:17` 的 `maxSize=50MB / maxCount=1M` 為效能/配額邊界，禁止為「更快寫入」而刪索引，或為「更多快取」而無界調大 `maxCount`；`TxtParser` 的 `_maxChapterChars=50000 / _fallbackChunkChars=30000` 為「超長章單章切塊」熔斷，調大會使 `Chapters` 單條 `start/end` 跨度過大而回填 `Book.totalChapterNum` 失真。
- **路徑與編碼的單向契約**：`AppStoragePaths` 的 `documentsDir/temporaryDir` 僅封裝 `path_provider`，禁止在上層硬編 `'/data/data/...'` 絕對路徑；`TxtParser` 的 `initialByteOffset=bomLength:30` 與 `_utf8UnitAt:229` 的 BOM/續位元組判定為唯讀解碼路徑，`book.charset` 寫入後即為該書後續 `start/end` 解釋的唯一依據，改 `charset` 必須重跑 `splitChapters` 重建位移，禁止僅改 `Book.charset` 而不重建 `Chapters`。
- **PreferKey 與快取 key 的字面量不可重命名**：`PreferKey` 的字串值（如 `language/themeMode/userAgent/replaceEnableDefault`）與 `AppCache` 的 `sha256(key)` 檔名、`ExploreUrlParser` 的 `md5(bookSourceUrl+exploreUrl)` 快取 key 為跨版本持久化契約，重命名需提供 `SharedPreferences` 遷移與舊檔 `delete`/`rename`，否則舊用戶資料與快取永久孤兒化。
- **測試以 Drift 記憶體庫為準**：所有 `test/core/database/*` 與 `test/core/models/*` 以 `AppDatabase.forTesting(NativeDatabase.memory())` 為基準，禁止在測試中依賴真實檔案路徑 `databases/night_reader.db` 或 `getApplicationSupportDirectory` 的平台實作；`test/core/local_book/txt_parser_test.dart` 的位移斷言以 `EncodingDetect` 的實際 `bomLength` 為準，禁止為通過測試而在 `TxtParser` 中寫死 `UTF-8` 快路徑。
