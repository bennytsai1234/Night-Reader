# 規則引擎 (engine)

## Responsibility
- 擁有 Legado 書源規則的完整解析與執行語意：以 `lib/core/engine/analyze_rule.dart:22` 的 `AnalyzeRule` 為總控，串接 `lib/core/engine/analyze_rule/analyze_rule_base.dart:16` 的 `AnalyzeRuleBase` 狀態容器、`lib/core/engine/analyze_rule/analyze_rule_string.dart:11` / `analyze_rule_element.dart:10` / `analyze_rule_regex_helper.dart:5` 的三條解析路徑，並透過 `lib/core/engine/js/js_engine.dart:27` 的 `JsEngine` 對規則內嵌 JS（`@js:`/`<js>`/`{{js}}`/`@put`/`@get`）做同步與異步執行。
- 擁有 URL 規則到 HTTP 請求的編譯與發射：`lib/core/engine/analyze_url.dart:17` 的 `AnalyzeUrl` 負責 `header` 注入、`@js:`/`<js>` 評估、`{{key}}`/`{{page}}` 替換、`",{"method":"POST"}` 選項解析、相對路徑 `baseUrl` 解析、charset 感知解碼與 `dio` 重試/`CookieStore`/`RateLimiter`/`HeadlessWebView` 分流。
- 擁有四種內容選取後端的等價封裝：`lib/core/engine/parsers/analyze_by_css.dart:8`（CSS/`@` 鏈）、`lib/core/engine/parsers/analyze_by_xpath.dart:11`（XPath + CSS 兼容層）、`lib/core/engine/parsers/analyze_by_json_path.dart:9`（JsonPath）、`lib/core/engine/parsers/analyze_by_regex.dart:5`（正則）皆對外暴露 `getString`/`getStringList`/`getElements`/`getElement` 契約，並由 `lib/core/engine/rule_analyzer.dart:13` 的 `RuleAnalyzer` 以 `&&`/`||`/`%%`/`@` 對規則做算子級切割。
- 擁有書源業務的抓取編排：`lib/core/engine/web_book/web_book_service.dart:24` 的 `WebBook` 以 `searchBookAwait`/`exploreBookAwait`/`getBookInfoAwait`/`getChapterListAwait`/`getContentAwait` 五個靜態入口整合 `AnalyzeUrl` + `BookListParser`/`BookInfoParser`/`ChapterListParser`/`ContentParser`，並處理 `loginCheckJs`、`isRedirect`、`PermissionLimit/LoginRequired` 攔截、目錄/正文多頁 daisy-chain 與 `%%` 並發、去重、排序與 `formatJs` 二次加工；`lib/core/engine/web_book/complete_content_fetcher.dart:18` 的 `CompleteContentFetcher` 另提供「完整性優先、任一子頁失敗即整章失敗」的嚴格正文抓取變體。
- 擁有發現頁分類的規則入口：`lib/core/engine/explore_url_parser.dart:12` 的 `ExploreUrlParser` 以 `parse`/`parseAsync` 支援靜態 `title::url`、`&&`/`\n` 列表、JSON 陣列/物件與 `<js>`/`@js:` 動態生成，並以 `AppCache` + `EncoderUtils.md5Encode` 做 JS 結果快取與串列化防併發。
- 擁有 JS 與 Dart 的雙向橋：`lib/core/engine/js/js_engine.dart:27` 封裝 `flutter_js`（QuickJS）`JavascriptRuntime`，`lib/core/engine/js/js_extensions_base.dart:24` 建立 `__asyncCall`/`__resolvePending`/`__ruleDone` Promise bridge，`lib/core/engine/js/js_extensions.dart:34` 注入 `java`/`cookie`/`cache`/`source`/`book`/`chapter` 等全域物件，`lib/core/engine/js/async_js_rewriter.dart:30` 在源码級注入 `(await ...)`，`lib/core/engine/js/js_rule_async_wrapper.dart:18` 以 async IIFE + `injectFinalReturn` 把最後表達式變 `return` 並在 20s 超時內回送 `__ruleDone`。
- 擁有輔助能力：`lib/core/engine/book/book_help.dart:7` 的書籍快取路徑與 `formatBookName`/`formatBookAuthor` 清洗；`lib/core/engine/reader/chinese_text_converter.dart:3` 的簡繁互轉（委派 `ChineseUtils.s2t/t2s`）；`lib/core/engine/app_event_bus.dart:4` 的 `EventBus` 單例（`upBookshelf`/`checkSource` 等 15+ 事件名）作為跨 Provider 的鬆耦合通知。

## Known Risks
- **JS 引擎的可用性與 isolate 約束**：`lib/core/engine/js/js_engine.dart:55` 以 `getJavascriptRuntime(xhr: !isNonInteractive)` 初始化，背景 `Isolate`（`SourceValidationContext.isNonInteractive=true`）下 `flutter_js` 的 `enableFetch` 會因缺少 `ServicesBinding` 崩潰，故強制 `xhr:false`；`main.dart` 的 `runZonedGuarded` 與 `WebBook` 註解「不使用 `Isolate.run`，`flutter_js` FFI 無法跨 isolate」為現行妥協，導致 `getChapterListAwait`/`getContentAwait` 的解析無法卸載，長列表仍在 UI isolate 執行；`_isAvailable=false` 時 `lib/core/engine/js/js_engine.dart:589` `_mockEvaluate` 僅識別 `key/page/result/baseUrl` 四個字面量，其餘皆回 `JS_ERROR: Library not available`，若錯誤被 `ExploreUrlParser._looksLikeJsError` 誤判為正常分類會混入 `ERROR:` 假數據。
- **Promise bridge 的超時與資源洩漏**：`lib/core/engine/js/js_extensions_base.dart:52` 的 `_pendingRuleCalls` 與 `lib/core/engine/js/js_engine.dart:36` 的 `_resolvedJsLibCache/_pendingJsLibCache` 為 `static` session 級快取，`ttfCache/fontReplaceCache` 存字型二進位（數百 KB/項），若批量校驗未在收尾呼叫 `JsEngine.clearCaches`/`JsExtensionsBase.clearCaches`（見 `js_engine.dart:42` 註解）會在長會話中持續膨脹；`evaluateAsync` 的 20s 硬超時（`lib/core/engine/js/js_engine.dart:154`）對慢速 `java.ajax` 可能誤判，且超時後僅 `cancelRuleCall` reject Dart `Future`，JS 側 `__lr.pendingResolvers` 仍殘留直至下次 `__resolvePending` 覆蓋；`HeadlessWebViewService._tail`（`lib/core/engine/web_book/headless_webview_service.dart:17`）以 `Completer` 鏈串列化多個 `getRenderedHtml`，若某次 `onPageFinished` 永不觸發，整條鏈阻塞 30s。
- **字串與正則的高頻快取一致性**：`AnalyzeRuleBase.stringRuleCache` 與 `regexCache` 為 `LruMap(maxSize:200)`（`lib/core/engine/analyze_rule/analyze_rule_base.dart:46`），`SourceRule` 實例被跨呼叫快取，`lib/core/engine/analyze_rule/analyze_rule_support.dart:145` 註解強調 `makeUpRule/makeUpRuleAsync` 不可 mutate `this.rule` 否則污染快取；`replaceRegexLogic` 的 `rule.replaceRegex` 若為非法正則僅 `return result`（`lib/core/engine/analyze_rule/analyze_rule_regex_helper.dart:53`），而 `AnalyzeByRegex._buildRegExp`（`lib/core/engine/parsers/analyze_by_regex.dart:6`）對 `(?ims)` 行內旗標的處理與 `AnalyzeRuleRegexHelper` 的 `replaceRegexLogic` 中「無 DOTALL/multiline」預設存在語意分歧，`##` 內外的旗標可能不一致。
- **HTML/JSON 內容的型別歧義**：`lib/core/engine/analyze_rule/analyze_rule_support.dart:276` 的 `stringifyRuleResult` 優先檢查 `Map` 內的 `__html/outerHtml/html`，`isJsonLikeRuleInput` 以 `startsWith('{','[')` 判 JSON，`AnalyzeRuleSupport.buildJsonFallbackRule` 對裸 `field` 補 `$.field`，三者共同決定 `AnalyzeRuleString:74` 的「CSS 失敗→JsonPath fallback」路徑；截斷 HTML（如 `AnalyzeByXPath._prepareHtml` 對 `</td>`/`</tr>` 的 `<table>` 包裝）與 `AnalyzeByCssBase._parseRootElement` 對 `<!doctype>/<html>/<body>` 完整文檔與 fragment 的兩套解析，會讓同一規則在不同 `content` 型別下結果分叉，難以在測試外復現。
- **URL 編譯的順序敏感性**：`AnalyzeUrl._replaceKeyPageJs` 中 `{{key}}` 的 GBK 編碼依賴 `_detectCharset` 從尾部 `,{charset...}` 提前嗅探（`lib/core/engine/analyze_url.dart:330`），若書源把 `charset` 寫在 `header` 而非 URL options，`_encodeKey` 會回退 `Uri.encodeComponent` 導致 GBK 站點搜尋亂碼；`_resolveRelativeBaseUrl` 以 `baseUrl→source.getKey()` 遞補，`source.getKey()` 可能是非 URL 的 `bookSourceUrl`（如 `https://example.com` 缺尾 `/`），`Uri.resolve` 對 `../` 的解析會錯；`_consumePrefetchedResponseBody` 的超集匹配（`lib/core/engine/analyze_url.dart:762` 以 `queryParameters.every`）在 `candidate` 含多餘參數時會錯誤命中。
- **WebBook 的排序與去重隱式契約**：`WebBook.getChapterListAwait` 同時存在兩處 `reversed`——先依 `isReverse`（`-` 前綴）對書源逆序做一次反轉（`lib/core/engine/web_book/web_book_service.dart:259`），再依 `book.readConfig.reverseToc` 做二次反轉（同檔 `321`），兩段註解互指對方，改任一旗標易使正/倒序整體翻轉；相鄰同名摺疊（同檔 `279`）僅比 `title` 相等，不比 `url`/`wordCount`，不同卷同名「第一章」若因書源分頁邊界恰好相鄰會被誤刪；`BookListParser` 以 `(name,author,bookUrl)` 去重（`lib/core/engine/web_book/book_list_parser.dart:133`）但 `bookUrl` 已被 `getAbsoluteURL` 正規化，大小寫/尾 `/` 差異仍視為不同條；`_fillWordCount` 以 `getFileName()` 為鍵回填，若書名變更導致檔名改變則回填失效但無提示。
- **發現與書資訊解析的容錯裂縫**：`ExploreUrlParser._resolveAsync` 對 `jsTimeout` 的 `timeout` 在超時後 `rule?.dispose()` 但不取消 `evaluation` Future，`JsEngine` 仍占資源至 20s；`_sanitizeRelaxedJson` 僅去掉 `,]`/`,}` 尾逗號（`lib/core/engine/explore_url_parser.dart:329`），對單引號/未引號 key 的寬鬆 JSON 仍依賴 `BookSourceSerialization.parseRule` 的二次清洗，兩層清洗規則未對齊；`BookInfoParser._resolveFallbackTocUrl` 僅識別 `章节目录/章節目錄/目录/目錄` 四種文本，非中文站點或按鈕以圖標呈現的目錄入口無法啟發式補齊，`tocUrl==bookUrl` 時覆寫 `tocHtml` 導致首頁目錄複用詳情頁 HTML，可能與首頁 `nextTocUrl` 的 `baseUrl` 期待不一致。
- **事件與持久化的漂移**：`AppEventBus` 為裸 `EventBus` 單例（`lib/core/engine/app_event_bus.dart:9`），事件名為字面量字串（`upBookshelf/bookshelfRefreshStart/searchResult/sourceChanged` 等）無枚舉或載荷型別，拼錯僅在運行時靜默丟失；`ExploreUrlParser` 的 `AppCache('explore')` 以 `md5` 為 key 無版本，書源 `exploreUrl` 語意變更後舊快取仍命中，需手動 `clearCache`；`RuleBigDataService` 對 >5000 字元變數以 `md5(bookUrl)/md5(key).txt`（章節變數含 `md5(chapterUrl)`）非同步落盤（`putBookVariable`/`putChapterVariable`/`putRssVariable`），並以 `getBookVariable`/`getChapterVariable`/`getRssVariable` 回讀；`AnalyzeRuleBase.put` 以 `value.length > 5000` 為閾值分流寫入，讀取經 `transientVariables` 與 `RuleDataInterface.putVariable` 回填，若跨重啟或跨 `bookUrl` 變更後讀取則可能因 `md5` 路徑不一致而未命中。

## Boundaries
- **不替 User 選序，不改書源語意**：`TocRule.preUpdateJs/formatJs`、`ContentRule.replaceRegex` 與 `isReverse`/`reverseToc` 的雙重反轉、`bookUrlPattern` 的 Legado 映射皆為書源作者的顯式語意，引擎必須原樣尊重，僅在 `lib/core/engine/web_book/web_book_service.dart:276` 的相鄰同名摺疊等「畸形書源相容」處做最小補丁，新增「整體重排序」或「自動正序化」屬破壞性變更，需書源白名單而非全域改寫。
- **JS 僅白名單，不動態分派**：`AsyncJsRewriter:22` 約束 `Template literal ${}` 內、`var fn=java.ajax; fn(url)`、`java['aj'+'ax']` 三類動態寫法刻意不支援，`jsRuleAsyncWrapper.dart:19` 約束 `injectFinalReturn` 僅處理最後 top-level 語句且對 `var/let/if/for/while/function/return/throw` 等不注入 `return`，保持可預測的「最後表達式即回傳值」語意，不為未知書源擴大複雜度。
- **Lru 200 與正則/DOM 的重建成本**：`lib/core/engine/analyze_rule/analyze_rule_base.dart:45` 的 `regexCache/stringRuleCache` 上限 200 為全域共享，替換為無界快取會放大記憶體，縮小則使高頻 `splitSourceRule` 重新解析；`AnalyzeByCss`/`AnalyzeByXPath` 每次 `setContent` 即 `html_parser.parse` 重建整棵 DOM，禁止跨規則複用同一個 `Element` 以避免 `querySelectorAll` 在已 detach 節點上的未定義行為。
- **AnalyzeUrl 的同步/異步雙軌不可合併**：同步建構子（`lib/core/engine/analyze_url.dart:47`）明定「只能處理純同步 rule JS」，`AnalyzeUrl.create`（`lib/core/engine/analyze_url.dart:79`）為支援 `java.ajax` 等 async 的唯一入口，呼叫端在 `getStrResponse` 前是否經 `await create` 決定 `prefetchedResponseBody` 是否可用與 `charset` 是否已嗅探，不可將兩條路徑合併為單一 `async` 建構子否則等價於把所有純字串 URL 構造也變異步。
- **WebView 僅事件觸發，不走批量**：`AnalyzeUrl.getStrResponse:501` 以 `SourceValidationContext.isNonInteractive` 衛語阻斷 `HeadlessWebViewService`，`CompleteContentFetcher:42` 明定多頁正文「任一頁失敗即整章失敗」且不使用 WebView，批量校驗路徑禁止為單章提速而對 `HeadlessWebView` 做並發或預取，`HeadlessWebViewService:17` 的 `_tail` 串列化為硬約束，不可改為併發池。
- **WebBook 的並發與分頁上限為安全邊界**：`WebBook._maxTocPages=100/_maxContentPages=20/_pageConcurrency=4`（`lib/core/engine/web_book/web_book_service.dart:28`）與 `CompleteContentFetcher._maxPages=100`（`lib/core/engine/web_book/complete_content_fetcher.dart:21`）為防止書源 `nextTocUrl/nextContentUrl` 環回或無限分頁的熔斷器，調大需同時評估 `Dio` 超時、`RateLimiter` 配額與 `ChapterDao` 批量寫入壓力，調小則可能截斷長篇正常書源。
- **Encode/Decode 的單向契約**：`AnalyzeUrl._decodeResponseBody:604` 的 `charset→Content-Type→meta→auto` 四階優先與 `Transfer: bytes` 唯讀，`_encodeKey` 的 GBK 分支僅對 `key` 生效，`ContentParser.finalizeContent:91` 的 `replaceRegex` 以 `AnalyzeRule.getStringAsync` 再跑一次規則（可含 `@js:`），三段不共享 `charset` 解析結果，改任一段的正則或優先序必須全鏈路回歸搜尋/目錄/正文三場景。
- **事件與快取的字面量契約**：`AppEventBus:12` 的事件名與 `PreferKey`/`AppPattern` 同為跨模組字面量契約，重新命名需全域搜尋並考慮舊版 `AppCache` 已落盤 key 的孤兒化；`ExploreUrlParser` 的 `_cacheKey/_legacyCacheKey` 雙 key（`lib/core/engine/explore_url_parser.dart:371`）為遷移期相容，不可僅刪其一。
