## State-transition contracts

四條狀態轉換路徑的觸發鏈是不同契約，調查轉換問題時先按路徑分流：

- **樣式**：`ReaderV2SettingsController.setFontSize/setTypography` → `ReaderV2Page` 的 `LayoutBuilder` 以 `readStyleFor` 產生 style → `ReaderV2ControllerHost.syncRuntimeConfiguration` 比對 `layoutSignature` → scheduler quiet-frame coalescing 保留最新 spec → `ReaderV2Runtime.applyPresentation` → capture 現有位置並以 `beginPresentation(layoutGeneration + 1)` 重建；Hybrid 由 `_positionHybridViewport` restore，分頁路徑則更新 resolver 後跳回同一語意位置。
- **旋轉／viewport**：外層 `constraints` 或 `MediaQuery.paddingOf` 改變 → 同一個 `LayoutBuilder` → `syncRuntimeConfiguration` → `layoutSignature` → 同一個 quiet-frame coalescing → `applyPresentation`。連續尺寸／inset stream 應只在安靜幀後套用最後 spec，不可把每個中間 frame 當成獨立 presentation 世代。
- **簡繁**：`ReaderV2SettingsController.setChineseConvert` 遞增 `contentSettingsGeneration` → host 偵測 content-settings 變更 → `ReaderV2Runtime.reloadContentPreservingLocation` 先 capture 舊位置、保留舊內容供 mapper 使用並清 content/layout cache → transformer 產生新 `displayText/contentHash` → `ReaderV2ContentLocationMapper` 以句子語意與 UTF-16 boundary 重映射 → Hybrid 或分頁 restore 新位置並回到 `ready`；這不是 `applyPresentation`。
- **換源**：`ReaderV2Page._handleChangeSourceSelected` → 先 `await host.flushProgress()` 取得唯一權威位置 snapshot → `SourceSwitchService.resolveSwitch` → `persistSwitch` → `Navigator.pushReplacement(BookOpenRoute(...))` 建立新的 `ReaderV2Page` 與全新 session。它不是舊 session 的就地 reload；resolve/persist 失敗則留在舊 session，由既有 catch 顯示錯誤。

兩個容易誤判的例外也屬於這組契約：`textColor` 不改變幾何，因此不 bump `layoutGeneration/epoch`；Hybrid 仍會重建帶顏色 freshness 的 bounded cache namespace 並 restore，主題切換期間短暫缺 paragraph、由 tint 逐塊收斂到直繪是設計瞬態，不等同於 layout transition 失敗。另一方面，`ReaderV2Style` 沒有 `fontFamily`，`readStyleFor` 將 `bold` 固定為 `false`；兩者目前不是可變設定，若未來支援，`layoutSignature` 與 hybrid fingerprint 都必須補上對應維度，現階段不要把它們當成已覆蓋的 style input。

換源的 `SourceSwitchService` 已有完整 service-layer regression（標題對齊、章節較少時 clamp、內容不可讀、無目錄、找不到書源、persist rollback 與章節內位置遷移）；目前缺口是 page-layer 的編排、flush 競爭與新 session 拆建，不是重建 service 測試。

## Known Risks
- **混合與分頁雙軌的世代漂移**：`ReaderV2Runtime.hybridViewportActive` 以 `registerHybridViewport` 的 `identical(owner)` 判定，`openBook/applyPresentation/reloadContentPreservingLocation/jumpToChapter/jumpToLocation` 皆據此分流——若 `HybridReaderScreen` 在 `dispose` 前未 `unregisterHybridViewport` 或 `didUpdateWidget` 的 `oldRuntime → newRuntime` 遷移遺漏，`hybridViewportActive` 誤為 `false` 會使 `NavigationController` 的 `PageWindow` 邏輯對 `DocumentIndex` 視口生效，兩套錨點座標互不相容且靜默錯位；`ReaderV2LayoutSpec.layoutSignature` 與 `HybridTypes.LayoutEpoch(value=layoutGeneration)` 為兩套獨立的世代（`Resolver._cacheGeneration` 與 `HybridReaderScreen._epoch/_fingerprint`），`bumpGeneration` 與 `invalidateNamespace` 的配對若漏一端會使 `MeasurementStore` 內殘留舊 `namespace` 的度量，後續 `admit` 以相似 `fingerprint` 誤命中而 1px 誤差逐列累積。
- **快取的容量與逐出語意**：`ReaderV2Resolver._maxLayoutCacheSize=50` 與 `ReaderV2ChapterRepository._maxContentCacheSize=20` 為 process 級常駐，`HybridReaderScreen.ParagraphCache(capacity:512)` 每章由 `maxBlockChars = costModel.maxCharsFor(ballisticSliceBudget)` 切出多個 `ChapterBlock`，512 對於超長章節（如 `displayText` > 50k 字）的 `BlockKey` 總數可能不足，`_restorePinning` 僅 pin 錨點與 `updateParagraphPins` 的 `pinRange`，若 `HybridReaderScreen._enqueued.clear()` 與 `ParagraphCache.unpinAll` 的時序在 `pumpPending` 的連續 `completed` 事件之間被打斷，LRU 可能在 `pumpUntilAnchorReady` 完成前逐出首屏後續塊，後續 `DocumentIndex.hitTest` 命中已無 `Paragraph` 的塊而 `captureVisibleLocation` 回 `null`，進度 capture 靜默丟失；`Resolver._inFlight` 以 `'$chapter|sig|generation'` 為鍵，`_invalidatedInFlightTaskIds` 僅在 `updateLayoutSpec/clearCachedLayouts/retainLayoutsFor` 標記而不取消 `Future`，舊排版仍在 `layoutEngine.layoutStep` 中持有 `TextPainter` 並在完成後以 `_throwIfStale` 拋棄結果，若頻繁切換字級會在 UI isolate 上堆積多個 `layoutStep` 的 `halfFrame` 切片，短暫 `jank` 且 `debugLastStats` 被舊切片覆蓋。
- **連續段落 group 與動態 segmentation**：效能切點不能成為排版邊界；`groupContaining/paragraphGroups` 必須同時核對 `isContinuation` 與 `sourceParagraphIndex`，否則相鄰但不同來源段落會錯誤共用縮排與段距。group 內多個 block 共用同一 `ui.Paragraph`，只要其中一塊缺 paragraph 就必須整組重建；章節逐出或失效時也必須同步清 `MeasurementStore`、`ParagraphCache`、`AdmissionController` 與 `DocumentIndex`，否則 `maxBlockChars` 改變後會混用兩套 segmentation 的高度。
- **Capture/Restore 的像素級耦合**：`ReaderV2Location.visualOffsetPx` 限幅 `[-120,120]`，`anchorOffsetInViewport = h*0.2 clamp [24,120]` 在 `ReaderV2LayoutSpec:74`、`AnchorManager:14`、`HybridReaderScreen._offsetForAnchor/_captureVisibleLocation` 三處各自實作（數值一致但無單一常數），改任一處未同步會使 `restore` 的 `top + lineTop - anchorOffset + visualOffset` 與 `capture` 的 `worldY - blockTop - lineTop` 互為逆運算時產生系統偏差，`_lineTopForChar` 與 `_textBoxTopForOffset` 依賴 `Paragraph.getPositionForOffset/getBoxesForRange` 的 `0.1px` 探針偏移，若 `LetterSpacing` 或 `cellWidth` 鎖寬使全形字 `advance` 含小數累積，則 `charOffset → lineTop → visualOffset → charOffset` 往返會因 `clamp` 與浮點捨入產生 ±1 字元漂移，長文連續 `capture/restore` 會逐步累積。T2 樣式矩陣與 T3 的五次直→橫→直、未 settle、章首／章末／短章 widget cases 均未觀測語意漂移；這降低了目前覆蓋案例的疑慮，但沒有移除像素公式未集中與真機旋轉未驗證的風險。
- **替換規則與正文雜湊的順序敏感性**：`ReaderV2ChapterRepository._contentTransformer.process` 在 `ReaderChapterContentStorage.read` 之後執行，`ChineseTextConverter.convert` 在變換尾端執行，`ReaderV2Content.contentHash = sha1(jsonEncode({chapterIndex, title, paragraphs, displayText}))` 包含 `displayText` 的最終形態——若替換規則含捕獲組或 `convertType` 由 0→1 切換，`displayText.length` 變化而 `ReaderV2Location.charOffset` 仍沿用舊 `chapterLength` 鉗制前的舊值，`HybridAnchor.fromLocation` 的 `clamp(0, displayText.length)` 會把舊 `charOffset` 截斷至新文本末尾，跳回該章時落在章末而非原句；`_enabledRules` 以 `getEnabledForBook(name, origin)` 快取於 `_contentCacheGeneration` 世代，`replace_rule_sheet` 的 `onReload` 僅觸發 `reloadContentPreservingLocation` 而未立即 `clearContentCache` 的話（現行已清），舊生成期的規則會在新內容上重放。T4 已驗證實際 `1→2` UTF-16 擴張會先重映射位置、更新 `displayText/contentHash` 並隔離 content/measurement/paragraph/disk freshness，且保留既有替換→轉換順序；因此本批次的轉換路徑不再接受單純舊 offset clamp，但未改變未來替換規則或管線順序變動時的順序敏感風險。
- **Viewport 七命令的串行與拖曳互斥**：`HybridReaderScreen._HybridCommandQueue` 對 `scrollBy/continuousScrollBy/animateBy/moveToNextPage/moveToPrevPage/ensureCharRangeVisible` 以 `mounted` 守衛串行，而 `settleScroll` 不經佇列直接 `jumpTo(pixels)` 停慣性，若 `TTS` 的 `ensureCharRangeVisible` 在 `dragging==true` 期間入隊，`pumpPending` 的 `PumpState.dragging` assert（`I4: must not layout while dragging`）會使該命令的 `pumpPending` 零完成並在 `dragging → idle` 恢復後才繼續，`maybeFollowTtsHighlight` 的 `_followingTtsHighlight` 旗標在此期間阻塞後續高亮，朗讀跟隨在拖曳中靜默停步；`_jumpBy/_animateByNow` 的 `_minimumViewportMovement=0.01` 與 `maxScrollExtent` 的 `clamp` 在 `DocumentIndex` 尚未 `admitAll`（`beforeExtent/afterExtent` 仍短）時會誤判 `atForwardBookBoundary/atBackwardBookBoundary` 為 `false` 而不 `emitUserNotice`，書尾/書首提示丟失。
- **進度落盤的時序與離場競爭**：`ReaderV2ProgressController.debounce 400ms` 與 `ReaderV2ViewportBridge.saveJumpAfterSettled(token)` 的「等待當前 `OperationToken` 仍為 `isCurrent` 才落盤」互相競爭——快速連續 `jumpToChapter`（如抽屜連點）會使前一次 `saveJumpAfterSettled` 的 `token` 在 `completeReady` 後已過期，`isCurrent` 為 `false` 而跳過落盤，僅剩 `captureVisibleLocation(notifyIfChanged:true)` 的 `notifyListeners` 路徑觸發 `saveProgress`，若期間 `HybridReaderScreen` 處於 `capturing==true` 而 `Runtime._onRuntimeChanged` 提早 `return`，則該次 capture 的 `notify` 被抑止，進度在離場前 `flushProgress` 才能補回，`dispose` 時的 `unawaited(flush())` 若在 `BookDao.updateProgress` 的 `await` 期間頁面已 `pop`，`Book.chapterIndex/charOffset/visualOffsetPx` 的記憶體鏡像已更新但 DB 仍為舊值（下次啟動以 DB 為準而回跳）。T5 的 page-layer cases 已確認 flush snapshot 是換源唯一權威、resolve/persist 失敗不破壞舊 session，且 `pushReplacement` 後舊 session 的 late flush 不會覆寫新 book row；這些情境在目前 bounded memory-DB seam 已通過，但不代表 real network 或 device timing 已驗證。
- **本地書與受支援格式的硬失敗**：`ReaderV2ChapterRepository._loadViaV2ContentPipeline:242` 對 `local://` 且 `isSupportedLocalBookPath==false` 直接拋 `ReaderV2ChapterRepositoryException('本地書格式不受支援')`，而 `MetricsDiskCache` 與 `HybridChapterRepository` 的快取鍵含 `bookUrl`，錯誤路徑下不寫 `Metrics` 也不發 `ChapterEvent.loaded`，`HybridReaderScreen._ensureChapterBlocks → _warmDiskMetricsForChapter` 的 `await` 永不 resolve（`_blocksInFlight` 殘留），後續同一章的 `ensureChapterBlocks` 命中 `inFlight` 而永久掛起，抽屜仍顯示該章但點擊無反應。

## Boundaries
- **`BookOpenRoute` 為唯一開書入口**：`ReaderV2Page` 僅由 `lib/shared/navigation/book_open_route.dart:14` 的 `BookOpenRoute(book, openTarget, initialChapters)` 具現，`openTarget` 的 `ReaderV2OpenTarget.resume/chapterStart` 決定首幀 `anchorOffsetInViewport` 的對齊語意，`initialChapters` 非空時 `ReaderV2ChapterRepository.ensureChapters` 跳過網路而以 `chapterDao.insertChapters` 為準；不可在閱讀器內另建 `ReaderV2Runtime` 或以 `Book.copyWith` 篡改 `bookUrl/origin` 後復用既有 `Runtime`，否則 `sourceDao.getByUrl(origin)` 與 `MetricsDiskCache` 的 `bookUrl` 鍵分叉。
- **`ReaderV2Location` 為跨層座標的唯一契約**：`chapterIndex/charOffset/visualOffsetPx` 的 JSON 形狀 `{chapterIndex, charOffset, visualOffsetPx}` 由 `ReaderV2Location.toJson/fromJson` 與 `Book.readerAnchorJson/bookDao.updateProgress(readerAnchorJson)` 共同約束，`visualOffsetPx` 必須經 `normalizeVisualOffsetPx` 限幅，`charOffset` 必須經 `normalized(chapterLength)` 鉗制；混合與分頁兩套視口的 `capture/restore` 必須經此類型互轉，不可直接以 `pixels/BlockKey/pageIndex` 跨層傳遞，`PendingChapterJumpTarget` 的 `identical` 精確清理依賴此單一類型語意。
- **`layoutSignature` 與 `LayoutEpoch` 的雙重世代隔離**：`ReaderV2LayoutSpec.layoutSignature`（`Object.hash(viewportSize, contentWidth, contentHeight, cellWidth, style.*, kReaderV2CjkTypographyFeatureSignature)`）與 `HybridTypes.LayoutEpoch(value=layoutGeneration)` 分別隔離舊排版快取與舊度量命名空間，`ReaderV2Resolver.updateLayoutSpec` 與 `HybridReaderScreen._handleEpochRebuild/_refreshEpochBinding` 必須成對呼叫（`bumpGeneration/invalidateNamespace/reset DocumentIndex`），不可僅改其中一套而復用另一套的舊 `BlockMetrics/ui.Paragraph`，否則 `cellWidth` 鎖寬的殘差與 `justify` 字距會 1px 累積至錯位。
- **`ReaderV2ViewportController` 七閉包為 Hybrid 與 Coordinator 的唯一操作面**：`scrollBy/continuousScrollBy/animateBy/moveToNextPage/moveToPrevPage/settleScroll/ensureCharRangeVisible` 的簽章與 FIFO 語意（`settleScroll` 直達）為 `ReaderV2PageCoordinator` 與 `ReaderV2AutoPageController`/`ReaderV2TtsController` 的契約，非 hybrid 分支的 `Runtime.moveToNextPage/moveToPrevPage` 僅作無 viewport 的 fallback，不可同時驅動兩套翻頁路徑；`ensureCharRangeVisible` 的 `chapterIndex/startCharOffset/endCharOffset` 為 TTS/選詞/搜尋跳轉的統一入口，改其語意需同步 `HybridReaderScreen._ensureCharRangeVisibleNow` 的跨窗 `restore` 分流與 `getBoxesForRange` 的 `0..displayText.length` 鉗制。
- **`HybridLayoutPump` 為唯一可建 `ui.Paragraph` 的實體（I4）**：`DocumentIndex/MeasurementStore/ParagraphCache/AdmissionController` 均不可直接 `ParagraphBuilder.build/layout`，全部經 `LayoutPump.submit → pumpPending → put(paragraphCache, measurementStore) → completed → admission.offer` 管線；`pumpPending` 在 `PumpState.dragging` 時必須零完成並以 `assert` 攔截，違規會使拖曳幀內 `Paragraph.layout` 觸發 `jank` 並污染 `BudgetGovernor.hasLeadDeficit`。
- **效能切塊不構成排版邊界**：同一 `sourceParagraphIndex` 的 continuation blocks 必須以一個 `LayoutTask`、一個 `ui.Paragraph` 連續排版，再把 metrics 分回各 `BlockKey`。縮排只屬 group 第一塊，段距只屬最後一塊；不可逐 block 建 paragraph、在人工切點插入換行，或只重建 group 的其中一塊。
- **`I2/I3` 的連續 admit 不變量**：`DocumentIndex.admit` 要求每側自 `centerKey` 向外單調連續（亂序以 `assert` 攔截並 `rebuildAll` 回退），`HybridReaderScreen._admitOrSubmitGroup` 在 `blocked` 後禁止同側後續 `direct-admit`（否則中間洞在補齊時使可見內容位移），`HybridReaderScreen._handleEpochRebuild` 必須 `measurementStore.invalidateNamespace + documentIndex.reset(centerKey)` 原子化，不可保留舊 `DocumentIndex` 的 `beforeExtent/afterExtent` 而僅換 `MeasurementStore`。
- **中文排版與字體鏈的固定契約**：`ReaderV2LayoutEngine._lineStartForbidden/_lineEndForbidden` 與 `kReaderV2CjkFontFeatures/kReaderV2CjkTypographyFeatureSignature`、`LayoutPump._cellWidthSignature`（`fontSize|letterSpacing|bold|signature`）與 `em-grid` 實測 `cellWidth` 構成 CJK 排版的視覺基線，`ReaderV2LayoutSpec.fromViewport` 的 `cells*cellWidth+0.05` 與 `sidePadding` 回填、`LayoutPump._buildParagraph` 的 `placeholder(indentCellWidth)` 與兩段式末行補償、`ReaderV2LayoutEngine._isEnglishLetter` 的單字防切斷，皆為 `ReaderV2Content.displayText` 的座標系前提，改任一常量需全鏈路回歸「字數建議預算 `maxBlockChars`→`DocumentIndex` 長度→`anchor` 換算」的像素級對齊。
- **章節章序與去重語意**：`WebBook.getChapterListAwait` 的去重與 `isReverse`/`reverseToc` 雙重反轉、`ReaderV2ChapterRepository.ensureChapters` 的 `insertChapters` 自增 `index`，均為 `BlockKey.chapterIndex/ChapterBlocks.blockForCharOffset` 的順序前提；`HybridReaderScreen._ensureWindowTasks` 的 `[0,1,-1,2,-2]` 與 `PreloadScheduler.scheduleAround(radius:1)` 的半徑需一致，否則視口可見章節與預載章節的交集在邊界產生洞（`DocumentIndex.keysInRange` 的對應範圍為可見幀提供 `O(k log n)`，洞會使 `hitTest` 回 `null`）。
