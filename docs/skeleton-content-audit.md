# 骨架與實際內容一致性巡查

日期：2026-11-02。範圍：`lib/` 中使用 `GroupedListView`、`GroupedSheetContent`、`SkeletonSwitcher`、`SliverSkeletonSwitcher` 及自訂骨架的入口。

## 判斷方式

比對載入時的列數、卡片分組、標題與副標、列首／列尾、行高、封面位置和實際內容的顯示條件。先看原始頁面的載入條件，再看骨架從何處取得資料；只要資料未讀完就可能改變整組或列高，便列為優先問題。形狀完全依網路或書源回傳的未知內容決定者，與已知資料卻使用固定假形狀者分開記錄。

本次是原始碼結構巡查，並補上可執行的 Flutter widget 測試；沒有實機逐頁錄影或像素量測，以下的「已修」不代表實機畫面已驗收。

## 已處理：進場資料與骨架的時間差

| 入口 | 原因與使用者可見的落差 | 現在的處理 |
| --- | --- | --- |
| 關於夜讀 → 權限 | `FutureBuilder` 在進場骨架量形狀時只產生轉圈，實際成功後卻有五列權限狀態及「開啟系統設定」「重新整理」兩列；形狀從一個小區塊跳成完整卡片 | 先依 `AppPermissionService.loadingSnapshot()` 畫固定五列的相同結構；完成查詢後才依真正狀態計算骨架並揭開。狀態字樣、可能出現的箭頭仍須等系統回報才知道 |
| 備份與同步 → 同步空間 | `_space` 初始為 none，背景讀設定後可能多出「停用同步」整組；Google／WebDAV 的帳號副標亦會增高列 | `GroupedListView.ready` 在同步空間與帳號載入完成前維持骨架，最後依實際選取與帳號排列 |
| 同步空間 → WebDAV | 進場後才把儲存的網址、帳號、密碼填回，並改變底部連線操作標題；字形長度和初始輸入框不同 | 儲存資料讀取完成後才揭開骨架 |
| 備份與同步（首頁） | 同步空間與上次同步時間異步載入；「立即同步」可能多出副標，改變該列高度，以下的備份分組往下移 | 等 `SyncService.load()` 完成後再揭開骨架 |
| 書源登入（腳本產生的表單） | 初次查詢不知道有幾個欄位／按鈕，固定預覽為兩個欄位、兩排按鈕；實際規則可能完全不同 | 保留未知時的通用預覽，但腳本回傳後改用真實欄位、按鈕及排列重算揭開前的骨架，避免最後仍照固定範本換場 |

以上共用的根因是：進場動畫已經結束，但業務資料還沒到齊，`GroupedListView` 會把「暫時的內容」當成最終版面。分組清單新增 `ready`（預設 true），讓需要異步讀取的頁面自行告知資料是否已齊；原本不需異步讀取的清單與面板維持既有行為。

## 待實機對照：資料未知或各列內容不同

| 優先 | 入口／骨架 | 待確認的具體落差 |
| --- | --- | --- |
| 高 | 書源管理：`SourceListSkeleton` | 初次進入沒有上次的書源資料時，名稱／網址只用預設長度，功能標籤固定畫三或四個；`SourceItemTile` 實際可以是零至五個標籤，並額外出現分組、異常標記、校驗進度、錯誤文字與網域分組標題。部分差異會改變整列高度 |
| 高 | 發現書源：`ExploreSourceListSkeleton` | 骨架依畫面高度填滿一整張清單；實際書源數可能不足一頁、為零、或顯示錯誤／空頁，展開的分類內容也非普通單列 |
| 中 | 發現分類書單：`ExploreBookListSkeleton` | 封面寬高依 `ExploreBookItem` 常數，但書名、作者等文字使用固定長度；資料未回來前無法推算實際文字寬度與可見書量 |
| 中 | 書籍詳情：`BookDetailSkeleton` | 已知簡介與章數會照真正文字排，未知時簡介假設四行、目錄假設八列；載入後可能有分卷、書源問題提示，列的種類和數量不同 |
| 中 | 書架：`BookshelfSkeleton` | 有上次記錄的書名、作者時照字量；首次打開或新加入的書仍使用固定長度，書本數量也可能與上次不同 |
| 中 | 朗讀與語音：`TtsSettingsPage` | 引擎尚未初始化時先畫「系統預設」；`TTSService.init()` 在換頁動畫後才執行，真正引擎、音色文字可能在骨架揭開後才變，需在 TTS 尚未初始化的裝置量測 |

上表的「待確認」為由程式路徑可證明存在的**差異條件**，不是宣稱每次使用者都會看見跳動。對資料尚未取得、也沒有上次紀錄的頁面，不能假裝一開始就知道精確文字；後續應優先利用既有快取、已回傳的資料與固定版面欄位，量測顯示期間及真正換場時的差距。

## 已有一致性保護與另一種載入狀態

- 分組頁、閱讀器面板：`GroupedItemShape`、`GroupedSkeletonItem` 以真正元件的文字和常數量形狀；`test/shared/widgets/grouped_list_skeleton_test.dart`、`test/features/settings/mine_pages_skeleton_test.dart`、`test/features/reader_v2/reader_v2_sheet_entrance_test.dart` 已有對照測試。
- 背景下載佇列：`_Subscribed` 以下載服務當下的值產生形狀，`test/features/cache_manager/download_manager_skeleton_test.dart` 已涵蓋主要佇列進場。
- 閱讀器正文：`LoadingVeil` 優先使用上次留存的每行位置，沒有可用紀錄時先顯示純色「紙」，待真正排版完成才給骨架；屬於有意設計，不能直接當成不符。
- 閱讀統計、更新紀錄、崩潰日誌：等待資料時目前顯示置中轉圈，完成後才建立分組清單；這些頁面**沒有先畫錯的骨架**，但與 App 以內容形狀載入的整體設計不同，屬於另一次改版決策，不納入本次直接替換。

## 驗收

新的測試：`test/features/about/permissions_skeleton_test.dart`，用可控制的權限回報模擬換頁已播完而資料尚未回來，確認骨架持續存在，資料到齊後用 `skeletonMismatches` 與最終內容逐塊比較。共用等待機制的回歸測試加入 `test/shared/widgets/grouped_list_skeleton_test.dart`。

建議補做：在 Android 手機及平板，分別用淺色／深色、正常／較大字級，錄下上述高優先頁面的初次進入，量骨架與內容各塊的 `Rect` 差距及整組縱向跳動；再決定固定未知資料時要顯示多少列。驗證前不可把上表的「待確認」視為已修復。
