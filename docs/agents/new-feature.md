# 開新的功能線

新的功能線（新的書的類別、新的閱讀方式、新的書源能力、新的設定頁）談定案時走一遍觸點。打磨現有功能不用走。

一條功能自己談得再細，談到哪些周邊還是看當時想到什麼；漏掉的都是沒人問過的那一格（要登入的網站在新閱讀器裡沒有出路、播不出來沒有提示、對外說明沒跟著改）。

## 步驟

1. 對 `DESIGN.md`「產品界線」與「否決過的方向」。越界或撞到否決過的，先和使用者談，談定改那一節與 ADR。
2. 走下面的觸點，每一格問使用者或自己查，答案是三選一：**做**（怎麼做）、**不做**（理由）、**不適用**。
3. 碰到的每一格，讀它右欄的 ADR：新功能是照它，還是例外。例外寫進新的 ADR 與它的索引行（例：有聲書手動下載是 ADR 0008 的例外，寫在 ADR 0055）。
4. 既有的每一類書各問一遍：這個功能對小說、漫畫、有聲書、本地書各自怎樣。

做完的條件：新功能的 ADR 有一節「觸點」，下面每一格都有答案，沒有空著的。空著就還不能開工。

## 盤點既有功能時

查某個功能有沒有接上某一格，在整個 `lib/` 搜，不只搜那個功能的資料夾：共用的東西常掛在外層（漫畫的閱讀計時掛在開書的路由 `BookOpenRoute`，不在 `comic_reader/`）。
