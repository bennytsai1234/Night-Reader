# AI 找書實跑

用真的書源與使用者的 AI 服務跑 AI 找書，照 `agent-harness` 技能第 3 到 5 步迭代：單件復盤、整批、評過程、歸因、終點都照技能。這裡只寫夜讀的材料、跑法與對應。金鑰、服務與並行的事同 `docs/agents/ai-repair-runs.md`「材料」。

## 材料

- **案件集**：`test/live/ai_find_cases.json`，一件是 `id`、讀者會打的描述與深度，書架是編的（`shelf`）。不附標準答案，評的是過程。能不能沒有結果：可以，交出零本並說明也算交件（ADR 0060）。
- **書源**：整份匯出檔 `.local/ai-repair/export_589_sources.json`（主資料夾），全部存進暫存資料庫，搜尋範圍是全部書源，同搜尋頁的預設。

## 一輪怎麼跑

1. **跑**：`test/live/ai_find_live_test.dart`，跑法與環境變數寫在檔頭，加 `FLUTTER_TEST_WALL=0`，放背景。一件接一件跑（每次搜尋都送全部書源，同時跑會互搶書源 isolate）。一個改動只重跑出現過那類問題的件：`NR_ONLY=adr-example,from-shelf`。
2. **只量搜尋**：不給 `NR_CASES`、給 `NR_SEARCH=<關鍵字>`，不問 AI，印出一次搜尋送了幾個書源、幾個出錯、花多久。改了搜尋工具或想知道一件要等多久時先跑這個。
3. **整理成表**：測試開頭與結尾印出紀錄資料夾，整個複製到主資料夾的 `.local/ai-find/runs/<日期-名稱>/`，跑 `dart run tool/ai_find_table.dart <那個資料夾> --out <那個資料夾>/_table.md`，跟上一輪的表比回合數、耗時、快取命中率。
4. **讀紀錄**：每件逐份讀完，看每輪 AI 想確認什麼、工具回了什麼、交出的每本有沒有工具給的證據撐著。

## 夜讀的對應

照技能第 5 步評過程與歸因時：

- **正式系統**是搜尋頁的搜尋（`SearchModel`）、書籍詳情、閱讀器的目錄與正文、發現頁，工具跑的是同一套（`AppAiFindLibrary`）。工具回的跟 App 上同樣操作看到的不同，是書庫或引擎的事。
- **用 App 以外的方法核對推薦**：推薦理由說的題材、完結、字數，打開那本書的詳情與第一章對照；說「書源裡沒有」時，拿描述裡的作品名或代表作親手搜一次。
- **品味的判斷是模型的事**：工具給的事實都對、推薦還是不合描述，才改提示詞的定義。
