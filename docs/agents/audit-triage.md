# 處理巡檢報告

自動巡檢開出來的報告（標 `auto-audit` 的 issue）由維護者處理：每一條核實後修掉、說明不修的理由，或指出早就修好，全部有結論才關。巡檢怎麼開報告見 `docs/agents/auto-audit.md`。

## 步驟

1. **列出來**：`gh issue list --label auto-audit --state open`。還開著的報告在 `PLAN.md` 寫成一條「處理巡檢報告」，列出每份報告的編號與一句話（`#505 閱讀器換源處理中關閉面板，畫面還是舊書源`）。順序：只改文件的、小錯，再來動到資料、背景工作或書源引擎的。
2. **一次一份**：照報告的連結走到最新 `origin/beta` 的程式。報告是讀程式推理、沒有執行，每一條都要自己核實：問題還在、推理每一步成立、讀者真的會碰到。書源、規則引擎的照 Legado 對（`AGENTS.md`「維護範圍」）。
3. **每一條定一個結論**：
   - **修**：照一般的分支與收尾流程（`AGENTS.md`「Git 與發版」、`docs/agents/finish.md`），先寫出會紅的測試再修。PR 說明寫 `Closes #<報告>`；一份報告有好幾條、分幾個 PR 修時，前面的寫 `Refs #<報告>`，最後一個寫 `Closes`。只改文件的直接在 `beta` 上改，提交訊息寫 `Closes #<報告>`。
   - **不修**：推理不成立、和 ADR 衝突，或使用者決定不做。理由留言在報告裡；使用者定案的取捨寫進 ADR 或 `DESIGN.md`「否決過的方向」，巡檢就不會再報。
   - **早就修好**：留言寫是哪個提交修的。
4. **留結論**：報告關閉前留一則留言，每一條一行：修了什麼（附 PR）、沒修為什麼。全部不修或都已修好的，用 `gh issue close <報告> --reason "not planned"` 或 `completed` 關。
5. **回報**：從 `PLAN.md` 那一條拿掉這份；回覆裡寫每條核實的結果、修了什麼、CI 與合併結果。全部處理完就刪掉那一條。
