# 換行做避頭尾，被拉字的那一行把空隙攤進字距

取代 ADR 0005。2026-10-18 起，換行引擎（`VisualLineLayoutEngine`）做避頭尾：在某處斷行會讓「，。、；：！？」』）》」這類標點落在行首、「「『（《」留在行尾，或把「……」「——」拆到兩行時，往回找可以斷的位置，把前面的字一起拉到下一行（整段英數字算一個字，最多拉三個）。被拉字的那一行少了一兩格，空出的寬度用補白（`LineSpacer`）平均攤進字距，只攤在旁邊有整格字的字距上，英文單字裡面不拉開；左右兩緣照樣切齊。

使用者對照了 legado 的排版：legado 預設用 Android 系統換行，系統依 Unicode 換行規則做避頭尾（只推字下去，不擠壓也不懸掛標點），再開「兩端對齊」把短少的寬度攤進那一行的字距。這樣做直行並沒有對齊，但看不出來：只有被推字的行會偏，每個字距只多約 1/15 格，偏移從左往右逐漸累加，最多在行中間偏半格，兩緣又回到格線上。使用者看了同一頁正文在這個 App 的前後截圖後採用。

ADR 0005 當初的依據是早期量到直行格點逐行漂移 0.6–1.5 字寬（`f5e0e21`），但那次量到的漂移混了另一個原因：當時文字框不是整數格，每一行都在攤剩下的空間。這個原因後來由整數格文字框與 ADR 0019 解決，避頭尾本身只讓被拉字的行偏移，最多約半格。

## Considered Options

- 維持不避頭尾（ADR 0005）：格線完全對齊，但「。」「——」會出現在行首，句號甚至會單獨佔一行，使用者不要。
- 行尾懸掛標點：放不下的標點伸進右邊留白，其他字的格線完全不變；但要佔用右邊距，正文就不再和頁首頁尾的資訊列貼齊（ADR 0019），沒有採用。
- 擠壓標點（把行內的全形標點縮成半格，擠出位置給放不下的字）：被擠的標點之後的字整排錯開半格，而且要逐字形調整，沒有採用。
- 被拉字的行不攤字距、右緣短一截：右緣參差，使用者要左右兩緣切齊，沒有採用。

## Consequences

- 被拉字的行字距比上下行鬆一些，中間的字最多偏離直行約半格；其他行仍然每格等寬、直行對齊。
- 攤進字距的寬度取整數個半格，不含文字框為防浮點誤差留的 0.05 slack；攤滿會讓原生排版把這一行再折一次。
- 往回拉超過三個字、或會把整行拉空時，照原本的位置斷，標點仍可能落在行首（例如一整行都是句號）。
- 英數字段在中間被拆開換行（長英文從字的開頭換行）的那條路徑沒有加避頭尾。
- 改動這套規則要提高 `kReaderV2CjkTypographyFeatureSignature`，舊的量測與換行快取才不會沿用。
