# 連書源網站不驗憑證，夜讀自己的服務照常驗

使用者 2026-11-14 決定：書源網站常放著憑證過期、自簽或網域對不上不管（AI 修復實跑裡肉肉屋⑥原本的網址就是憑證過期），驗了書就讀不到，所以連書源網站的請求照 Legado 不驗憑證；夜讀自己的服務照常驗。

## 決定

- **不驗的**：Legado 不驗的地方都不驗：
  - 書源的請求（搜尋、詳情、目錄、正文、下載（含有聲書）、登入），規則 JS 的 `java.ajax` 這類與 Jsoup 連線。
  - 從網址匯入書源與書架。
  - 網路封面（顯示與存進手機）。
  - 書源用的看不到的瀏覽器、Cloudflare 檢查與網站登入頁：遇到憑證錯誤照樣載入，同 Legado 的 `onReceivedSslError` 都 `proceed()`。
- **照常驗的**：App 更新（查版本、下載 APK）、同步空間（WebDAV、Google 雲端硬碟）、AI 服務、字型下載。這些各用自己的連線，不經過書源的那一條。
- 書源的連線全部從 `lib/core/network/source_tls.dart` 拿，新的書源請求也從那裡拿；夜讀自己的服務不要用書源的連線（`NetworkService().dio`）。

## 考慮過的做法

- **全部都不驗（Legado 的做法）**：Legado 的 App 更新也走同一條連線。不驗的話，下載的更新檔可能在傳輸途中被換掉，所以 App 更新另開一條。
- **照舊全部都驗**：書源網站憑證一過期，這個書源就不能用，AI 修復也只能放棄。

## 後果

- 連書源網站時，被人從中間攔下也看不出來：登入書源網站的帳號密碼、Cookie 可能被看到，搜尋結果與正文可能被換掉。書源本來就很多是不加密的 `http`，差別不大。
- 從網址匯入的書源、書架可能在傳輸途中被換掉，和從不加密的 `http` 網址匯入一樣。
- 書源校驗不再因為憑證有問題判成「上游異常」；握手失敗這類其他加密連線的錯誤照舊是。
- 有聲書沒下載的章節線上播放時，是播放器自己連網（帶標頭時經過 just_audio 的本機轉送，不帶時是系統播放器），照常驗憑證：這類網站的有聲書要先下載才聽得到。Legado 的播放器走書源的連線；要照做得換掉播放器連網的那一層。
