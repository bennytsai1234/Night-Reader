# AI 建立書源：貼一個網址，AI 從空白寫出書源，通過校驗才加入

使用者 2026-11-23 要的：「AI 修復其實已經把 90% 的能力做好了——抓網頁、找字、試解析、試抓、跑過書源校驗才套用。貼一個冷門小說／漫畫／有聲書網站的網址（可選填一本書名當樣本），直接跑同一套循環從零生出通過夜讀校驗的 Legado 3.0 書源，做完還能匯出分享。」書源由使用者自己貼的網址做出來、存在使用者手機上，夜讀不帶任何網站清單（產品界線 2）；用使用者自己的 AI 服務（界線 3）。

## 決定

- **同一套循環，換開場、角色與驗收**：迴圈、工具（看網頁、讀頁、找字、解析、跑程式、試抓、交出、放棄）、書源校驗、紀錄、AI 服務設定、背景工作都照 AI 修復（ADR 0054）。夜讀先做一份只有網址開頭的空白書源（名稱是主機、類型先填小說），檢查網站（同修復異常書源的網站檢查；網站不在了就不問 AI），抓貼的那一頁；開場給 AI 的是空白的書源、貼的網址、樣本書名、網站檢查的結果與那一頁的開頭。系統提示換成建立員的角色與做事的步驟；書源格式、規則語法，以及網站不穩定、限流、驗證頁、別的網域、頁面程式填內容、搜尋、放棄這些判斷照用修書源那一份的原文（`aiSourceRules`、`aiSourceMethod`），修書源的提示詞不變。
- **付費與要登入，一看到就放棄**（使用者 2026-11-23：「只要一付費，就立即放棄」）：放在步驟最前面；認網站時同一次回覆打開一本書的目錄看最後幾章。看到任何一本書要付費才看得到（VIP、鎖頭、訂閱、購買、點數、只給試讀，前面幾章免費也算），立即用「要付費」放棄，不先寫其他規則、不改挑免費的書當樣本、看到一處就夠；內容要登入才給的（後面的章節或集數要登入也算）同樣用「要登入」放棄。校驗另外照 ADR 0057 抽查目錄與後段章節，AI 漏看的付費也過不了。登入要在登入頁裡做，背景跑的 AI 證明不了登入後讀得到，所以要登入的網站不建立。
- **類型由 AI 照網站內容判斷**，校驗照正文確認（ADR 0051）；輸入頁不放類型選項。聚合源不做：一個書源接很多網站、靠登入表單切模式，不是貼一個網址做得出來的。
- **樣本書名選填**：有填時 AI 用它找搜尋、試抓，並寫成書源的校驗關鍵字；沒填時 AI 從首頁、分類或排行挑一本站上確實有的書，同樣寫進去。
- **發現頁選做**：只要求搜尋、詳情、目錄、正文；網站有清楚的分類或排行時可以寫發現，寫了就要一起過校驗，過不了拿掉發現再交。
- **驗收要整個通過**：沒有修書源「只剩發現頁壞也算」的寬限；校驗每一段都驗，不照使用者在校驗設定關掉的段（從空白寫的書源，關掉的那一段可能根本沒有規則）。校驗判成付費、要登入或要網頁驗證時直接結束、不建立，不再退回給 AI。名稱照 AI 寫的網站站名，網址開頭照空白書源的（只接受換開頭，同修書源），說明寫「夜讀 AI 依 網址 建立（日期）」，不加分組，加在書源最後、啟用。
- **跟已有的書源撞到，分兩次查**（不讓自動合併替使用者挑，ADR 0062）：按「開始建立」時已經有同一個主機的書源就先問（「仍然建立｜取消」，那個書源帶「異常」時多一顆「AI 修復它」），這時還沒送任何東西給 AI；存的時候網址一樣、或同主機同類已有書源就不存，結果寫出是哪一個；查重與寫入在同一個交易裡，查完到寫進去之間匯入或同步進來的書源不會被蓋掉。
- **做不出來時什麼都不存、不留標記**：放棄原因同修書源；結果頁寫原因與 AI 的說明，紀錄照樣可以複製與分享。
- **網址裡夾帳密的不收**（`https://名稱:密碼@網站`）：網址會送給 AI、寫進書源說明。網站存在 Cookie 罐裡的 Cookie 值和書源的一樣，送出前遮掉（修書源一起）。
- **沒有 AI 服務時不做剪貼簿**：跳「還沒設定 AI 服務」帶去設定頁，同 AI 找書。從空白寫要來回看很多頁，網頁版 AI 沒有工具。
- **背景工作與暫停**：是一件背景工作，和修書源、校驗、AI 找書共用一次一件的位置（ADR 0058）；通知欄標題「AI 建立書源 · 名稱」。暫停後按繼續從頭重來（同單一書源修復），存的是網址與樣本書名。
- **一件最多 36 輪**，同修書源。
- **做好時結果頁多一列「分享這個書源」**，用書源管理「分享選中」的同一套檔案。
- **畫面照慣例**（使用者 2026-11-23）：入口在「加入書源」最下面「從網站建立（AI）」；輸入頁照 AI 找書的開始前；建立頁與結果照修復頁（`docs/design/screens.md`「AI 建立書源」）。

## 考慮過的做法

- **AI 先不看網頁、憑網址寫第一版再試**：沒看過網站，第一版幾乎一定錯，白花一輪。
- **夜讀先用程式猜搜尋表單與書單再交給 AI**：要讀頁面才知道的是判斷題，修書源時就否決過程式替 AI 判斷頁面（ADR 0054）。
- **使用者先選小說、漫畫、有聲**：多一個要選的，選錯時（例如有聲小說站）反而誤導 AI。
- **書名必填**：使用者得先去網站找一本書。
- **一律要寫發現頁／一律不寫**：輪數多、有的網站沒有分類頁；或使用者在發現分頁看不到這個網站。
- **輸入頁讓使用者填名稱、或固定用主機當名稱**：多一格；主機不好認。名稱建好後在書源編輯改。
- **只在存的時候查重複**：可能白花一整輪 AI 用量。**照存、交給自動合併**：可能把使用者原本的書源併掉。
- **要登入的網站照樣存一份、標「需要登入」**：校驗沒過的書源夜讀從來不存。
- **付費照修書源的做法、查完再放棄**：實跑晉江寫完搜尋、目錄才看付費，19 輪；使用者要一看到就放棄。

## 觸點

| 觸點 | 答案 |
|---|---|
| 書源類型、匯入時怎麼分 | 照 ADR 0051：AI 判斷、校驗照正文確認；聚合源不做 |
| 書源校驗怎麼判斷抓得到 | 照現狀，交出後整個通過才存 |
| AI 修書源 | 共用同一套；建好的書源之後壞了照常交 AI 修復 |
| 要登入、要網頁驗證 | 不建立：要登入用「要登入」放棄；要人操作的驗證用「要真人驗證」放棄（ADR 0033、0038） |
| 付費章節 | 照 ADR 0057：一看到就放棄，校驗另外擋 |
| 搜尋、發現、換源 | 照現狀：建好的書源和匯入的一樣參加 |
| 手機上的檔案匯入 | 不適用 |
| 書架、書籍詳情、下載、檢查新章節 | 照現狀 |
| 閱讀器失敗時的畫面 | 照現狀 |
| 偏好、設定 | 不做：沒有開關；AI 服務設定同修書源 |
| 進度、閱讀統計、書籤、標註、朗讀 | 不適用 |
| 通知、鎖定畫面 | 做：背景工作的通知（ADR 0058） |
| 同步、備份 | 照現狀：建好的書源和其他書源一樣同步、備份；建立的過程不同步 |
| 匯出、和 Legado 互通 | 做：「分享這個書源」是 Legado 格式的書源 JSON |
| `PRIVACY.md` 與「隱私說明」 | 做：兩處與 AI 服務頁「會送出什麼」各加一段 |
| `README.md`、網站 | 這次不改：流程與畫面會照實跑再改，穩定後另談 |
| `GLOSSARY.md` | 做：加「AI 建立書源」 |
| `docs/design/` | 做：`screens.md`「AI 建立書源」 |
| iPhone | 照常：同一套 AI 服務與書源引擎；背景照 ADR 0058 |
| 自動巡檢 | 新檔案在 `lib/core/ai_repair/` 與 `lib/features/source_manager/ai_repair/`，照所在資料夾的分段 |
| 小說、漫畫、有聲、本地書 | 小說、漫畫、有聲都做；本地書不適用 |

## 後果

- 建立要等幾分鐘、用掉使用者的 AI 額度；有聲書站常要解開播放網址的簽名，輪數多。
- 同一個網站兩次的結論可能不同（13听书一次要登入、一次網站不穩定），兩種都不建立。
