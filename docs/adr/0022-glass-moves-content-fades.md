# 一個元件的進出場只做一件事：玻璃只動、內容只淡，最後一幀等於靜止

動畫的最後一幀必須和靜止時的畫面一模一樣：位置、大小、透明度、模糊、顏色、陰影都要跟著進度連續變化，不能有任何一項到結束那一刻才跳到位。

在這個前提下，一個元件的進出場只做一件事：

- **玻璃的控制元件只做動畫，不淡入**：閱讀選單（上、下、亮度條）、浮動分頁列與它後方的漸隱帶、書架多選的工具列、書籍詳情的「開始閱讀」膠囊，都從畫面邊緣滑進滑出（`GlassSlide`）。收起時移開自身大小，再加上離螢幕邊緣的距離與陰影伸出的 `AppGlass.shadowReach`，陰影不會留在畫面邊緣；完全收起時不畫、不進讀屏，裡面的動畫也停著：收起的選單仍在元件樹裡，開書時「上一章／下一章」從停用變成可按的主題漸變，原本在畫面外每格重算、落在開書的換頁動畫裡（2026-10-21）。
- **在原地出現的玻璃**沒有畫面外可以滑進來，只移動的話第一幀會整塊冒出來：
  - 跳出的玻璃選單從靠錨點的那個角由 0 長大，不淡。
  - 提示框只淡入、不縮放，由玻璃自己連同模糊一起淡（`GlassReveal`）。
  - 長按預覽背後的全螢幕模糊，模糊強度與底色一起淡入。
- **內容只淡入，不移動**：文字、封面、骨架換成內容、搜尋結果陸續出現、書架網格與列表互換。書架列表多選時，封面往右讓出位置，勾選圈的濃淡由讓出的寬度決定，寬度不到圓圈本身時完全透明，不會被邊緣削一半。
- **放在不透明底上、跟著內容淡入的玻璃按鈕不模糊**（`blur: false`）：例如書籍詳情目錄組標題的圓鈕。底下只有頁面底色，模糊看不出差別，卻會在淡入的最後一幀才糊上。

2026-10-16 使用者指出閱讀選單「前面的動畫都跑得很好，最後一下非常突兀，整個閃出來」，並決定玻璃不需要淡入，淡入加動畫太多。

## 為什麼玻璃不能包在淡入裡

Flutter 在透明度不到 1 時，會把那一塊先畫在一張獨立的透明畫布上，再疊到畫面。玻璃的背景模糊（`BackdropFilter`）取樣的是這張空白畫布，不是底下的正文，所以整段淡入期間都沒有模糊。透明度到 1 的那一幀不再需要獨立畫布，模糊才取得到正文，底下的字一瞬間全被糊掉。#71 的測試量的是「半途透明度在 0 到 1 之間」，數值都對，卻看不到模糊在哪一幀生效。

所以玻璃不包在 `Opacity`、`FadeTransition` 或 `AnimatedOpacity` 裡，測試在動畫途中用 `expectNoGlassUnderFade`（`test/support/glass_motion.dart`）檢查。

## Considered Options

- **保留滑入加淡入，讓模糊強度跟著淡入一起變**：可以修掉最後一幀的閃，但每個元件仍同時做兩件事，使用者覺得太多；而且每一幀都要重算模糊。只用在一定得淡入的玻璃（提示框、預覽背後的模糊）。
- **選單拿掉模糊**：最省事，但失去毛玻璃質感；否決。
- **換頁動畫也照這條規則**：「滑入、推進、覆蓋、縮放」四種換頁動畫都是移動加淡入，但它們照原本 App 的參數重做、由使用者在設定裡挑選（ADR 0020），不改。

## Consequences

- 閱讀選單、分頁列、工具列、「開始閱讀」膠囊收起時移得比原本遠一些（多了陰影的距離），同樣的時長下滑得稍快。
- 玻璃完全收起時不再畫，畫面重繪時不必為看不到的玻璃取樣模糊。
- 提示框在玻璃裡面再放玻璃時，裡面那塊仍包在外層內容的淡入裡，會在最後一幀才糊上；目前沒有這種用法，之後要加時另外處理。
- 之後新增的動畫照這條規則檢查：最後一幀是否等於靜止、一個元件是不是只做一件事、玻璃有沒有包在淡入裡。
