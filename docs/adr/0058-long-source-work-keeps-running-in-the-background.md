# 修書源與校驗書源離開夜讀也繼續，通知欄顯示進度

修復異常書源一次要十幾分鐘（每個網站等 AI 想 5 到 10 輪），原本修的時候得一直開著那一頁、螢幕不關，返回就停。使用者 2026-11-10 提出要丟到背景、通知欄顯示進度，邊讀書邊修；2026-11-11 談定下面五件。

在夜讀裡換頁、讀書時，這些工作本來就在主 isolate 繼續跑；真正會斷的是離開夜讀（切到別的 App、關螢幕），系統把沒有前景服務的 App 凍結或收掉。所以要做的是「離開也不斷」與「通知欄的進度」。

## 決定

- **推翻「修的時候不能離開頁面」**（畫面規格「AI 修書源」「修復異常書源」的返回等於停止，與當時否決的「背景跑加膠囊」）。當初的理由是修的時候可能正在編輯或校驗同一個書源；現在存修好的書源前會核對書源有沒有被改過或刪掉，改過就不存（`saveRepairedSource`），整批的重新校驗碰到別的校驗在跑就停下說原因。開始後可以返回，工作照跑。
- **涵蓋三件使用者按了才開始的長工作**：修復異常書源、單一書源的 AI 修復、校驗書源（使用者選的範圍是「修書源與校驗書源」）。背景下載不做：書架的網路書會自動下載（ADR 0008），每加一本就冒一條通知，和「預設克制」相衝，要做另外談。換源搜全部書源通常一分鐘內結束，不列。
- **一次只跑一件**：三件共用一個位置，一件在跑時另外兩件的入口是灰的（照原本「校驗中不能 AI 修復」），通知欄最多一條，不做排隊。整批修復裡的重新校驗算整批的一部分，不另外佔。
- **自己寫一個小的前景服務**（Kotlin，類型 `dataSync`）：只負責讓系統別凍結夜讀、讓 CPU 在關螢幕時照跑（部分喚醒鎖），與通知欄的進度；工作照舊在主 isolate，修書源與校驗的程式不搬家。從最近使用滑掉夜讀等於停止，已經存進去的照存。Android 15 起 `dataSync` 每天最多 6 小時，到了系統叫停時也照停止處理。
- **通知**（使用者在 HTML 候選上選了甲）：不跳出、不出聲，只在通知欄；標題是工作，內文是做到哪一段和數字，和頁面上那一段的副標同字；按鈕只有「停止」（按了內文變「正在停下…」），點通知本身回到那一頁。進度條是整件的進度：修復異常書源四段各佔 25%（第幾段的 25% 加這一段做完的比例），校驗只有一段；單一書源的 AI 修復不知道總數，不畫進度條，內文是修復頁正在做的那一步。做完就收掉，不留「做完了」。
- **回到那一頁**：書源管理的「修復異常書源」「AI 修復」在那件工作還在跑、或做完還沒看過結果時，推的是同一批的頁面，不重開；看過做完的結果、離開頁面後才算結束。書源管理在工作做完時重讀清單。
- 第一次開始這三件工作時要通知權限（原本只在第一次朗讀時要）；沒給的話工作照跑，只是通知欄看不到。

## 考慮過的做法

- **維持返回等於停止、只開著螢幕**：原本的做法；使用者要邊讀邊修。
- **只做修書源**、**連背景下載一起做**：見上面的範圍。
- **用 `flutter_foreground_task`**：做的和自己寫的一樣，多一個要跟著升級、可能要修補的第三方套件，功能比需要的多。
- **搬到 `workmanager` 的背景工作**：滑掉 App 也不會斷，但書源引擎、資料庫、AI 連線都要在另一個 Dart 引擎重開一份，等於重寫整批修復與校驗。
- **通知的寫法**：乙（標題帶數字、內文跟著 AI 每一輪換）字一直跳；丙（不畫進度條）看不出進度。四段各自從 0 跑到滿的進度條換段時會倒回去，改成每段佔 25%。
- **做完留一條「做完了」的通知**：使用者選收掉。
- **單一書源修復畫來回跑的動畫條**：一直在動，不夠安靜；不放進通知：離開夜讀就斷。

## 觸點

| 觸點 | 答案 |
|---|---|
| 書源類型、校驗怎麼判斷、付費章節 | 不適用：判斷照舊，只是離開夜讀不斷 |
| AI 修書源 | 做：見上 |
| 要登入、要網頁驗證 | 照 ADR 0038：背景工作碰到就停、記成狀態，整批修復本來就把需要登入、驗證的書源列為不修 |
| 搜尋、發現、換源、匯入 | 不做：換源搜尋一分鐘內結束 |
| 書架、書籍詳情、檢查新章節 | 不適用 |
| 下載、清除已下載 | 不做：見上面的範圍 |
| 閱讀器、播放器、偏好、進度、統計、書籤、朗讀 | 不適用；沒有新設定（ADR 0030） |
| 通知、鎖定畫面 | 做：新的通知頻道「背景工作」，和播放的媒體通知（ADR 0055）分開；鎖定畫面照系統設定 |
| 同步、備份、匯出 | 不適用：沒有新的資料 |
| `PRIVACY.md` 與「隱私說明」 | 不改：不多送任何資料。App 的「權限」頁「通知與背景任務」一段改寫：通知權限也用在修書源、校驗書源的進度，跑的時候開前景服務 |
| `README.md`、網站、`GLOSSARY.md` | 不做：是修書源與校驗的改進，不是新的一類功能 |
| `docs/design/` | 做：`screens.md` 的 AI 修書源、修復異常書源、書源管理 |
| iPhone | 不適用：iOS 不讓 App 在背景跑這種工作，離開夜讀照樣停；沒有通知 |
| 自動巡檢 | 做：新的服務資料夾與 Kotlin 檔排進分段 |
| 小說、漫畫、有聲、本地書 | 三類書源一樣修、一樣校驗；本地書不適用 |

## 後果

- 使用者 2026-11-11 回報播放通知在 vivo 上「多跳一個」，原因還沒查清（`PLAN.md`）；這個通知用新的低重要性頻道、只提醒一次、靜音，前景服務只在開始時啟動一次、之後只更新，是不靠手機能做的防備。在 vivo 上會不會跳，和播放通知是同一個待查的問題。
- 修的時候不再強制開著螢幕：前景服務加喚醒鎖讓關螢幕也照跑。
