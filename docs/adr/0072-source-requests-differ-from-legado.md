# 書源請求和 Legado 刻意不同的兩處：瀏覽器標識用當下的 Chrome 正式版，正文分頁留 1000 頁上限

連書源網站的請求照 Legado（ADR 0063），這兩處刻意不同。

## 決定

- **預設的瀏覽器標識（User-Agent）用當下的 Chrome 正式版**（使用者 2026-11-18 要最新的）：書源沒寫 User-Agent 時，電腦版送 `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/158.0.0.0 Safari/537.36`，`m.` 開頭的網站送手機版（`Android 10; K`，同真的 Chrome 的寫法；Legado 只有一個電腦版）。網路封面與封面存檔直接用書源連線、不經攔截器，沒帶標識時也送電腦版這一個（同 Legado 沒有 UA 時補上預設，原本送 Dart 自己的）。版號照寫入時的正式版、只寫主版號，後面是 `.0.0.0`（真的 Chrome 現在就這樣送）；不寫還沒出的版號，網站看得出是假的。Chrome 每 4 週出一版，使用者說要更新時照當時的正式版改。
  - Legado 寫 `Chrome/128.0.0.0`：它內建的網路元件就是 Chrome 128，自稱的版本和連線方式對得上。夜讀的連線不是 Chrome，寫哪一版都只是自稱，對得上的好處拿不到；改前是 2021 年的 Chrome 91。
  - Cloudflare 通行後的請求、書源登入頁與網址選項的 webView 頁用手機內建瀏覽器自己的標識；規則的 `java.getWebViewUA()` 讀到內建瀏覽器的標識前（全新安裝、還沒開過瀏覽器）回這裡的手機版。規則 JS 的 Jsoup 連線照 Jsoup 的預設（Chrome 79），同 Legado 用的 Jsoup。
- **正文分頁照 Legado 抓到「下一頁網址出現過」或「下一頁就是下一章」為止，另外留 1000 頁上限**：Legado 沒有頁數上限。下一章網址沒有傳進來時（書架自動下載、漫畫、有聲書），同 Legado 查這本書存著的目錄，用下一章、沒有就第一章當停點；原本夜讀這幾條路沒有停點，「下一頁」規則抓到下一章的書源靠 100 頁上限報錯才停，上限放寬前一起補上。夜讀的書架自動下載沒人看著，規則一直給新網址時會抓不完，所以留一個正常章節碰不到的上限，碰到時整章失敗、不存半章。原本是 100 頁：2026-11-13 AI 修復實跑的环安小说网一章 110 到 121 頁，校驗報「正文分頁超過 100 頁」，AI 只好改寫成規則 JS 自己一頁頁抓。

## 量到的

2026-11-18 用 589 個書源的匯出檔整批校驗（含發現，同時 8 個），一次只改一處：

| | 通過 | 耗時 |
|---|---|---|
| 改前（Chrome 91、100 頁） | 350 | 10:01 |
| 只換 Chrome 158 | 341 | 9:14 |
| 再把上限改 1000 頁 | 347 | 8:45 |

翻轉的全是校驗超時或上游 502、403，同一批書源在三次之間翻來翻去。換 UA 那次翻轉的 17 個，兩種標識各重跑一次：Chrome 91 過 11 個、158 過 10 個，過的不是同一批。兩處都沒有量得到的差別；三次都沒有書源碰到 100 頁上限，也沒有書源因為上限放寬而把下一章接進來（校驗每章都傳了下一章網址，量不到書架自動下載那條路，那條路靠上面的停點）。擋電腦版標識的網站（腐书网、鲤鱼乡#2、神话之后）用 curl 試 91、128、158 一樣被擋，要書源自己寫手機版標識。

## 考慮過的做法

- **照 Legado 寫 128**：見上，對得上的好處夜讀拿不到；使用者要最新的。
- **寫一個比正式版大的版號**：網站看得出是不存在的瀏覽器。
- **拿掉正文分頁上限（照 Legado）**：書架自動下載碰到一直給新網址的規則會停不下來；1000 頁對正常章節沒有差別。
- **上限照舊 100 頁**：一章超過 100 頁的網站讀不到，AI 修復只能繞過。
