# 閱讀器的正文骨架照一頁真正的行畫，頁首頁尾一蓋紙就畫成骨架

開書、跳到別章、改排版設定與重載內容時，正文區蓋上紙（`LoadingVeil`）的同一刻，頁首頁尾每個設定了的欄位就畫成骨架（照真正內容的寬度）。正文區的骨架照一頁真正的每一行畫：開書時有上次記下的那一頁（ADR 0024）就照它，紙一蓋上就淡入；其他時候紙中間先空著，正文取到後先只排第一頁，骨架照第一頁的每一行淡入，淡入播完才排前後其他頁，全部排好後紙照骨架換場掀開，每一條剛好換成那一行字。使用者的判斷是（2026-10-17）：骨架一出現就是那一頁的樣子、從頭到尾不換形，才連貫、有邏輯；先畫固定的段落樣式、之後再換一次樣式，看起來不連貫。

骨架等的是「第一頁排好」這件事，不設「等一段時間還沒好才出骨架」的門檻。排版照 ADR 0018 切成每幀放得下的小塊，骨架淡入照 ADR 0023 播完才往下做。

為了讓第一幀就有骨架，閱讀設定在閱讀器建立時從已預載的 SharedPreferences 同步讀出，不再先等一次非同步載入。

## Considered Options

- **紙一蓋上就畫固定的段落樣式**（本 ADR 原本的決定）：正文區不會空著，但段落與行長是猜的，換場時骨架與正文對不上；使用者改選照真正的一頁畫。
- **先畫固定樣式，第一頁排好再淡換成真正的行**：不留空白，但載入中骨架看得到換一次形，使用者覺得不連貫，否決。
- **只先照目錄的章名畫第一條**：從章首載入時章名對得上，其他行仍是猜的；照第一頁畫已經涵蓋，不另做。
- **載入快時不出骨架**（等約 0.2 秒還沒好才浮出）：章節有快取時可以省掉骨架一閃，但載入通常沒那麼快，否決。
- **頁首頁尾只把進度畫成骨架**：時間、電量、書名、章名、章節序號在正文排好前就知道，可以照常顯示，只有本章／全書進度要等排版。使用者選擇整條資訊列一律畫成骨架，否決。

## Consequences

- 沒有上次的紀錄時，正文取到、第一頁排好之前，正文區是空白的紙，只有頁首頁尾的骨架；要上網抓的章節空白比較久。
- 第一頁排好到全部排好之間多了一段骨架淡入（`AppMotion.fade`），內容比原本晚一點出現（ADR 0023）。
- 骨架照捲動最後停住的位置畫：書頭書尾排進來、或前後章取不到時夾在可捲的範圍內（例如從書的最開頭開書時章名頂在最上面），和掀開後的正文一致。
- 載入途中又蓋一次紙（第一頁淡入中跳章、改排版，或開書的紀錄對不上），畫著的骨架照原本的版面淡完，才換成新的第一頁。
