# 書源分成小說、漫畫、有聲，只看書源的類型欄位；匯入照字樣補判、校驗照正文改

使用者 2026-11-09 要在整理書源時選要留下哪幾類，把漫畫源、有聲源留給漫畫閱讀器（`feat/images-comics`）與有聲書播放器（`feat/audiobook-player`）。在這之前，類型不是文字、或名稱／分組／網址帶有聲、漫畫、影視字樣的書源一律算「非小說」：匯入時停用並加上「非小說源」分組，「刪除非小說源」與清理失效書源都會刪掉。三條分支由使用者同一批合併、發成同一個測試版，所以不做「留著、還不能用」的過渡狀態。

## 決定

- **三類加不支援**（`BookSourceKind`）：類型 0 是小說、2 是漫畫、1 是有聲；類型 3（文件）、其他值，和類型 0 但帶影視字樣的是不支援。影視不另成一類（使用者：「影視就有點太多了」），照舊停用、可刪。
- **只看類型欄位**：這個書源是哪一類，問 `sourceKind`，它只看 `bookSourceType`（加上類型 0 的影視字樣）。漫畫分支問「是不是漫畫源」就看它，不自己看名稱或類型。
- **匯入時照字樣補判，寫進類型**（`prepareIncoming`）：類型寫 0 的，帶有聲字樣改成 1、帶漫畫字樣改成 2。匯入、還原備份、書架交換檔都這樣；同步不做，以免一台照正文改回 0、另一台又照字樣改成 2。舊版加的「非小說源」標記：補判後是漫畫、有聲的，拿掉標記與「異常」、重新啟用（停用是舊版替使用者做的）。資料庫 schema 15 對既有書源做同一件事。
- **校驗照正文改類型**：漫畫、有聲源和小說一樣跑搜尋、詳情、目錄、正文；校驗抓正文時留下圖片（`keepImages`）。有十足把握才改（`ChapterContentKind`）：至少 200 字的成段文字是小說（每章附插圖的小說也是），至少兩張圖、不到 50 字是漫畫，只有音訊連結、沒有圖、不到 20 字是有聲；判斷不出來維持原樣。正文算不算抓到照改過之後的類別：小說要讀得到字、漫畫要有圖、有聲要有網址。
- **手動、校驗與之後的 AI 復判都改同一個欄位，誰最後改算誰的**：書源編輯加「書源類型」選單（小說、漫畫、有聲；原本是文件或其他值時也列出來）。
- **留下來的漫畫、有聲源照書源原本的開關**，不強制停用；不進文字書的搜尋、發現與閱讀（`isSearchEnabledByRuntime`、`isReadingEnabledByRuntime`），健康狀態照校驗結果，不因為是漫畫、有聲就列入清理。
- **在兩處選留下哪幾類**：匯入預覽多「漫畫源」「有聲源」兩個勾選，預設勾著，不勾的不匯入；「刪除非小說源」改成勾選漫畫源、有聲源、影視與文件源，預設只勾影視與文件源。書源管理的篩選多「漫畫源」「有聲源」，有這類書源時才出現。不做成「保留哪幾類」的設定。

## 考慮過的做法

- **多一類「其他」讓影視也能留**：沒有對應的播放計畫，留著用不到。
- **影視、文件各自一類**：同上。
- **只看類型，字樣不補判**：類型標錯的漫畫、有聲源會照舊被刪。
- **類型不動，另記一欄「判定的類別」**：兩處說了算，匯出給 Legado 時類型還是錯的，同步要多帶一欄。代價是從同一個網址重新匯入會蓋回作者寫的類型，要再校驗一次。
- **手動改過的記一個標記，校驗不再動**：同上多一欄；手動設錯時校驗也救不回來。
- **留下來的照舊強制停用，標籤寫「即將支援」**：上線時得一個個打開，或升級時替使用者打開卻分不出哪些是他自己關的；三條同批合併就不需要過渡狀態。
- **只在匯入預覽選，或只在書源管理選**：前者已匯入的不能整類清，後者匯入幾千個時先多一堆用不到的。
- **閱讀用的正文也留下圖片，校驗直接看它**：那是文字書插圖（`feat/text-illustrations`）的範圍；這裡只讓校驗多要一份帶圖的正文。

## 後果

- 匯入的書源類型可能和作者寫的不同，匯出給 Legado 時是改過的值。
- 漫畫、有聲源的校驗會實際抓網站，校驗時間跟著書源數變長。
- 校驗只抽查前幾章的正文；判斷錯了，使用者在書源編輯改類型。
