# 左右對齊把湊不滿一格的空隙攤進字距

正文的文字框寬度是整數個字格（ADR 0005），內容寬（螢幕寬扣掉左右邊距）通常湊不滿，剩下不到一格的空隙原本平分在正文兩側，所以正文左右兩緣都比頁首頁尾的資訊內縮一點，最多半格。使用者要正文左右兩緣都貼齊頁首頁尾。2026-10-15 起，「版面」多一個「左右對齊」開關，預設開啟：建立排版規格時（`ReaderV2ControllerHost.specFromStyle`）把空隙平均攤進每一格的字距（`ReaderV2TextLayoutFrame.justifiedLetterSpacing`），用新字距重量字格，文字框就撐滿內容寬，只留 0.05 的 paragraph slack 防浮點誤差。每一格仍然等寬，直行照樣對齊；每格多出的字距不到「一格寬 ÷ 每行字數」，18 號字約 1 px 以內。

## Considered Options

- 調一個預設邊距讓正文剛好貼齊：空隙取決於螢幕寬、字號與字距，換一台手機或改字號就對不上，否決。
- 正文貼齊左邊、空隙全留在右邊：左邊對齊，右邊最多差將近一格，使用者要左右都對齊，否決。
- 讓頁首頁尾跟著正文內縮：使用者確認頁首頁尾目前的位置是對的，要動的是正文，否決。
- 只靠手動調左右邊距：邊距每變一次，畫面上的留白要等跨過一格才跳一次（跳半格），調不到剛好貼齊，所以保留為開關關閉時的行為，不當成解法。

## Consequences

- 開啟時實際字距會隨螢幕寬與邊距微幅變動；使用者設定的「字距」是基準，攤進去的空隙加在它上面。
- 只有排滿的行兩緣都貼齊；段落最後一行、行尾是英數字段（ADR 0007 行尾不補右側）的行，右緣照舊短一些。
- 字距寫進排版規格，排版簽章跟著改變，換開關或換邊距會重新排版，不會沿用舊的量測快取。
