# 從書架開書不做封面放大轉場

從書架點書開閱讀器，照使用者選的換頁動畫（`AppPageTransition`，預設上浮），不做「書卡封面放大翻開成閱讀頁」。2026-10-14 曾做過封面放大（`d96c0cc`），使用者在實機上看過後要求移除：書架封面是縮圖，放大到整頁時畫質很差；而且封面放大結束時正文常常還沒準備好，接著仍然看到載入轉圈，轉場沒有真的把等待藏起來，反而多了一段。

## Consequences

- 2026-10-14 清單與書籍詳情之間的封面共享元素轉場（Hero）也已移除：使用者看過後覺得醜。改成全 App 共用一種換頁動畫，由使用者在「外觀與主題」從上浮、平移、淡入、展開四種挑選，返回一律是開啟倒著播；「展開」從手指按下的位置撐開，不是從封面。
- 2026-10-15 換頁動畫改成八種（照 Telegram、Android 系統、Legado 等的參數），返回改成先快後慢、不再倒著播。其中「展開」照 iOS 18 縮放，從被點的書卡長出來：長出來的是新頁本身縮在卡片裡，不是把封面圖放大，所以沒有縮圖畫質的問題；開閱讀器時正文區先蓋著紙（`LoadingVeil`），也不會在轉場後才看到轉圈。這不是本 ADR 否決的封面放大。
- 之後若要重新考慮開書轉場，前提是閱讀器在轉場結束時已經能直接顯示正文（見閱讀器開書流程），並且有可放大的高解析封面。
