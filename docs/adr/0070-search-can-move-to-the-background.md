# 搜尋可以放到背景，回來看到同一次的結果

搜全部書源要一陣子（396 個書源要一兩分鐘，慢的書源每種寫法等 20 秒）。使用者 2026-11-11 要：按一顆鈕把搜尋放到背景，自己先去看書，之後重開搜尋頁看到它還在跑、或已經跑完的結果。原本斷在兩處：搜尋頁關掉（回書架開別本書）就取消搜尋，離開夜讀、關螢幕時沒有前景服務、系統凍結夜讀。研究紀錄在 `docs/research/background-book-search.md`。2026-11-18 由 agent 照研究的建議定，使用者之後再改。

## 決定

- **按一下放到背景**：搜尋中，進度那一列右邊一個「放到背景」；按了，這一次搜尋就成了背景工作（ADR 0058 的第五件），已搜完、已送出的書源不重送，頁面不關、不跳提示，那一列右邊換成「暫停」。沒按的搜尋照舊：被整頁蓋住時暫停送出、關頁就取消。放到背景的不再跟著頁面暫停。
- **結果只留最近一次**：一次只有一件放到背景的搜尋，不做多次的搜尋歷史（搜尋紀錄照舊只記關鍵字）。結果在記憶體裡跟著這件工作；每搜完一個書源，同時在 App 的私有資料夾附加一行（這個書源搜到的書，或失敗原因；零本也記，才分得出搜完沒有）。開始時先寫搜尋條件：關鍵字、類別、範圍、精準、這次要搜的書源網址。不進資料庫、不同步、不進夜讀的備份。開 App 時只讀這份檔、合併成搜尋結果等打開搜尋頁、進場播完才做。
- **結果什麼時候清掉**：照 ADR 0058「回到那一頁」：做完而且在搜尋頁上看過、離開搜尋頁之後才刪；開始新的一次搜尋也刪。做完之後夜讀被系統收掉的，下次打開搜尋頁照樣看得到。
- **回來看到結果**：從沒帶關鍵字的入口打開搜尋頁（書架、發現、我的的搜尋鈕，點通知也是）時接回這一次：輸入框是它的關鍵字，類別、範圍、精準照它當時的（不寫回偏好），結果、進度、失敗書源照它。帶書名或書源打開的（例如閱讀統計、書籤裡書已移除、書源管理的「搜尋」）是另一次普通搜尋，背景那次照跑。接回之後搜新的關鍵字，或換類別、範圍、精準（原本就會重搜），就結束背景那次、開始新的普通搜尋。
- **暫停與結束照 ADR 0058**：暫停是不再送新的書源、正在搜的那幾個取消，繼續時重搜它們；從最近使用滑掉、被系統收掉都算暫停。暫停後搜尋頁那一列寫「已暫停 124/396」、右邊「繼續」（別的背景工作在跑時灰掉）；繼續只搜沒搜完的書源，這段時間刪掉、停用的書源略過。結束（頁首的「結束」或通知的「結束」）是結果留著、不再續搜，同普通搜尋按「結束」。
- **一次一件**：放到背景的搜尋佔 ADR 0058 的位置，在跑時修書源、校驗書源、AI 找書的入口灰掉；別件在跑時「放到背景」灰掉，不排隊。暫停中的不佔位置；暫停中再把另一次搜尋放到背景，暫停的那次就結束（同修書源與校驗）。
- **通知**：標題「搜尋書籍 · 關鍵字」，內文和搜尋頁那一列同字（「正在搜尋 124/396」，剩不到三個書源時「還在等：書源名、書源名」，照 ADR 0058「內文和頁面上那一段的副標同字」），進度條照搜完幾個書源走，「暫停」「結束」兩顆；點通知推接回的搜尋頁，已經在那一頁就不動。
- **閱讀的抓章插隊**：放到背景的搜尋送下一個書源前，先等閱讀時正在抓的抓完：文字閱讀器抓沒存的章（含預先載入的下一章）、漫畫抓一章的圖片清單、有聲書抓一集的音訊。最多等 10 秒，抓章卡住時搜尋不跟著停。同時搜的書源數照普通搜尋（16 個）。這只排還沒送出的：已送出的最多 16 個書源（每個最多三種寫法）照跑完，正在規則 JS 裡的也停不下來（ADR 0034），所以不保證閱讀的抓章在幾秒內回來；這條沒在手機上量過。
- **搜尋快取**：放到背景的搜尋照普通搜尋寫搜尋快取（從結果進書籍詳情後，換源與換封面先列剛搜到的來源）。接回背景那次的搜尋頁關掉時不清快取（之後還會回來看）；其他搜尋頁照舊關掉就清，背景搜尋之後寫的那些留到下次清。

## 考慮過的做法

- **讓搜尋頁的狀態一直留著**（研究的方案一）：篩選、排序、輸入框都跟著留，不同入口打開會互相影響；程序被收掉時沒有東西可讀回來。
- **多次搜尋歷史**：每個關鍵字都能回看，要列表、刪除與容量管理；使用者要的是「回來看到剛剛那次」。
- **新的資料表**：要資料庫遷移，結果卻只活到看過為止；附加一行的檔案就夠讀回來。
- **整份結果每搜完一個書源重寫一次**（同 ADR 0058 的暫停存檔）：結果上千本時每次在主執行緒重編整份。
- **背景時降低同時搜的書源數**（研究的原型 A）：整件變慢，閱讀的抓章照樣排在已送出的後面；也違反設計原則「相信手機的效能」。
- **書源 isolate 前的優先佇列**（研究的原型 B）：要改四條書源 isolate 共用的派送，搜尋、下載、發現、換源、AI 工具都經過，回歸面大；等手機上量到插隊不夠再做。
- **按「放到背景」就關掉搜尋頁**：使用者可能還想看已經出來的結果；返回本來就是一下。
- **每次搜全部書源都自動放到背景**：會佔住一次一件的位置，修書源、AI 找書跟著灰掉。
- **放到背景時跳一則「已放到背景」的提示**：ADR 0009；那一列換成「暫停」、通知欄出現就是回應。

## 觸點

| 觸點 | 答案 |
|---|---|
| 書源類型、校驗、付費章節 | 不適用：搜法照普通搜尋，照類別送給那一類的書源與聚合源 |
| AI 修書源 | 不適用；一次一件：放到背景的搜尋在跑時 AI 修復的入口灰掉 |
| 要登入、要網頁驗證 | 照 ADR 0038：背景不等人，要登入、要驗證才搜得到的書源記成失敗，可以「重試失敗」 |
| 搜尋 | 做：見上 |
| 發現、手機上的檔案匯入 | 不適用 |
| 換源 | 不適用：換源搜尋照舊一分鐘內結束、不放背景；搜尋快取照上面 |
| 書架、書籍詳情 | 不適用：結果在搜尋頁上看，點進去照舊推書籍詳情 |
| 下載、清除已下載、檢查新章節 | 不適用 |
| 閱讀器、播放器 | 做：閱讀時的抓章插隊（見上）；畫面不變 |
| 偏好、設定 | 不做：沒有開關（ADR 0030）；接回時的類別、範圍、精準不寫回偏好 |
| 進度、閱讀統計、書籤、標註、朗讀 | 不適用 |
| 通知、鎖定畫面 | 做：照 ADR 0058 的背景工作通知 |
| 同步、備份、匯出 | 不適用：結果檔只在這台，不同步、不進備份 |
| `PRIVACY.md` 與「隱私說明」 | 不改：只向書源的網站送請求，同普通搜尋。App 的「權限」頁「通知與背景任務」一段改寫，列出用到通知權限的背景工作 |
| `README.md`、網站 | 不做：搜尋的改進，不是新的一類功能 |
| `GLOSSARY.md` | 做：「背景工作」加上搜尋書籍 |
| `docs/design/` | 做：`screens.md` 的「搜尋」「背景工作」 |
| iPhone | 照 ADR 0058：沒有通知；離開夜讀時系統停住夜讀，回來接著送，這段時間正在搜的書源多半逾時、算失敗，可以「重試失敗」；被收掉時照暫停 |
| 自動巡檢 | 不改分段：新檔都在既有的 `lib/features/search/` 與 `lib/core/services/` |
| 小說、漫畫、有聲、本地書 | 三類書源一樣搜、一樣放到背景；本地書不適用。閱讀的抓章插隊三類的閱讀器都接 |

## 後果

- 背景搜尋跑的時候，閱讀時抓沒存的章最多等已送出的 16 個書源跑完；書架上的書多半已經自動下載好（ADR 0008），碰到的時候少。手機上覺得慢再做優先佇列。
- 結果檔在做完、看過之前一直留著；沒去看的話，下次放到背景或開新的一次搜尋時才刪。
- 接回背景那次時，搜尋頁的類別、範圍、精準是那次的，和偏好可能不同；搜新的一次就回到偏好的。
