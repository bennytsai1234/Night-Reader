# 骨架照上次的畫面畫，骨架換場由左而右

> 2026-10-20 改寫：原本換場方式與時長可在「外觀與主題」選，連同 #83 的骨架深淺與呼吸一起拿掉。使用者說可以控制的選項多到控制不完；固定的值就是使用者在原型上選的預設（由左而右、0.6 秒、標準深淺、由左而右・緩的呼吸）。

骨架照樣出現，但形狀照上次看到的真實畫面畫，而不是固定的樣式：書架記下本數與前 30 本的書名、作者，骨架的書名長條照真正書名的換行與寬度畫；閱讀器在離開或 App 切到背景時記下畫面上每一行字的位置與當時的進度，下次從同一處、用同樣的版面開這本書時，紙上的骨架照那一頁畫，頁尾進度欄的骨架照當時的字樣量寬。骨架換場時每一條長條剛好換成那一行字，不會有對不上的收尾跳變。骨架由左而右換成內容，0.6 秒。使用者的判斷是（2026-10-17）：要的是骨架之後的換場自然，不是省掉骨架；在原型上比過整頁淡入與由左而右後，選了由左而右。

紀錄存在偏好設定：開 App 時已整份讀進記憶體，開書時同步取得，換頁動畫播放中不碰磁碟（ADR 0018）。紀錄也記下哪幾行是章名（長條照章名與正文的字級比放大）和那一章正文的雜湊。對不上（換了位置、改了排版、沒有紀錄）時不用紀錄，改等第一頁排好照它畫（ADR 0016）；開書時位置與版面相同、取到正文才發現正文換過（替換規則、重新取得）時，紀錄的骨架淡掉，同樣改等第一頁。跳章、改排版與重載內容一律照第一頁畫。

## Considered Options

- **整個書架記下來、開 App 直接畫出書**：封面仍要解碼，只能再閃一下骨架或讓系統啟動畫面多停，好處只有少等一點（ADR 0023），否決。
- **書一本一本依序淡入**：ADR 0017 要的是書與封面一起出現，看起來也比較碎，否決。
- **由左而右加一道柔邊光帶掃過**：使用者覺得多餘，只要左邊先出、右邊後出。
- **用版面的 `presentationSignature` 判斷版面是否相同**：它是 `Object.hash`，每次啟動 App 的雜湊種子不同，存起來下次比不上；改成把決定行位置的版面參數逐項寫成字串。

## Consequences

- 換場時長從原本的 0.25 秒（閱讀器）與 0.4 秒（書架）一律改成 0.6 秒。
- 整頁淡入（`SkeletonRevealStyle.fade`）與其他深淺、呼吸的值留在元件裡（骨架自己淡掉時用整頁淡、測試要量每一級的深淺），使用者選不到。
- 第一次開新版、或讀一本十本以前讀過的書時沒有紀錄，紙中間先空著，第一頁排好才出骨架（ADR 0016）。
- 閱讀器記下的進度在開書時先放進進度通道，排好後換成重算的同一個進度。
