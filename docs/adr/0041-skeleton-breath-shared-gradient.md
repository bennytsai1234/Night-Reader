# 骨架呼吸：漸層每個骨架每幀一道，形狀照舊各自畫

平板書架 7 欄時骨架方塊是手機的一倍半以上，開 App 的骨架呼吸在平板上掉幀。所有骨架（開 App、書架、書籍詳情、發現、書源管理、設定各頁、閱讀器頁首頁尾）的呼吸改成：每個骨架每一幀、每種骨架色只建一道整個畫面寬的漸層（螢幕座標），底下每個形狀照舊畫在自己的位置，畫之前把畫布的橫軸換成螢幕的橫軸用那道漸層；到螢幕的轉換只算到骨架最外層，那一層一幀算一次；不捲動的骨架清單不每列各一層。長相和原本一樣（逐像素最多差 1 階），平板呼吸每幀中位數從 2.3–3.1ms 降到 1.5–1.8ms（電腦，2026-11-02）。使用者 2026-11-02 在儀表板上選定，理由是不犧牲原有的長相；每幀的工作仍跟形狀數成正比，只是便宜，要更低的中位數不值得換掉長相。

量出來的成本在哪（電腦，平板 69 個形狀）：每個形狀各建一道漸層不是大宗；每個形狀從頭沿元件樹算到螢幕的轉換約 0.7ms、清單每列各一層每幀重錄才是。要再省時先量，不要照直覺改。

## Considered Options

- **整個骨架蓋一層遮罩**（第一版做法 B，分支 `fix/skeleton-breath-mask` 已刪）：形狀畫一次、每幀只換遮罩，呼吸每幀約 0.8ms，和形狀數無關。但遮罩蓋住骨架裡所有東西：卡片底跟著呼吸（深色最多差 8 階），只好把卡片底拉出來另外畫，拉出來就失去裁切、捲動位置與第一幀的先後（Codex 審查，都重現過）。補不完，否決。
- **開 App 整段用定格畫面**（做法 A，分支 `fix/skeleton-breath-stills` 已刪）：呼吸只混合兩張圖，每幀約 0.8ms。只修開 App，其他頁照舊；長出時頁首與分頁列跟著由左而右掃進來，長相變了。沒選。
- **只在開 App 書架用遮罩、其他頁照舊**：兩套呼吸並存，使用者不考慮。

## Consequences

- 呼吸開頭偶爾一幀撐破上限的是舊生區回收（ADR 0036「待處理」），三個做法都有，不屬於這裡。
- 證明的框架：`test/frame_budget/launch_skeleton_work_test.dart` 數呼吸每幀用了幾道漸層（手機、平板一樣，改前 44／69、現在 6），並和改前逐像素比；`test/shared/widgets/skeleton_breath_look_test.dart` 比長相；重複量測用 `FRAME_REPEAT=5 FRAME_GC=1 FRAME_SIZE=1280x880 bash tool/frame_budget_compare.sh`。
