# Cloudflare 的瀏覽器檢查由看不到的瀏覽器自動通過，要真人勾選的網站當成不能用

書源網站回 Cloudflare 的瀏覽器檢查頁（「請稍候」「Just a moment」）時，夜讀在背景用手機內建的瀏覽器（WebView）打開那一頁，等檢查自己跑完，把通行 Cookie（`cf_clearance`）存進 Cookie 檔，再重送原本的請求；之後帶著通行 Cookie 的請求一律用那個瀏覽器的標識，因為通行 Cookie 只對它有效。整個過程不需要使用者操作，所以閱讀、搜尋、背景下載、檢查更新與書源校驗都一樣，和 ADR 0013「不做需要使用者操作的驗證」不衝突。

檢查停在要真人勾選的那一步（Turnstile 勾選框）時，夜讀不替使用者勾，也不跳出頁面請使用者勾：那個書源當成暫時不能用，書源校驗把它隔離。網站直接封鎖目前網路（Cloudflare 的「Sorry, you have been blocked」、網站防火牆寫明擋 IP 歸屬地）時也一樣，錯誤寫明是網站封鎖了網路，不是書源壞了。

2026-10-25 用真的瀏覽器實測源倉庫被擋的書源：霹靂書坊的檢查約 12 秒自己通過；天空書屋、思路客、一流小說網是封鎖網路，誰來開都過不了。

## Consequences

- 瀏覽器要接在畫面上（看不到、點不到）網頁的計時器才照常跑，所以檢查期間在 App 根部掛一個透明的 WebView（`HiddenWebViews`）。通行 Cookie 是網頁程式讀不到的 HttpOnly，從原生端讀（`night_reader/webview` 頻道）。
- 通不過的網站記十分鐘，這段時間裡同一個網站的請求直接回報，不讓每章都再等半分鐘。
- 書源校驗不再用另外一套簡化的背景 isolate，改成每個書源開一個和書源 isolate 同樣環境的 worker（`SourceWorker`，ADR 0028）：網頁渲染（網址選項 `webView`）、規則的 fetch、Cookie 檔與資料庫都和閱讀時一樣，逾時照樣直接結束 worker。原本校驗一律拒絕 `webView` 書源，只是因為那套 isolate 做不到。

## 考慮過的做法

- **程式自動勾選真人驗證**：使用者 2026-10-25 要求過；那個勾選框就是專門確認「是真人在操作」的驗證，自動勾等於破解別人網站的驗證碼，不做。使用者接受「勾不了就當成不能用」。
- **跳出頁面讓使用者勾**：使用者不要，每次看書、每次校驗都要勾太麻煩。
- **校驗時跳過 Cloudflare 與網頁渲染**（原本的做法）：校驗結果和實際閱讀不一致，能用的書源被標成失效。
