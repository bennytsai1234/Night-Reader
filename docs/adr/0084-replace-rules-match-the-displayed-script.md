# 正文先轉繁簡再套替換規則，規則照字面與顯示的寫法各比一次

開了繁簡轉換的讀者，照畫面上的字寫規則（例如簡體站開「簡轉繁」，照畫面寫繁體的「廣告詞」），夜讀原本先套規則、整章處理完才轉，規則對的是網站的簡體原文，對不到；從 Legado 帶來的規則也是照轉換後的字寫的。對照 Legado 閱讀的 R10，2026-11-25 定案。

## 決定

- **先轉再套，同 Legado**（`ContentProcessor.getContent`、`BookChapter.getDisplayTitle`）：正文照「去重複章名、去分頁殘留、重新分段 → 繁簡轉換 → 替換規則 → 段落修復與排版整理」的順序；章名先轉再套標題規則。
- **規則的字兩種寫法都比**：每條規則照字面比一次；規則的字轉成顯示的寫法（和正文同一個轉換器）後和字面不同時，再用轉過的比一次。照畫面寫的規則（選字「隱藏」「替換」建的、讀者照畫面打的、Legado 帶來的）用字面那次對上；以前照網站原文建的簡體規則用轉過的那次對上。
  - 一般規則整段轉。正則只轉非 ASCII 的字（漢字與全形標點），一段連續的一起轉；語法照原樣：`\p{…}`、`\k<…>`、反斜線跳脫、具名群組的名稱、字元類別的括號。
  - **替換成的字照字面放，不轉**（同 Legado）。
  - 每條規則轉過的字算一次就留在記憶體裡重用；轉完和字面一樣時只比一次。
- **去重複章名照 Legado 看網站原文**：正文開頭的章名找不到時，章名套了標題規則再找一次；網站原文是簡體還是繁體不一定，標題規則照字面、轉繁、轉簡都比。
- **選字「隱藏」「替換」照畫面上的字建規則**：找原文那一段也先轉再套既有規則，和畫面一樣的寫法；替換規則面板的測試原文、試跑也照這個寫法。找原文時有規則跑超過逾時，照畫面上的做法停用它。

## 考慮過的做法

- **完全照 Legado，規則照字面比**：之前夜讀選字「隱藏」「替換」建的規則是網站原文的寫法（多半是簡體），預設又是簡轉繁，改了先後這些規則全部失效。開 App 時把「選字隱藏」「選字替換」兩個分組的規則轉一次也救不全：分組改過名的、之後換了繁簡設定的，照樣失效。
- **規則的字只用轉過的**：轉換器轉兩次不一定一樣，照畫面寫的規則被轉壞：「干擾」再轉成「幹擾」、「襯托」成「襯託」、「幾里」成「幾裏」、「征討」成「徵討」、「斗膽」成「鬥膽」。選字隱藏「干擾。」對不到正文，畫面卻提示已隱藏。簡轉繁的詞組約 2.4% 再轉一次會變字。
- **替換成的字也轉成顯示的寫法**：同上，照畫面寫的替換字會被轉壞（換成「襯托」，正文顯示「襯託」）。

## 後果

- 和 Legado 刻意不同：Legado 照字面比，寫錯寫法就對不到；夜讀照字面與顯示的寫法各比一次。規則本身存的仍是讀者寫的字，匯出給 Legado 時照原樣。
- 替換成的字照字面放：以前用簡體寫替換字的規則，在繁體正文裡會插進簡體字（同 Legado）。
- 轉過的那次是照規則自己的字轉的，沒有正文的上下文。一個字對到好幾個字時（「发」是「發」或「髮」），照原文寫的規則只寫單字可能對不到：規則「发」對不到正文的「头发」（轉成「頭髮」）、「面」對不到「面条」（「麵條」）；正則被語法隔開的字也是各自轉，`(头)发` 對不到「头发」。寫成詞（「头发」「发现」「干净」「面条」「后来」）就對得到。照畫面寫的規則不受影響，字面那次就對上。
- 照轉換器沒採用的異體字寫的規則對不到：轉換器把「这里」轉成「這裏」，規則寫「這裡」對不到。
- 關掉繁簡轉換時只照字面比：在簡轉繁下照畫面建的繁體規則，對不到簡體原文。
- 不套規則時，改了先後的正文和原本一字不差（《西游记》101 回，簡轉繁、繁轉簡各比一次），已存的書籤、標註與閱讀位置不動。套了規則的書，規則對到的地方變了，位置照新的正文對，和新增一條規則時一樣。
- 匯出書不做繁簡轉換，規則照字面套，和原本一樣。
