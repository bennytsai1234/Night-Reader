# 正文先轉繁簡再套替換規則，規則照顯示的寫法比對

開了繁簡轉換的讀者，照畫面上的字寫規則（例如簡體站開「簡轉繁」，照畫面寫繁體的「廣告詞」），夜讀原本先套規則、整章處理完才轉，規則對的是網站的簡體原文，對不到；從 Legado 帶來的規則也是照轉換後的字寫的。對照 Legado 閱讀的 R10，2026-11-25 定案。

## 決定

- **先轉再套，同 Legado**（`ContentProcessor.getContent`、`BookChapter.getDisplayTitle`）：正文照「去重複章名、去分頁殘留、重新分段 → 繁簡轉換 → 替換規則 → 段落修復與排版整理」的順序；章名先轉再套標題規則。去重複章名照 Legado 看網站原文，那一步用的章名也不轉。
- **規則的字也轉成顯示的寫法**：套規則前，規則的「替換內容」與「替換為」用和正文同一個轉換器轉（簡轉繁時轉繁、繁轉簡時轉簡、不轉換時照原樣）。照網站原文寫的與照畫面寫的規則都對得到。
  - 一般規則整段轉。正則只轉非 ASCII 的字（漢字與全形標點），一段連續的一起轉；語法照原樣：`\p{…}`、`\k<…>`、反斜線跳脫、具名群組的名稱、字元類別的括號。「替換為」的 `$1`、`${名稱}`、反斜線跳脫不動，`@js:` 整段不動。
  - 轉過的字留在記憶體裡重用，每一章、每一次試跑不重轉。
- **選字「隱藏」「替換」照畫面上的字建規則**：找原文那一段也先轉再套既有規則，和畫面一樣的寫法；替換規則面板的測試原文、試跑也照這個寫法。

## 考慮過的做法

- **完全照 Legado，規則照字面比**：之前夜讀選字「隱藏」「替換」建的規則是網站原文的寫法（多半是簡體），預設又是簡轉繁，改了先後這些規則全部失效。開 App 時把「選字隱藏」「選字替換」兩個分組的規則轉一次也救不全：分組改過名的、之後換了繁簡設定的，照樣失效。
- **規則轉兩種寫法各套一次**：同一處可能被換兩次（「替換為」含另一種寫法的字時），每條規則跑兩遍。

## 後果

- 和 Legado 刻意不同：Legado 照字面比，寫錯寫法就對不到；夜讀兩種寫法都對得到。規則本身存的仍是讀者寫的字，匯出給 Legado 時照原樣。
- 一個字對到好幾個字時（「发」是「發」或「髮」），規則和正文要轉出同一個字才對得到。詞照詞組轉，「头发」「发现」「干净」「干部」「面条」「后来」「皇后」「这里」都對得到；只寫一個字的規則沒有上下文，照單字的預設轉：規則「发」對不到正文的「头发」（轉成「頭髮」），「面」對不到「面条」（「麵條」）。正則被語法隔開的字也是各自轉，`(头)发` 對不到「头发」。
- 照轉換器沒採用的異體字寫的規則對不到：轉換器把「这里」轉成「這裏」，規則寫「這裡」對不到。
- 不套規則時，改了先後的正文和原本一字不差（《西游记》101 回，簡轉繁、繁轉簡各比一次），已存的書籤、標註與閱讀位置不動。套了規則的書，規則對到的地方變了，位置照新的正文對，和新增一條規則時一樣。
- 匯出書不做繁簡轉換，規則照原樣套，和原本一樣。
