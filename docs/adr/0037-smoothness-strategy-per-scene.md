# 每種場景用定好的流暢策略

ADR 0036 定了動畫流不流暢的標準，但沒定怎麼做到；2026-10-28、10-29 全 App 動畫探索一律把工作切碎攤進動畫的每一幀（ADR 0029「用時間換流暢」），很多地方最重一幀降了一半、還是超過上限，等於沒修，還把搜尋改排序原本落在點下去那一幀的工作攤進後面的動畫，掉幀變多。使用者 2026-10-29 定的：不同的場景用不同的策略，但每個策略都先定好什麼時候用、怎麼做、代價和怎樣算做到；開 App 進場（ADR 0025、0031、0035）不卡，是因為重的工作全在畫面靜止時做完、動畫本身每一幀不做事，這是策略一、二的範本。

## 掉幀

一幀超過上限（手機 8.3ms，電腦照 ADR 0029、0036 換算成 4.2ms），而且畫面正在變：錄影裡這一幀和前一幀或下一幀的像素不同。畫面沒在變的幀再重都看不出來，不算掉幀；點下去那一幀照 ADR 0036 第 1 條不算。最重一幀降了但還超過，一樣是掉幀，不算修好。

## 五個策略

1. **靜止時準備**（預留停頓，ADR 0036 第 2 條）。用在點一下進新頁、打開面板與選單、閱讀器原地重排（開書、跳章、改字級行距主題日夜）、底部分頁切換。點下去那一幀與之後畫面靜止的時間做完重的工作，骨架這時停在最深、不呼吸；做完隔 0.1 秒動畫才開始。代價是動畫晚「工作時間＋0.1 秒」開始。做到：做工作的那些幀畫面都沒在變。
2. **動畫只播不做事**。所有動畫本身，和策略一搭配。動畫播放的每一幀只改位置、透明度、裁切，或混合拍好的圖（定格換場，ADR 0031）；底下的內容不重建、不重排。代價是動畫途中到的新內容等播完才換上，定格畫面多佔記憶體。做到：動畫播放期間內容沒有重建、沒有重排。
3. **等靜止再放**。用在時間不受控的資料與工作：搜尋結果陸續回來、發現書單補封面與字數、換場後才開始的背景工作。資料到了先排隊，畫面上沒有動畫在跑時一次放進去（接策略一），再照策略二淡入；淡入播完前又到的等下一個靜止點。代價是結果最多晚一段動畫（淡入 0.25 秒）才出現。做到：沒有資料是在動畫播放中放進畫面的。
4. **每幀限量**。用在手指一直在動的時候：捲清單、甩目錄、拖進度條、往右拖返回。每一幀的工作有上限、做到就停，下一幀接著做；手指動之前在靜止時先把會用到的列建好。ADR 0029 的「工作拆小、分攤到更多格」只用在這裡與下面補充的那類工作。代價是捲很快時畫面外的內容晚一點補上。做到：手指在動的每一幀都在上限內。
5. **動畫只平移裁切**。用在動畫本身在改尺寸、每一幀都要重新排版的地方。版面一開始就排成動畫結束的樣子，或兩種狀態用同一個版面，動畫只平移與裁切。代價是外觀可能和現在差一點，每個地方的取捨記在下面或 `DESIGN.md`。做到：動畫播放期間沒有重新排版。

補充：會照時間切、每一幀照實算後都在上限內的工作，可以和動畫同時跑。閱讀器排版就是這種：每幀最多 4ms，而且照手機這一幀實際剩下的時間縮放（`BudgetGovernor`），加上骨架呼吸在手機上約 6ms，不必停下呼吸。切不開的一次性工作（例如讀進目錄後閱讀頁整頁重建、掀紙前建好正文畫面）才照策略一停下動畫，每次只停一兩幀加 0.1 秒，骨架不會像凍住。

## 場景對策略

| 場景 | 策略 |
|---|---|
| 開 App 進場 | 一＋二（範本） |
| 進新頁（書籍詳情、設定各頁、書源管理）；資料到了換場 | 一＋二；資料到了接三 |
| 選單、面板、彈出選單滑入 | 一＋二 |
| 閱讀器開書、跳章、改字級行距主題日夜 | 一＋二；排版照補充那條 |
| 底部分頁切換 | 一＋二 |
| 搜尋結果、發現書單補資料 | 三（接一＋二） |
| 捲動、甩動、拖動、往右拖返回 | 四 |
| 書源管理進出多選這類尺寸動畫 | 五 |

**書源管理進出多選**（使用者 2026-10-29 選的）：文字區在平常與多選兩種模式都用同一個寬度，取兩者中窄的那個；多選時勾選圈從左邊滑進來，文字只往右平移。平常模式下長的書源名與網址會早 2–3 個字截斷（文字區窄約 40 像素），換來進出多選時「…」不跳、標籤列不在動畫中途換行，動畫完全不用重新排版。

## Considered Options

- **每個場景都用同一招**：一律停下來做，手指在動時停不了；一律切碎攤進動畫，就是探索走偏的原因（見開頭）。
- **書源多選：版面一開始就排成多選的樣子**：動畫同樣不重排，但被截斷的列每次進出多選，「…」在第一幀跳 2–3 個字，會換行的標籤列第一幀就長高或變矮；使用者選了靜態少幾個字、永遠不跳（`_TrailingSwap` 當初也是為了文字區不跳）。
- **書源多選：保留寬度動畫、精簡每一列**：一幀要重排上百段字，要從電腦 13–15ms 降到 4.2ms 得少掉七成，精簡做不到，標籤中途換行那一跳也還在。
- **閱讀器工作很長時讓呼吸與工作輪流**：分析後不需要；最長的排版本來就照時間切、能和呼吸同時跑。

## Consequences

- 量測工具目前以「有沒有計時器在跑」判斷一幀算不算動畫中（`frame_budget.dart` 的 `moving`），和上面的掉幀定義不同：看不見的計時器在跑也算動畫中，畫面沒變的重幀也被算成掉幀。改成照畫面有沒有在變判斷之後，再照這份重錄整個 App。
- 修一段動畫前先說它屬於哪一種場景、用哪個策略；用了表上沒有的組合，先補進這份。
