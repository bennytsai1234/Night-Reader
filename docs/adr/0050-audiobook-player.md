# 有聲書另做播放器：進度記毫秒、手動下載、和朗讀共用一個系統播放控制

使用者 2026-11-09 要播放有聲書源（Legado `bookSourceType` 1）的章節音訊，和文字閱讀器（Reader V2）分開，第一版照 Legado 全套功能（播放模式、倍速、定時、快退快進、換源、保持喚醒、複製音訊網址），畫面專為有聲書重新設計（`docs/design/audiobook.md`）。有聲書源的正文規則回傳的是音訊網址。和「書源分類與保留」、漫畫閱讀器三條分支同一批合併，所以有聲書這邊只問書源分類（ADR 0051）是不是有聲源，不另判字樣。

## 決定

- **有聲源和小說源一樣進搜尋、發現、閱讀、下載與檢查新章節**：哪幾類打得開由 `isOpenableSource` 一處決定（小說、有聲；漫畫等漫畫閱讀器）。這是 ADR 0051「留下來的漫畫、有聲源不進文字書的搜尋與閱讀」對有聲源的例外。
- **收聽進度記「章＋第幾毫秒」，存在放字位置的同一個欄位**（`Book.charOffset`），照 Legado（它也存在 `durChapterPos`）。書源 JS 讀 `book.durChapterPos` 本來就對到 `charOffset`，拿到的毫秒和在 Legado 一樣。進度跟著閱讀進度的日常同步走（ADR 0039、0046），同步紀錄格式不變；兩台相差 10 秒以內不跳（對應文字書的 100 字）。
- **音訊手動下載，書架自動下載跳過有聲書**：這是 ADR 0008「書架上的網路書整本自動下載」的例外。有聲書一章常見 5–20 MB，一部書可達幾 GB，照 0008 不分網路整本下載會吃掉流量與空間。使用者在書籍詳情或目錄照文字書的手動下載選範圍；音訊檔存在資料夾，不進 SQLite，移出書架就刪。播放時預先抓下一章。漫畫照 0008 自動下載（使用者 2026-11-09：「這跟漫畫不一樣」）。
- **播放用 `just_audio`，接現有的 `audio_service`**：Android 底層是 ExoPlayer（同 Legado），iPhone 是 AVPlayer，mp3、m4a、m3u8 都能播、能帶書源的請求標頭。
- **朗讀與有聲書共用同一個系統播放控制**：`AudioService.init` 整個 App 只能一次，通知、鎖定畫面與耳機鍵由同一個 handler 轉給目前的來源。一個在播時開始另一個，後開始的接手，原本在播的暫停（有聲書記住毫秒，朗讀停在那一句）。
- **通知與系統播放資訊給齊**：通知欄播放器、鎖定畫面、iPhone 動態島與各家手機的「島」都由系統照標準播放資訊畫，相容的做法就是把標題、副標、封面、位置與總長、按鈕給齊，不替各家另接。vivo 原子島可能只認白名單裡的 App，不是 App 能決定的。

## 考慮過的做法

- **另開欄位存秒數**：要改資料庫，書源 JS 拿到的值也和 Legado 不同。
- **收聽進度只記在這台**：換手機要自己找章、拖到聽過的地方，和文字書的同步不一致。
- **只有播放暫存、不能下載**（Legado 的做法）：沒網路時只聽得到已抓好的下一章。
- **照 ADR 0008 整本自動下載**：見上。
- **`media_kit`**（mpv）：格式更多，但 App 大好幾 MB，有聲書用不到。
- **另一個來源開始時先跳框問要不要停掉**：多點一下；手機上開另一個音樂 App 也是直接接手。
