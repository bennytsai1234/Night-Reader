# 選單與頁首的項目一律畫出，不能用的灰掉

使用者 2026-11-11 審查設計時說選單隨狀態變形「主要是狀態太多了，很難理解」：同一個選單這次五項、下次七項，頁首的鈕一下有一下沒有，記不住東西在哪。照狀態隱藏讓每個選單在每種狀態都最短，但形狀一直變；使用者要的是每個選單只有一種樣子，變長另外靠整理分組與名稱解決（使用者：「先露出，再整理」）。

## 決定

- **範圍**：彈出選單、長按選單、底部動作表、多選工具列，以及頁首與頁首下方的鈕和膠囊。
- **一律畫出**：條件不成立時項目照樣在原位，停用（灰），不寫原因。
- **頁首的鈕一直在**：選單裡一項都不能選時整顆停用；能選的不只一項時才有意義的鈕（例如類別），只有一類時照樣在，打開後其他類灰掉。
- **不算變形、照舊的**：
  - 同一格依狀態換字或換成進度（修的時候「停止」、修完「完成」；播放與暫停；批次作業中工具列換成進度）。
  - 跟著資料長的清單（每個分組一項、系統裡能處理文字的 App）。
  - 這台裝置做不到的（亮度條只有 Android）、返回鈕（沒有上一頁）。
  - 不同的對象各有自己固定的樣子（規則小幫手在網址欄與規則欄給的項目不同；漫畫閱讀器的目錄沒有書籤與標註分頁）。
  - 有沒有內容換成另一個畫面（空書源頁、搜尋還沒有結果時沒有結果工具列）。
- **設定頁不在範圍內**：依賴另一個開關的子設定照 ADR 0009 在上層關閉時隱藏，原因就在正上方的開關。

## 考慮過的做法

- **照狀態隱藏**（原本的做法）：每種狀態最短，但選單的形狀跟著狀態變，使用者記不住、看不懂。
- **灰掉並在後面括號寫原因**：選單寬 250，一行約放 12 個字，「清除已下載的正文（本地書沒有）」這類項目會換行；改放第二行、放在右側取代圖示或把原因縮短都畫了候選，使用者選了不寫原因（「換行完全沒有美感」「乾脆別加原因」）。
- **連設定頁一起畫出**：設定頁變長，又把上方開關說一次。

## 後果

- 每個選單的長度固定在原本最長的那一種；太長的另外整理成分組或第二層。
- 灰掉的項目不說明為什麼不能按；看不懂時先改名稱或整理分組。
- 新增選單項目時，條件寫成 `enabled`，不寫成不放。
