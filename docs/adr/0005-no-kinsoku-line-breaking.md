# 正文換行不做標點避頭尾

> 已由 ADR 0026 取代：2026-10-18 起換行做避頭尾，被拉字的那一行把空隙攤進字距。文字框寬度是整數個字格的部分照本文。

正文的視覺行由 Reader V2 自己決定（`VisualLineLayoutEngine`，2026-09-20 起）：一個字形只要放得下就留在這一行，標點沒有否決權，所以行首可能出現「，。」』！？」。文字框的寬度是全形字格的整數倍（`ReaderV2TextLayoutFrame.centered`），不避頭尾時每條滿行的字格數相同，直行格線對齊、右緣切齊。早期版本做過避頭尾：被推到下一行的字會在上一行留下缺口，開左右對齊時缺口被攤進字距，各行字距不一，直行格點逐行漂移（`f5e0e21` 量到 0.6–1.5 字寬）；不開左右對齊時，那一行的右緣就短一截。2026-09-20 移除了避頭尾的約束（`b0118f9`），網站上的避頭尾說法也已撤下（`54d6e14`）。

## Consequences

- 不要把避頭尾（或擠壓、懸掛標點）加回換行策略；改動換行規則要先推翻這份 ADR。
