# 轉場與骨架換場不掉幀：內容可以晚，畫面不能頓

使用者的要求（2026-10-20）：流暢度拉滿，延遲打不掉沒關係，可以稍微等，但點下去到下一個畫面、骨架換成真實內容的過程都不能掉幀。ADR 0018 定了「動畫播放時不跑重工作」；這份把實際踩過的坑整理成每個轉場都照著做的一套做法。開 App 書架換場在 beta.8 仍會頓，原因不在換場本身，而在換場前後那幾格：換場一結束就啟動的背景工作、為了一個小狀態整頁重建，以及換場期間手機 GPU 每一格要多合成的圖層。

## 做法

1. **先骨架、後內容，重的工作不進動畫那幾格**（ADR 0018、0028）。資料庫查詢與書源解析在背景 isolate；轉場動畫播完（`TransitionSettled`）才開始載入；大量 widget 分幀建（`CoverRevealSlot` 一幀一張）；封面解碼好才換場（`waitForCovers`）。
2. **換場只遮一層**：骨架與內容後面是單一實色（頁面底色）時，`SkeletonSwitcher` 給 `backdrop`。內容不再套動畫遮罩、不另開離屏圖層；骨架墊著底色蓋在上面，由左而右退開。方向、時長與頭尾和兩層交叉淡換相同，中間是骨架覆蓋著淡出（換到一半時骨架比交叉淡換稍微明顯一點），換來每一格少合成一張整區大的圖層；上面有模糊玻璃（頁首、分頁列）時差更多，因為玻璃每格都要重新取樣底下的畫面。內容會不會每格重畫，看子樹有沒有重畫邊界（書架的書卡由清單各自包了一層），這個參數本身不保證。後面不是實色時才讓兩層各自淡入淡出。
3. **小狀態用小訊號，不通知整頁**：動畫前後會變的旗標（頁首流光的「正在檢查」、書卡角標、單列補到的封面）各自是一個 `ValueListenable`，只有用到的那一小塊聽它；頁面整體的 `ChangeNotifier` 只在清單本身變了才通知。重新讀取時畫面不會換回骨架（清單已經有東西）就不要先通知「載入中」。
4. **換場結束後的工作錯開**：一段動畫播完要啟動好幾件工作時，依序啟動、每件隔一格（16ms），各自留在主執行緒的同步部分落在不同的格。不用 `Priority.idle` 的閒置工作：只要畫面上還有任何動畫（別處的骨架呼吸）就輪不到，等它資料的骨架會永遠停著。
5. **推入的頁面第一格只畫骨架**（2026-10-21）：設定這類一進頁就有完整內容的頁面，第一格原本把整頁的列建好（閱讀偏好約 1300 個元件，電腦 debug 50ms 以上）。`GroupedListView` 掛上時頁面還在進場就先只畫骨架（整個畫面一個 `SkeletonShapes`），進場播完的下一格才在骨架底下一格建一列（組標題文字與卡片外框先建，第一個畫面裡的列與組標題右側的按鈕各自排隊，`CoverRevealSlot`），都建好再照骨架換場；畫面外的列和組一起建、換場不等它們（一列一格的話，兩百列的替換規則要等三秒以上）；不是在進場中掛上的（分頁、已經在畫面上的頁面）照舊直接建。骨架照真的畫面畫：換成內容時從畫面上量下每一行字、圖示、圖片、開關與小色塊的位置（`GroupedItemShape.measure`），以頁面的結構、寬度與字級為 key 存進偏好設定，下次與重開 App 後照著畫；沒看過的頁面照列的種類估（步進列畫「－」、數值膠囊與「＋」，開關列畫開關，有值的列畫值與箭頭；包在各頁私有元件裡的列認得步進列，其他的只畫標題條）。頁面裡的 `Focus` 原本依賴路由的 `FocusScope`，推入第 1 格、返回第 0、1 格整頁的焦點元件跟著重建；`_AppTransition` 在頁面外包一層不取焦點的 `Focus`，路由的焦點變化停在這一層。分組清單的列與步進鈕改用 `PressInk`（按下高亮與點擊回饋，不帶每個 `InkWell` 的 `Focus`／`Actions`／`MouseRegion`）。

   閱讀器的三個面板（外觀與排版、朗讀、替換規則，2026-10-22）原本第一格就把整個面板建好（電腦 debug 第一次打開 55–120ms），改成照同一套進場（`GroupedSheetContent`）：滑上來時只有骨架，滑到位才逐列建。面板照內容的高度收縮，骨架的高度就是滑上來時面板的高度，換成內容時差一點都會跳；所以面板的骨架高度不能估個大概，每一項照元件本身的版面常數與字樣算：組標題與附註照字排（和 `Text` 一樣合併預設字樣），步進列用 `NumberStepperRow.height`，色票列、分段控制、輸入框這類區塊實作 `GroupedSkeletonItem`，用的是元件 build 裡同一份常數與字樣。紀錄的 key 連各項高度一起比（同一種元件也會換高度，例如定時選了自訂分鐘多一列步進），紀錄只讓下次的字條照真的字寬畫。
6. **量到骨架換完再多一秒**：每個轉場都在 `test/frame_budget/` 有情境（`test/support/frame_budget.dart`），量的範圍從點下去開始，到骨架完全換成內容、再多看一秒，換場開始、結束與之後幾格都要看；`FRAME_ATTRIBUTE=1` 找出是誰在那一格重建。改轉場、換場或開 App 流程前後各量一次，數字寫進 commit message。測試的資料庫在主執行緒（記憶體資料庫），手機上在自己的 isolate：「幀前」「幀後」裡的資料庫時間在手機上不在主執行緒，看的是 build、layout 與重建範圍。

## Considered Options

- **換場改成整頁淡入**：一樣要開圖層，而且使用者選了由左而右（ADR 0024）。
- **骨架與內容各自照橫向位置算透明度、完全不開圖層**：骨架裡有卡片底這類不是 `SkeletonBox` 的元件，沒辦法各自淡；保留一層遮罩換取正確。
- **開 App 的背景工作用閒置工作排**：試過，量測時骨架停不下來（見做法 4），否決。
- **推入時清單不預建畫面外的項目（捲動預留區設 0），其餘照舊第一格建好**：第一格少建畫面外的兩組，但畫面上的列還是全在第一格；有了骨架就拿掉。
- **一格建一組**：「排版」這樣一組八列步進的組整組一起建，那一格在電腦 debug 要 50ms 以上，改成一格一列。
- **再精簡頁首與 `Scaffold`**（返回鈕的 `Tooltip`、頁首的 `LaunchSkeleton`）：推入一頁的固定成本（導覽、`Scaffold`、頁首）約 170 個元件，其中約 100 個是 Flutter 換頁本身；拿掉這幾個量不出差別，沒做。第一格因此停在空白頁的成本附近，到不了 8ms 以下。
- **骨架照列的種類畫（不量畫面）**：分組卡片裡的列多半包在各頁的私有元件裡，認不出種類，畫出來只有標題條；量畫面才和真的一樣。
- **面板的骨架照列的種類估個大概，高度不對時換成內容那一刻補差值，或下次照紀錄改正**：估的時候組標題用字號乘行高、包在 `FutureBuilder` 裡的列看不出有列首圖示、輸入框沒照它的字樣量，第一次打開時朗讀少 0.3、替換規則少 8.1 像素，換場那一刻面板會長高；使用者要高度從同一個來源來、第一次就對，不在頁面上補像素、不先畫錯再修。
- **頁面改用 `context.select` 只挑需要的欄位**：書架頁大部分內容都依賴書單，選出來還是整頁；把會頻繁變動的小狀態拆成獨立訊號比較直接。

## Consequences

- 開 App 的背景工作比原本晚幾十毫秒開始。
- `SkeletonSwitcher` 的 `backdrop` 只在後面是實色時能給；新的骨架區塊放在卡片或半透明底上時照舊兩層。
- 設定頁、書源編輯、替換規則、背景下載佇列與「關於」底下的頁面，推入時都先是骨架，換頁播完後第一個畫面有幾列就再等幾格（一般的設定頁約 0.2–0.3 秒）才換上內容；組裡畫面外的列很多時（上百條替換規則），建這一組的那一格仍然重，只是不在換頁那幾格裡。第一次進一頁（沒有紀錄）時骨架照估的畫，換成內容時位置可能差一些；骨架只記、只畫第一個畫面。
- 閱讀器的三個面板滑到位後，畫面上有幾列就再等幾格才換上內容。面板裡新增不是一般分組列的區塊時，要讓它實作 `GroupedSkeletonItem`，不然骨架算不出它的高度，面板會在換成內容時跳。
- `PressInk` 不接鍵盤焦點：分組清單的列與步進鈕不能用實體鍵盤的 Tab 移過去（觸控與讀屏不受影響）。
- 之後新增的轉場、換場與背景工作照這六點檢查；`CODING_STANDARDS.md`「動畫」指向這裡。
