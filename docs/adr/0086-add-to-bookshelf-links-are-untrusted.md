# 加入書架的連結當成外來的：網址裡的程式與選項不照著跑，註明的書源要和網址同一個網站

`legado://import/addToBookshelf?src=` 的連結從 App 外面來，任何網頁、訊息都做得出來。找書源、抓詳情的順序照 Legado `AddToBookshelfDialog`，這三處刻意不同。

## 決定

- **網址裡有規則 JS 或反斜線的不抓**：`src` 的網址部分（`,{` 之前）出現 `{{`、`}}`、`<js>`、`</js>` 或 `@js:`（不分大小寫）時，提示「書的網址格式不對」。抓詳情時網址會先跑這些 JS（`AnalyzeUrl.initUrl`），JS 跑在書源裡，讀得到書源的登入資料、能發任意請求。Legado 照跑。有反斜線的也不抓：各家網址解析對它看法不一，下面判斷的主機可能和真的送去的不同。
- **網址選項只拿 `origin` 挑書源**：`headers`、`js`、`retry`、`method`、`body`、`webView` 這些都不照著送；存進書的網址也只留網址部分，之後書籍詳情、目錄照它抓；查書架上有沒有這本、比詳情頁網址規則也用這一段（Legado 比整串）。引擎本來就不讀 `origin`，拿掉不影響抓取。Legado 整串照存、照送。
- **註明的書源要和網址同一個網站**：選項註明的書源（`origin`）的主機（`siteHost`，`@` 前面的使用者資訊與連接埠不算）要和網址的主機一樣，或網址整個符合它的詳情頁網址規則（`bookUrlPattern`）；都不符合就不抓，提示「連結指定的書源和書的網址不是同一個網站」，也不往下試別的書源。請求會帶著那個書源的 Cookie 與登入標頭，網站對不上時等於把它們送給連結指定的網站。註明的書源不在時照 Legado 往下找。另外兩條路（網站相同的啟用書源、詳情頁網址規則符合的啟用書源）本來就對得上，照舊。

## 考慮過的做法

- **照 Legado 全部照跑**：一條連結就能拿走讀者登入過的書源的身分資料。
- **選項整個不認、`origin` 也不看**：網址註明書源是 Legado 的寫法，拿掉就可能找錯書源。
- **註明的書源對不上時改試其他書源**：連結明說要用哪個書源卻對不上網站，多半是做壞或故意的，提示比默默換一個書源清楚。

## 後果

- 靠網址選項才抓得到詳情的書（要 POST、要自訂標頭、要用網頁抓）從連結加不進來，要從搜尋找。
- 連結帶選項時，加進書架的書的網址比 Legado 存的少了選項。
