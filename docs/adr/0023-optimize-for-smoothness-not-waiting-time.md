# 不以縮短等待時間為優化目標，看整體流暢與動畫完整

改進體驗時，目標是整體使用起來流暢、每段動畫完整播完，等待時間的長短不列入考量。骨架停得久、內容晚一點出來都沒關係；不為了讓東西早點出現而縮短或跳過動畫、讓工作疊到動畫上，也不為了省時間加上快取或捷徑。使用者的判斷是（2026-10-17）：在意的是使用體驗，而等待時間不算在使用體驗裡。

這條把 ADR 0017（開 App 先看骨架是想要的流程）和 ADR 0018（寧可內容晚一點出現，也不讓動畫掉幀）背後的取捨講成通則：評估一個改動，問的是畫面順不順、動畫有沒有完整播完，不是使用者少等了多久。

## Considered Options

- **縮短書架等封面的上限（0.3 秒）與淡入時間（0.4 秒）**：只換來等待短一點，淡入也變得倉促，否決。

## Consequences

- 只能讓等待變短、對流暢與動畫沒有幫助的改動不做，例如只為了讓書架早點出現而把整個書架存起來。
- 之後評估效能或載入相關的改動，先看會不會掉幀、會不會打斷動畫，載入快慢只能當附帶結果。
