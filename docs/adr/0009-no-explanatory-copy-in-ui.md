# 介面不放解釋性文案

畫面上不寫「這個設定或功能在做什麼」的說明：設定列沒有說明副標，分組下方沒有說明段落，輸入框不用 placeholder 解釋欄位用途，標題旁也不放操作提示。使用者要的是乾淨的介面，標題要自己說得清楚；說不清楚就改標題，不是補一行說明。2026-10-13 依這條規則清過一次全部畫面。

## 保留的文字

判準是「這段字少了，使用者會不會拿不到資訊或做錯決定」，而不是「這段字有沒有幫助理解」。下面這些留著：

- **狀態與數值**：版本號、目前選擇、數量、網址、檔案大小、最新章節、最近更新時間、下載進度。
- **確認與後果**：確認問句，以及破壞性操作會造成的結果（例如移出書架會刪除已下載的正文、匯入會覆蓋本機已有的書源）。
- **錯誤**：錯誤訊息、失敗原因與重試入口。
- **空狀態**：`AppStateView` 的標題與描述，告訴使用者這裡為什麼是空的、下一步去哪裡。
- **法律與隱私**：免責聲明、授權、隱私說明與權限頁的說明段落（使用者主動點進去看的文件）。
- **工具性內容**：書源除錯輸出、校驗日誌、規則小幫手列出的語法，以及書源編輯器裡寫出輸入格式的 placeholder（例如 `JSONPath, XPath 或 CSS`、`多個分組用逗號分隔`），這些是在寫規則時要查的資料，不是功能說明。

## 新增設定時

- 列只寫標題；副標（`GroupedRow.subtitle`）只放值，`GroupedSwitchRow` 沒有副標。
- `GroupedSection.footer` 只放狀態或數值，不放說明。
- 依賴另一個開關才有作用的設定，上層開關關閉時整列隱藏，不用停用加說明文字表達「需先開啟某某」；更好的是把兩個合成一列選項。例如原本「在 Wi-Fi 下自動下載更新」只在「自動檢查更新」開著時出現，2026-10-20 合成一列「自動更新」：不自動／自動檢查／Wi-Fi 下自動下載。
- 輸入框的 placeholder 可以寫格式或範例，不寫用途。

## 考慮過的做法

- 保留副標但縮短：仍然是在解釋，畫面上每列多一行，列高從 44 變 60，清單變長。
- 把說明收進「?」按鈕或長按提示：多一個要維護的入口，而且說明一樣會過時；標題說不清楚時應該改標題。
- 依賴的設定用停用加說明：停用的列留在畫面上還要解釋為什麼不能用，隱藏更乾淨，上層開關一打開就出現。

## Consequences

- 功能說明改放在 README 與網站，介面上不再重複。
- 有些設定的效果只能從標題推敲（例如「啟動時檢查書架更新」不再寫「在背景」）；如果使用者反映看不懂，先改標題。
- 審查新畫面時，看到說明副標、說明 footer 或用途 placeholder 就照本 ADR 拿掉。
