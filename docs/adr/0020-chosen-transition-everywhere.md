# 選定的換頁動畫用在每一種換頁，拖曳返回與點分頁也一樣

「外觀與主題 → 換頁動畫」選的那一種，用在 App 裡每一種換頁：按按鈕開頁與返回、往右拖返回（左緣右滑、Android 手勢導覽的預測返回），以及點主頁下方的分頁。2026-10-15 使用者指出拖曳返回不管選哪一種都是平移、點分頁是整頁快速掠過中間的分頁，要求全部照選定的動畫。

原本拖曳返回一律用平移的跟手樣子（加入八種換頁動畫時定的，沒有記錄理由），推測是因為只有平移的頁面是真的跟著手指橫移。現在改成：拖曳中照選定那一種返回的幾何走，位置、縮放、透明度都和拖曳進度成正比，不套時間曲線；例如縮放是頁面隨拖曳縮小淡出，展開是縮回當初點的卡片。放開後的門檻與收尾時間仍照 Telegram（拖過 20% 或快過 1000pt/s 就返回）。

點分頁不滑過中間的分頁，直接換過去，往右邊的分頁照開新頁播、往左照返回播；換頁前的畫面拍成快照當舊頁。在「發現」「我的」用 Android 手勢返回回書架，也和一般頁面的預測返回一樣跟著拖曳走。手指左右滑動換分頁仍是頁面跟手的橫移，不套換頁動畫：那是捲動，不是換頁。

不套換頁動畫的：底部面板、對話框與浮動選單（只蓋住一部分畫面，不是換頁）、頁內的內容切換、閱讀器的翻頁動畫（另有設定）、換深淺與風格的暈開。閱讀器的手勢返回不跟手、放開後才播選定動畫：返回鍵在閱讀器裡會先收選單或目錄，有時還要先問要不要加入書架，拖曳當下還不知道這次返回要做什麼。換源或跳到最新章重開閱讀器時，照開一本書播一次完整的開頁動畫。

## Considered Options

- **拖曳返回維持一律平移**：只有平移是頁面跟著手指走，但使用者選了別種動畫時，按鈕返回和拖曳返回看起來是兩回事。
- **點分頁改成淡入切換，或保留滑動只滑一頁**：都不是使用者選的那一種，跟 App 其他換頁不一致。
- **加動態模糊**：見 DESIGN.md「換頁不加動態模糊」。

## Consequences

- 新增一種換頁動畫時，要同時寫開啟、返回與拖曳中的樣子（`_TopPose.follow`／`_UnderPose.follow`）。
- 除了平移，拖曳中頁面不一定跟著手指的位置走（例如縮放、上浮），手感由拖曳進度帶動。
- 點分頁的舊頁是快照，換頁中舊頁不會更新，也不接受點擊。
