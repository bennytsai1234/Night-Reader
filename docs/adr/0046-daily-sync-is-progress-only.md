# 日常只同步閱讀進度，其他資料按「立即全面同步」才同步；合併計算在背景 isolate

使用者 2026-11-03 回報：開 App 後第一次從書架開書，紙上骨架換成正文時很卡，第二次不會。他判斷是 #199 把同步範圍擴大到書源、書架、替換規則、設定、登入資料，加上 #208 把同步排在開 App 後第一個跑，開書時同步和閱讀器排版搶主執行緒。要的結果：日常只同步閱讀進度，其他資料按「立即全面同步」才同步、期間鎖住 App；解 JSON、算指紋與合併搬到背景 isolate，資料庫寫入留在主執行緒。這份取代 ADR 0039「什麼時候同步」那一段，合併規則、衝突處理、同步空間照 0039。

量測（`test/frame_budget/launch_sync_book_open_frame_budget_test.dart`：60 個書源、另一台改過一個、每次讀寫雲端等 0.3 秒，先暖身再量）：改之前，開 App 後馬上開書，三次都在開書動畫中段出現一支 83–120ms 的長幀，落在同步比對書源的時候；不設同步空間的對照組沒有這支。檢查書架更新、書架自動下載在書源 isolate 跑，不是原因（`docs/agents/main-thread.md`）。

## 決定

- **日常只同步閱讀進度**（`SyncService.syncProgress`）：開 App 進場播完、回到前景、退到背景、離開閱讀器。開書最多等 0.5 秒、進度晚到而讀者還沒動就接續的做法照 ADR 0039。
- **全面同步**（`SyncService.syncAll`）：只在「備份與同步」按「立即全面同步」，以及剛選好同步空間時（使用者選的：選好就全面同步一次，不只同步進度再提示去按）。書源、替換規則改了不再自動同步。「上次全面同步」只記全面同步。
- **全面同步期間鎖住 App**：按下後開一個不能關的進度對話框，顯示正在同步哪一種、第幾步，可以取消；取消在種類之間停，已經寫完的種類留著、不回滾。正在同步進度時按下，等含全部種類的那一輪做完才關。
- **合併計算在背景 isolate**（`sync_merge.dart`）：解雲端的 JSON、算指紋、三方比對、補時間、刪除紀錄、編碼要上傳的檔案，整段交給 `Isolate.run`。讀寫同步空間、讀這台的資料、套用與寫資料庫留在主執行緒，交易與「套用前重讀、變了就不套用」照舊。
- **只有真的變了才通知畫面**：書架同步沒套用任何一本時不發書架重讀的通知。

## 考慮過的做法

- **自動在背景跑全面同步，只是晚一點或分段**：開書的時間不固定，排在哪裡都可能撞上；比對與套用在主執行緒就一定會搶。使用者要的是日常不跑。
- **把資料庫寫入也搬進 isolate**：同步的套用要經過 DAO、事件與服務（書源搬家、書架加書後排下載），搬過去要重寫一套；寫入本身在資料庫 isolate 跑，主執行緒只送查詢。
- **全面同步不鎖畫面**：同步途中使用者改的書源或設定，可能在同一輪被雲端的蓋掉或沒送上去；鎖住整個 App 最簡單也最確定，全面同步本來就是使用者自己按的。
- **開書時暫停同步**：同步跑到一半停下要記住做到哪；日常只剩閱讀進度一個小檔，不必。
