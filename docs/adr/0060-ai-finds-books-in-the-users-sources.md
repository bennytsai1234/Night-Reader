# AI 找書：使用者描述想看的，AI 用工具在使用者的書源裡搜、比、讀，交出推薦

使用者 2026-11-12 提出：用一段話描述想看的（例：「爽文、穿越，我在看這幾部動漫，想要更刺激的」），AI 自己定策略、呼叫工具去找、比較、讀，交出值得一讀的幾本書和理由；照書架推薦是同一件事換個問法。方向和 AI 修復一樣是給足工具讓 AI 自由發揮，共用 AI 修復的迴圈與紀錄（ADR 0054）。2026-11-12、13 談定下面的做法。

## 決定

- **只在使用者的書源裡找**：AI 的工具只有夜讀自己的搜尋、詳情、目錄與正文、發現頁、書架與閱讀紀錄，沒有網路搜尋；交出的每本書都是這次工具回過的（工具給每本書一個編號，交出時寫編號，夜讀照編號拿書名、作者與書源），編出來的書名不會出現。
- **工具**：
  - 搜尋：照搜尋頁的範圍膠囊（預設全部書源，使用者可以先縮小）；類別（小說、漫畫、有聲）是工具的參數，由 AI 照描述選，照類別送書源同搜尋頁（聚合源每一類都送，ADR 0056）。同一本合併成一筆（和搜尋頁同一套），回書名、作者、字數、分類、最新章節、幾個書源有；一次回前 30 本，AI 可以接著拿下一批。
  - 看詳情：簡介、標籤、連載或完結、章數。
  - 讀章節：指定第幾章，一次給前 3000 字，超過的寫出共幾字、下一段從哪讀，AI 可以接著讀。付費、還沒買的章節不抓（ADR 0057），需要登入或網頁驗證的照實回（ADR 0038）。讀到的正文不存進快取：這本書還不在書架上。
  - 看發現頁：某個書源的排行與分類清單，與清單裡的書。
  - 看書架與閱讀紀錄：書架上的書（含本地書）與閱讀紀錄（含已經移出書架的）的書名、作者、讀了多久、讀到哪；登入資料與 Cookie 不送。
  - 交出：推薦的書（編號、推薦理由）與一段說明；什麼都沒找到也能交出零本並說明。
- **深度由使用者每次選**（使用者 2026-11-13 選「可以選擇深度」）：放在輸入描述的地方，三段，交出時照它檢查，不合的那本退回給 AI、說哪本不合：
  - 快速：工具回過就收。
  - 一般：每本都看過詳情。
  - 深入：小說還要讀過至少一章正文；漫畫、有聲書讀不了內容，照一般。
  預設一般，之後記住上次選的；只存這台手機、不同步（使用者 2026-11-13 選）。和搜尋頁的類別膠囊不同：類別每次從小說開始、不記住。
- **迴圈照 AI 修復**（ADR 0054）：服務的 function calling、每輪送完整對話、AI 的思考原樣放回；停下的條件同 AI 修復（卡住、失控、沒收斂、服務的錯誤、使用者按停止）。回合數先用共用迴圈的預設（36 輪），使用者 2026-11-13 說「先量測吧不急」：每次找書記下用了幾輪、多少 token，實跑量過再定；輪數用完還沒交出時，給不給 AI 已經看過的書也一起量過再定（共用迴圈現在是「沒收斂」、沒有結果）。不設用量上限，頁面上顯示目前用了多少 token。
- **AI 服務設定與 AI 修書源共用網址與金鑰，模型各選**（使用者 2026-11-13 選）：設定頁多一欄「找書的模型」，留空就用修書源的模型；書源管理與搜尋頁都能進這一頁，頁首從「AI 修書源」改成「AI 服務」（使用者 2026-11-13 同意），入口的「AI 修書源設定」跟著改名，卡片下的說明分兩段寫修書源、找書各送什麼。網址、金鑰與兩個模型還是一筆、一起同步（ADR 0054 的理由：分開比新舊會拼錯）。
- **入口在搜尋頁，一直都在**（使用者 2026-11-13 選，不只設定好 AI 服務的人看得到）：沒設定 AI 服務時照 AI 修復跳「還沒設定 AI 服務」、帶去設定頁；沒有剪貼簿：要 AI 一來一回用工具，貼來貼去做不到。長什麼樣做的時候畫候選圖選。
- **第四件背景工作**（ADR 0058）：有一頁看 AI 每一步在做什麼，返回或離開夜讀照跑；和修書源、校驗共用一次一件的位置（都在搶書源 isolate），一件在跑時其他幾件的入口灰掉。通知欄標題「AI 找書」、內文是最新一步、不畫進度條（輪數事先不知道，同單一書源的 AI 修復），點了回那一頁，做完收掉；從搜尋頁再進來是同一次找書。搜尋頁一般的搜尋照常能用，和找書的搜尋共用書源 isolate。
- **結果與每一次找書都留著**：每本列書名、推薦理由、字數與分類，點了進書籍詳情（照找到的書源）或加入書架。搜尋頁有「過去的找書」清單，列當時的描述與日期，點了看那次的報告（結果、AI 的說明、輪數與用量），可刪除；每一次是一筆，進備份與全面同步（ADR 0039、0046：新的贏、刪除也同步）。
- **紀錄照 AI 修復**：頁面「⋯」有「複製摘要」與「分享完整紀錄」，內容與存放同 ADR 0054「修復紀錄」，是量回合數的依據。

## 產品界線

- 書從使用者自己的地方來、沒有伺服器、背景不等人、不接付費內容：見上（只搜使用者的書源、自備金鑰、登入與驗證照實回、付費章節不抓）。
- 預設要克制：新功能，使用者明確提出。按了才送；沒有新的開關；入口一直都在是使用者選的，沒設定時不送任何東西。預設深度是一般不是最省的快速：快速的推薦可能只看書名與字數。
- 否決過的「搜尋結果顯示書源名稱」：結果列字數與分類，不列書源。

## 觸點

| 觸點 | 答案 |
|---|---|
| 書源類型、校驗、AI 修書源 | 不適用：找書不改書源 |
| 要登入、要網頁驗證 | 照 ADR 0038：工具碰到就照實回給 AI，不開登入頁 |
| 付費章節 | 照 ADR 0057：讀章節不抓，回「付費章節」 |
| 搜尋 | 做：入口與「過去的找書」；搜尋工具用搜尋頁的範圍與合併 |
| 發現 | 做：看發現頁的工具 |
| 換源、匯入手機上的檔案 | 不適用 |
| 書架 | 做：結果可以加入書架；書卡與篩選不變 |
| 書籍詳情 | 做：點結果進詳情；選單不變 |
| 下載、清除已下載 | 照 ADR 0008：加入書架後照常整本下載；讀章節抓的正文不存 |
| 檢查新章節 | 不適用 |
| 閱讀器、播放器 | 不適用；找書頁的服務錯誤照 AI 修復顯示 |
| 偏好 | 深度記住上次選的，不做成設定（ADR 0030）；AI 服務設定頁多「找書的模型」 |
| 進度、閱讀統計 | 只讀不寫：讀章節不算閱讀時間、不動進度 |
| 書籤、標註、朗讀 | 不適用 |
| 通知、鎖定畫面 | 照 ADR 0058：背景工作頻道，第四件 |
| 同步、備份 | 做：每一次找書一筆，進備份與全面同步；找書的模型跟 AI 服務設定那一筆；深度不同步 |
| 匯出、和 Legado 互通 | 不適用：Legado 沒有對應的功能 |
| `PRIVACY.md` 與「隱私說明」 | 做：新增「AI 找書」一節（送描述、工具結果、書架與閱讀紀錄）；備份與同步兩段加上找書紀錄與找書的模型 |
| `README.md`、網站 | 先不做：等回合數量過、跑穩再加（使用者 2026-11-13 選），記在 `PLAN.md` |
| `GLOSSARY.md` | 做：「AI 找書」 |
| `docs/design/` | 做：`screens.md` 的搜尋頁入口、找書頁、過去的找書，候選圖選定後寫 |
| iPhone | 能用；iOS 不讓 App 在背景跑這種工作，離開夜讀就停、沒有通知（同 ADR 0058） |
| 自動巡檢 | 做：新的資料夾排進 AI 修書源那一段 |
| 小說、漫畫、有聲、本地書 | 小說可以讀正文；漫畫、有聲只看簡介與資料，深入照一般；本地書不搜，書名與作者在書架與閱讀紀錄裡送 |

## 考慮過的做法

- **入口只在設定好 AI 服務後出現**：最克制，但沒設定過的人不知道有這個功能；使用者選一直都在。
- **不設回合上限、只看有沒有進展**：2026-11-12 的計畫原本這樣寫，同一天 AI 修復改成照技能的 36 輪上限；先量再定。
- **固定一種交出條件**：搜得到就收最省、但可能只看書名；小說都要讀一章最準、但每本多幾千 token。使用者要每次自己選。
- **AI 自己挑搜尋範圍**：開場要多送一份分組清單；**先回的書源先給 AI**：最快，但慢的書源上的書找不到、「幾個書源有」不準。
- **讀章節一次給整章（最多 1 萬字）、或只給 1500 字**：讀過的正文之後每輪重送；3000 字涵蓋多數章節。
- **AI 服務設定完全共用一組、或找書另一整組**：前者換不了模型，後者同一把金鑰要填兩次、同步兩份。
- **剪貼簿**：見上。
- **README、網站跟著這次一起做**：流程和畫面還會因為實跑改，改了要重拍。

## 後果

- 一次找書用多少 token 事先不知道，讀章節最耗，每輪送完整對話時累計照輪數平方成長；頁面上看得到目前用量，使用者隨時可以停。
- 找書在跑時不能校驗或修書源，反過來也是。
- 搜尋範圍是全部書源時，每次搜尋都要等全部書源回來；書源多的人一次找書會比較久。
- 做的那條分支一起改：ADR 0058 涵蓋的工作（三件變四件）、ADR 0054 的 AI 服務設定那一筆與設定頁、ADR 0039 同步哪些、ADR 0008 加入書架的時機、`PRIVACY.md` 與「隱私說明」、`docs/design/screens.md`。
