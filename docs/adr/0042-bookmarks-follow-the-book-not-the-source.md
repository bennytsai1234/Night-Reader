# 書籤跟著書名加作者，位置和閱讀進度同一套

使用者 2026-11-01 要重做書籤（2026-09 `54d6e14a` 整個拿掉過）：在某一句留個記號，之後從清單一點就跳回去；位置記「第幾章＋第幾個字」，跳回時照目前的排版算；要放進備份與同步，換源時跟著搬。

## 怎麼做

- **一個書籤記**：書名、作者、章名與這台目錄裡的章節序號、章內第幾個字、那個字綁定的正文錨點（`ReaderV2Location`：正文的身分與前後 48 字的原文）、那一句的字。留在選到的字所在那一句的開頭（照朗讀的分句），跳回時從整句讀起；清單顯示那一句，選得比一句長時顯示選到的全部。
- **跟著書名加作者，不跟書源**：和同步認書的方式一樣（ADR 0039）。換源、另一台用別的書源讀同一本書，都還是這本書的書籤；換源時在同一個交易裡把書籤搬到新書源那本（書名、作者照新書源的寫法），章節照換源時的閱讀進度對到新目錄的同一章（`alignChapterIndex`）。
- **跳回時照章名找章、照錨點找字**：章節序號只是這台目錄的座標，用的時候先找同名的章（繁簡不同也算；好幾章同名時取離記下序號最近的那一章，2026-11-02 審查標註時補上），再照章號；正文和留書籤時不同（換源、替換規則、繁簡）就照前後原文找回同一句（`ReaderV2ContentLocationMapper`），找不到照長度比例估。跳過去的位置照目前的排版算，和開書接上進度是同一套。
- **編號是建立時間的毫秒乘 1000 加隨機三位數**（`BookmarkDao.newId`）：同步拿編號當身分，兩台各自新增的不能撞號。只用毫秒（替換規則的做法）時，兩台同一毫秒新增、或一台時鐘曾經偏快（兩台都接在同一個最大編號後面）就會撞號，從沒同步過的那台的書籤會被雲端那筆蓋掉（Codex 審查 #212 找到）。比替換規則那樣在同步時對齊編號簡單，書籤沒有舊的流水號要相容。
- **同步**：一個書籤一筆，刪除也同步。「內容」是書名、作者、章名、第幾個字與那一句的字；章節序號與錨點不算，換源或書源插章時序號跟著變、讀到的地方沒變，不會被當成改過送上去。書籤表一改，隔 5 秒同步一次（同書源、替換規則）。
- **書移出書架，書籤留著**：書籤不屬於某個書源的那本書，重新加回書架（不論哪個書源）就回來；同 Legado。「我的 → 書籤」照書名加作者找手機上的那本書開，找不到就用書名搜尋（同閱讀統計）。
- **備份**：`bookmark.json`；2026-09 以前的備份裡的書籤（照書的網址記、欄位名不同）也還原得回來。

## Considered Options

- **照書的網址記**（2026-09 以前的做法）：換源要逐筆改網址，另一台用別的書源就對不上；同步還得另外換算。
- **換源時章內位置歸零**（以前的做法）：章內第幾個字在別的書源沒有意義，但有錨點就能找回同一句，不用丟掉。
- **只記章節序號**：書源在前面插一章就錯一章。
- **書移出書架時刪掉書籤**：移出後再加回來（換個書源加、整理書架誤刪）就沒了；書籤佔的空間很小。

## Consequences

- 書架上同一本書（書名、作者相同）從兩個書源都加進來時，兩本看到同一組書籤。
- schema 10 新增 `bookmarks` 表；schema 3 刪掉的舊表資料不搬（那時已經升級過的手機早就沒有了）。
