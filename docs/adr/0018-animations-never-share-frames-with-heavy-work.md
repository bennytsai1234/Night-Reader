# 動畫播放時不跑會佔住主執行緒的工作，寧可內容晚一點出現

畫面上有動畫在播（換頁、骨架淡入與呼吸、捲動）時，主執行緒上的重工作要嘛等動畫播完再開始，要嘛切成每一幀都放得下的小塊；不讓一段工作一口氣佔住好幾幀，把動畫卡掉。使用者的判斷是：內容晚一點出現可以接受，看到動畫掉幀不行。

開書照這條規則：

- 載入等開書的換頁動畫與骨架淡入都播完才開始（`ReaderV2Page` 交給 `ReaderV2ControllerHost` 的 `entrance`）。原本閱讀器第一幀畫完就開始，讀目錄、抓正文與排版都疊在換頁動畫上。系統關閉動畫時只等換頁。
- 載入期間排版每幀的上限和甩動捲動一樣是 4ms（`BudgetGovernor` 的 `PumpState.loading`）。原本載入時排版用滿整幀（3fc9570，理由是載入畫面沒有正文、轉圈要維持更新率），但骨架一直在呼吸，用滿整幀時只要哪一步估得不準就掉幀。
- 目錄分批讀（`ChapterDao.getByBook` 一批 200 章，包在同一個交易裡）。查詢本來就在背景執行緒，但結果傳回主執行緒轉成章節是一口氣做完：五千章在電腦上一次佔住主執行緒 3–10ms，手機更久。這個方法所有呼叫端共用，書籍詳情、下載與書架檢查更新也一起受益。

其他地方用同樣兩個做法：

- **頁面等進場動畫播完才載入**（`TransitionSettled.entered`）：書籍詳情、書源管理（等待期間就算載入中，不顯示「尚未加入書源」）、搜尋頁（讀搜尋範圍、書架、分組與紀錄，帶關鍵字進來時讀完才搜尋）。從閱讀器回到書架時，等返回動畫播完（`TransitionSettled.uncovered`）才重排書架。推入新頁的第一幀，Hero 會把新頁放在 offstage 量位置，路由的動畫暫時是「已播完」，所以要等這一幀過去才看得準。
- **背景工作等動畫播完**（2026-10-14 到 10-19）：背景下載每一章開抓前、書架的每一種檢查更新每一本書開始前，等畫面上的動畫（換頁、骨架、捲動、主題暈開、書卡移位等持有的 `MotionGate`）播完。書源的抓取與解析搬進書源 isolate 後（ADR 0028），主執行緒每一章只剩收正文與寫入，使用者決定拿掉，連同閘門本身。這個判斷漏了下載自己的流程：下載不經過 `BookSourceService`，整本目錄的比對、逐章檢查已下載的章節與進度、正文寫入都還在主執行緒，使用者在開 App 書架換場與跳章時看到掉幀（2026-10-19）。改成下載的比對與抓取寫入整段在書源 isolate 做，主執行緒只收章節序號與每章成敗（ADR 0028）。
- **開 App 的背景工作等進場播完**（2026-10-19）：啟動維護、書架補下載與檢查更新、App 更新檢查、排版快取清理，原本書架讀完就開始，那一刻正是書架換場開始；改成等 `LaunchEntrance` 整段進場播完、最後一幀畫完（`onFinished`）。重的部分已經搬到背景，使用者仍選了也等進場：檢查完重建書卡、掛角標這些搬不走的工作才不會碰到換場。只在開 App 這一處等，沒有恢復到處都有的閘門。
- **正文切段落與雜湊在 worker 做**（2026-10-19）：`ReaderV2Content.fromRaw`（整章正規化、切段落、編 JSON 算 SHA-1，電腦上一章 7000 字約 2–5ms，第一次 19ms）改在內容轉換 worker 算好傳回。
- **骨架換場不重建內容、書卡一幀建一張**（2026-10-19，用 `test/frame_budget/` 量）：`SkeletonSwitcher` 換場開始與結束時只是自己的動畫狀態變了，原本每次都把整個書架重建一次（電腦 debug 模式約 20–40ms），改成沿用同一個內容元件（`SliverSkeletonSwitcher` 同樣）。換場前在骨架底下建書架內容時，原本一幀建完所有書卡（約 45ms），改成書卡排隊、每幀畫完放行一張（`CoverRevealSlot`），全部建好、封面解碼好才換場；換場晚幾幀開始（一張書卡一幀）。跳章剩下的兩幀（紙下排第一頁、掀紙前建好整個視窗）量到約 8–15ms，沒有再改。
- **從目錄跳章**：點下一章時目錄與選單馬上收起、紙蓋上淡入骨架，等目錄收起與骨架淡入都播完才開始取得正文（`ReaderV2Runtime.jumpToChapter` 的 `settled`）；原本是目錄開著、列上轉圈，等正文排好才收目錄。「目錄收完」以目錄內容從畫面上拿掉為準：`Scaffold.onDrawerChanged` 在收起動畫一開始就發，不能用。
- **主題暈開**：換色讓整個 App 重建的那一幀，蓋圖整張蓋著；圓從下一幀才開始計時，不會一開始就跳一段。

## Considered Options

- **載入照舊一開始就跑，只靠排版的時間預算避開動畫**：排版以外的工作（讀目錄、抓正文）不受預算管，換頁中仍會卡；否決。
- **只延後排版，讀目錄與抓正文照舊先跑**：網路等待本身不佔主執行緒，先跑可以早一點出正文；但讀目錄的轉換、書源規則解析都在主執行緒，一樣會疊到換頁上；使用者選擇全部等動畫播完。
- **載入期間排版維持用滿整幀**：開書快一點，但骨架呼吸會頓；否決。

## Consequences

- 開書時正文比以前晚出現，大約晚一段換頁動畫的時間（平移 0.5 秒、上浮 0.28 秒），排版也比以前慢；書籍詳情、書源管理與搜尋的內容也晚一段換頁動畫。
- 帶 JS 的書源解析仍在主執行緒一口氣做完：閱讀器自己抓沒下載過的章節、已經開始的下載與檢查更新，還有書架檢查更新時「書架」字樣的流光（流光就是在提示檢查正在進行，不能讓檢查等它），都可能頓一下；要根治得把書源引擎搬到背景（`docs/research/source-engine-off-main-isolate.md`，已排進交接的下一次研究）。（2026-10-19 起書源的抓取與解析都改在書源 isolate，見 ADR 0028，這幾個情境不再因為解析書源而頓。）
- 之後新增的載入或背景工作，也照這條規則檢查會不會疊到動畫上。
