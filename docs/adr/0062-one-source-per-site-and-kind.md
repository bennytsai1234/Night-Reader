# 同一個網站、同一類的書源只留一個，匯入時與讀書源清單時自動合併

使用者 2026-11-13：同一個網站的書源就是重複，不必規則完全一樣；匯入時和打開書源管理時都自動清掉。類型不同（同一個網站的小說源與有聲源）不併，使用者在兩個選項裡選了這個。Legado 沒有這個，同一個網站有幾個書源就留幾個；夜讀刻意不同。

## 決定

- **什麼算重複**：書源網址的主機一樣（和書源管理「按域名分組」同一個分法，`m.site.com` 與 `www.site.com` 算兩個：手機版與電腦版的網頁不同，書搬過去讀不了），類型（`bookSourceType`）也一樣。網址不是 http(s) 的不算。規則不看。
- **留哪一個**：沒有「異常」標記的、啟用的、手動排序在前的，最後照網址。只看會同步的欄位：兩台各自合併時留同一個（書架上的書數、最後更新時間各台不同，會讓兩台各留一個、同步後兩個都被刪）。
- **合併做什麼**：書架上的書、搜尋紀錄與快取的正文搬到留下的那個，被併掉的書源自己的分組併過去（校驗標記與「AI 修不好」不併），被併掉的刪掉，連同它們存的登入資料與變數（留下的那個的照舊）。記一筆書源搬家（ADR 0039 的 `movedFrom`）：另一台已經有留下的那一個時，照同一套把併掉的書源與它們的書併過去；那台的書源先被同步刪掉、書還記著它的也搬。
- **什麼時候做**：
  - 匯入書源之後（書源管理、從外部打開的檔案或網址）：匯入結果多一句「合併了 N 個同網站重複的書源」。
  - 書源管理每次讀清單（打開、匯入、校驗或修復做完、同步套用之後）：併了就從底部提示「已合併 N 個同網站重複的書源」。書源校驗、修復這類批次工作在跑、或書源管理正在批次改書源時不併，等它們做完重讀時再併。
- **修復異常書源**不另外合併：AI 修好的規則套到同網站的其他書源之後，它們回到書源管理就被併掉（ADR 0054）。

## 考慮過的做法

- **規則完全一樣才算重複**：使用者 2026-11-13 否決：同一個網站留好幾個沒有用。
- **類型不同也併**：同一個網站的有聲書會被搬到小說源，打不開；使用者選了不併。
- **留書架上的書最多的那個**：兩台的書架不同，各自合併會留不同的那一個。
- **給一顆「合併重複書源」的按鈕，或修復結果頁的「合併同網站重複的 N 個」**：使用者要自動做。

## 後果

- 規則不同的書源被併掉時，書架上用它的書搬到留下的那個；兩個書源解析的網頁格式不同（例如一個抓 API、一個抓網頁）時，那幾本抓不到新章節，要自己換源。
- 留下的那個可能是規則壞了的：同一個網站的書源都帶「異常」時，照啟用與排序挑。
- 書源被自動刪掉，使用者事先不會被問；匯入結果與底部提示寫了併掉幾個。

## 觸點

| 觸點 | 答案 |
|---|---|
| 書源類型 | 照 ADR 0051：類型不同不併 |
| 書源校驗 | 不改校驗；校驗在跑時不併，「異常」標記決定留哪一個 |
| AI 修書源 | 照 ADR 0054：修好、套用到同網站之後由這裡併，結果頁不另外合併 |
| 要登入、要網頁驗證 | 留下的那個的登入資料照舊，被併掉的刪掉 |
| 付費章節 | 不適用 |
| 搜尋、發現 | 同一個網站只搜一次；不改介面 |
| 換源 | 少了同網站的重複來源；書搬過去讀不了時照常換源 |
| 匯入手機上的檔案 | 做：匯入書源之後合併，結果寫併掉幾個 |
| 書架、書籍詳情 | 書的來源換成留下的那個（書名旁的來源名稱跟著換） |
| 下載、清除已下載 | 已下載的正文跟著搬；合併時暫停那幾本的下載，搬完再繼續 |
| 檢查新章節 | 照留下的那個的規則 |
| 閱讀器、播放器 | 不適用 |
| 偏好與設定 | 不做成設定（ADR 0030） |
| 進度、統計、書籤、標註、朗讀、通知 | 不適用：書本身不變，只換來源 |
| 同步 | 做：書源搬家紀錄帶著被併掉的網址，另一台照著併 |
| 備份與還原 | 不適用：還原後書源管理讀清單時照樣併 |
| 匯出、和 Legado 互通 | 不適用：匯出的是合併後的書源 |
| `PRIVACY.md`、README、網站 | 不適用 |
| `docs/design/` | 做：`screens.md` 書源管理與匯入的提示 |
| iPhone | 同 Android |
| 自動巡檢 | 不適用：沒有新的資料夾或服務 |
