# 書架上的書，書源被刪掉時在背景自動換源一次

修復異常書源會刪掉網站失效、網站不穩定的書源（ADR 0054），書源管理、發現頁也能刪。書源刪掉後書還在書架上，已下載的章節照常能讀，沒下載的章節與新章節抓不到，書籍詳情寫「目前找不到書源，請先換源後再試」，要使用者自己一本一本換。使用者 2026-11-16 要：刪除照舊立刻刪，夜讀替原本用它的書找替代的書源。

## 決定

- **觸發是「書源被刪掉」，不分從哪裡刪**：修復結果頁、書源管理（一個、多選、依標記清理）、發現頁，與同步跟著另一台刪的，刪完都觸發；刪除本身照舊立刻刪，不先等換源（使用者：「刪除就是刪」）。對象是書架上、書源是刪掉的那幾個的網路書。
- **每本只在書源被刪掉的那一刻找一次**，找不到就維持原狀，之後不再自動找（使用者 2026-11-16 選；否決過匯入或新增書源後再找、每次開 App 都找）。這一版之前就沒有書源的書，更新後第一次開 App 找一次（記一個做過的標記，不逐本記；開始找就記，中途被收掉也算找過）。
- **刪的那一刻記下書，輪到時再看一次**：輪到一本時書源又加回來了、使用者自己換過源、書移出書架了，就不換。開 App 時刪的（同步）先記著，進場播完才開始換。
- **正開著的書等關掉再換**：閱讀器、播放器手上還是舊的書，背景換了源，它存進度時會把舊的那本寫回書架。所以閱讀器、播放器、書籍詳情開著的那本先跳過，關掉時再換那一本。
- **候選與檢查**：只從啟用、沒有異常標記（校驗的狀態標記與「AI 修不好」）、同一類別的書源找（聚合源不算，ADR 0056 照 Legado 只用同一類），書名與作者都要一樣（全形、空白、繁簡不同也算；書沒寫作者的，只認也沒寫作者的），搜法同手動換源（繁簡兩種書名都搜）。換過去之前照手動換源的檢查（書籍詳情、目錄不是空的、讀到的那一章的正文抓得到），再加：讀到的那一章的章名在新目錄裡找得到（忽略繁簡與空白；手動換源對章名也照這個比法）。沒打開過的書，讀到的那一章是目錄上的那一章。手動換源對不到章名時照位置換算，使用者看得到結果、可以再換；自動換源沒人看，對錯了進度悄悄跳到別章，所以對不到就不換。章數不當門檻（合章、舊書源的公告章都會讓章數正常地變少，使用者 2026-11-16），只用來挑：幾個都合格時挑目錄章數最多的，一樣多照書源管理裡的排序。只對章數最多的抓正文，抓不到才換下一個。
- **搜的時候進度變了照新的再對一次**：搜全部書源要一兩分鐘，這段時間同步可能改了進度；換之前重讀這本書，讀到的那一章變了就照新的進度重找一次，分組、封面、閱讀設定這類照最新的寫回。
- **換過去的那本已經在書架上就不換**（從那個書源加過同一本）：換了會蓋掉那本的進度、書架少一本，兩本都留著給使用者自己決定。
- **候選出錯只跳過它**：一個書源搜不到、抓不到，或出了沒預期的錯（記進日誌），都只跳過那一個，不讓整本書放棄；背景沒人看，放棄了這本就不會再找。
- **換源照手動換源的做法**：閱讀進度、書籤、標註搬過去，新書源讀到的那一章先存，舊書源的正文刪掉，之後書架自動下載從新書源整本重抓（ADR 0008）。
- **靜默**：跑的時候照背景工作有進度通知（Android 規定前景服務要有通知，ADR 0058），做完收掉，不寫結果、不做結果頁（使用者 2026-11-16）；換不到的書在書籍詳情照舊提示換源。通知只有「結束」，點通知不開任何頁面；不為它要通知權限（刪書源時不跳出權限詢問），沒給權限的就看不到通知。
- **排隊，ADR 0058「一次只跑一件、不做排隊」的例外**：刪除時有別的背景工作在跑（校驗、修書源、AI 找書），等它做完再開始；它佔著位置時其他幾件的入口照 0058 灰掉。前一件做完時通知不收、直接換成自動換源的，前景服務一直開著：夜讀那時不在前景的話，Android 不讓它重開前景服務。最常見的是修復結果頁按刪除，那時修書源已經做完，不用排。

## 考慮過的做法

- **刪之前先換源，換不到的書源留著**：刪除變成有時立刻刪、有時要等背景工作；使用者要刪除就是刪。
- **做完只寫數字的通知、或通知加結果頁**：使用者選靜默。
- **只套用在系統建議刪的書源**：手動刪掉有書在用的書源時，那幾本一樣讀不到；觸發改成「書源被刪掉」就不用分。
- **章數不少於原本才換**：見上，章數正常也會變少。
- **保留舊書源已下載的正文，新書源只補沒下載的章，使用者打開確認後再清**：自動換源沒人挑書源，舊下載能離線讀。使用者 2026-11-16 否決：換源就是因為原本的書源品質不好，舊的正文順便刪；留著的話一本書的正文一半舊、一半新，分章與文字版本可能對不上。

## 觸點

| 觸點 | 答案 |
|---|---|
| 書源類型、匯入時怎麼分 | 不適用：只照書的類別找同類的書源 |
| 書源校驗怎麼判斷抓得到 | 不適用：候選排除有異常標記的書源，判斷照校驗留下的標記 |
| AI 修書源 | 做：修復結果頁刪掉網站失效、網站不穩定的書源後觸發 |
| 要登入、要網頁驗證 | 照 ADR 0038：背景不等人，候選書源要登入或網頁驗證才抓得到時跳過這個候選 |
| 付費章節 | 照 ADR 0057：標了「付費」的書源不當候選；讀到的那一章是付費章節時正文檢查不過，跳過 |
| 搜尋 | 做：搜法同換源，不存進搜尋快取（同 ADR 0060 找書的理由） |
| 發現 | 做：發現頁刪書源也觸發；發現本身不適用 |
| 換源 | 做：照手動換源（ADR 0053 同類別才算同一本、0056 聚合源），加上面兩條 |
| 手機上的檔案匯入 | 不適用 |
| 書架、書籍詳情 | 不做：書卡不加標記；換不到的照舊提示換源 |
| 下載、清除已下載 | 照手動換源與 ADR 0008：舊正文刪掉，新書源整本重抓；有聲書照手動換源 |
| 移出書架、檢查新章節 | 不適用：換好之後照新書源檢查 |
| 閱讀器、播放器 | 做：開著的那本不換，關掉時再換（閱讀器、播放器不接 `AppEventBus.bookSwitched`，開著時換了會被它存進度寫回舊的那本） |
| 偏好、設定 | 不做：沒有開關（ADR 0030） |
| 進度、閱讀統計、書籤、標註、朗讀 | 照手動換源：進度、書籤、標註搬過去；統計照書名記，不受影響 |
| 通知、鎖定畫面 | 做：照 ADR 0058 的背景工作通知，做完收掉 |
| 同步 | 照 ADR 0039：書換到新書源照常同步，新的贏；同步跟著刪的那台也觸發，候選照同步過的書源排序挑，兩台多半挑到同一個 |
| 備份與還原、匯出、和 Legado 互通 | 不適用：「更新後找過一次」的標記只存這台，不進備份、不同步 |
| `PRIVACY.md` 與「隱私說明」 | 不改：只向書源的網站送請求，同手動換源 |
| `README.md`、網站、`GLOSSARY.md` | 不做 README 與網站（靜默的改進）；`GLOSSARY.md` 做：加「自動換源」 |
| `docs/design/` | 不適用：沒有新畫面；通知用 0058 的寫法 |
| iPhone | 照 ADR 0058：離開夜讀被系統收掉時沒做完的不接著做 |
| 自動巡檢 | 做：新的服務檔排進分段 |
| 小說、漫畫、有聲、本地書 | 三類網路書都換（正文檢查照各自的「抓到」標準）；本地書不適用 |

## 後果

- 一本書要在全部書源裡搜一次，589 個書源約 80 到 95 秒（ADR 0060 量的），一次刪掉很多書在用的書源時，背景工作會跑很久；一本一本換，不同時搜好幾本，閱讀時抓章不被擠掉。
- 換不到的書不會再自動找；網站後來恢復或匯入了新書源，要使用者手動換源。
- 通知只有「結束」：按了或被系統收掉時，還沒輪到的書也算找過，不接著做（要接著做得逐本記，和「只找一次」不用逐本記的取捨相反）。等著關掉再換的書也一樣，關掉夜讀之前沒關的就不再找。
