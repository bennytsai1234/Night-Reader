# AI 服務相容：各家服務的工具呼叫與思考送回

AI 修復、AI 找書與「測試連線」接各家 OpenAI 相容服務時，哪些會壞、怎麼修。2026-11-23 讀程式、對照各家官方文件與論壇回報整理；沒有實跑（這台沒有金鑰）。只動手做標「已定」的。

## 1. 一律由模型決定要不要呼叫工具（已定，提議 B）

- **改前**：每次都強制呼叫工具（`tool_choice: required`）。DeepSeek 官方 API 思考模式預設開，強制呼叫工具回 400（官方文件），夜讀又沒有關思考的選項，第一輪就失敗、測試連線也不過；Ollama 不支援強制。強制的理由是迴圈沒有「用文字回答」的結局（交出與放棄都是工具），ADR 0054 舉的實跑證據講的其實是「要帶工具清單」，強制與不強制沒有比過。
- **改後**：請求照樣帶工具清單，不送 `tool_choice`（各家預設都是由模型決定）。系統提示寫明每次回覆都呼叫工具、結束只能用交出或放棄的工具；模型用文字寫結論、沒呼叫工具的那輪照現有的「這一輪沒有呼叫工具」接回對話，連續 3 輪整件重跑。改 ADR 0054。

## 2. 服務附的額外資料原樣保存、原樣送回（已定）

- **改前**：工具呼叫上的額外欄位（Gemini 直連的思考簽章，`extra_content`）與整則回覆的完整思考資料（OpenRouter 的 `reasoning_details`）收到就丟。Gemini 3、4 官方規定工具呼叫的簽章要送回，少了回 400：第二輪一定失敗。
- **改後**：兩種都照收到的樣子存進對話、下一輪原樣送回，修復紀錄的存檔與續跑也帶著；串流分段送來的照各家的拼法接起來。

## 3. 串流的工具呼叫照 OpenAI 官方套件的方式拼（已定）

- **改前**：沒標第幾個呼叫時照「這一段裡第幾個」放，分在不同段的兩個呼叫會被接成一個；呼叫的編號與名稱接在後面，服務每段都重送時名稱變成 `fetchfetch`。
- **改後**：有標第幾個照標的；沒標時看呼叫編號，新編號開新的一個；編號與名稱用換的，參數用接的。

## 4. 測試連線的第二步也帶工具清單（已定）

- **改前**：第二步對話裡已經有工具呼叫，請求卻沒帶工具清單；Anthropic 這類服務規定兩者要一起出現。
- **改後**：第二步帶同一份工具清單、不強制呼叫，和實際使用送的一樣。

## 5. OpenAI 官方改走 Responses 介面（已定）

- **改前**：GPT-6 Astra、GPT-6.1 Sol 在 `chat/completions` 不支援工具呼叫（OpenAI 官方文件），選了只看到「AI 服務出錯（400）」；其他 OpenAI 模型的思考不會回給夜讀，下一輪要重想。
- **改後**：服務網址是 OpenAI 官方時改走 `responses`：工具、工具結果、思考（不存在 OpenAI 那邊，加密的思考原樣送回）都照那套介面的格式；其他服務照舊走 `chat/completions`。

## 6. 思考空的那輪也送思考欄位（已定）

- **改前**：一輪的思考是空的就不送 `reasoning_content`；DeepSeek 思考模式規定每一輪都要送回，Kimi 有人少了這個欄位被拒。
- **改後**：對話裡有任何一輪帶過思考時，每一則 AI 的回覆都送這個欄位，空的送空字串；從沒帶過思考的服務照舊不送。

## 7. 沒有欄位的工具參數補上欄位（已定）

- **改前**：「改書源的內容」與「看書架」的參數是沒有列欄位的物件，舊版 Gemini 會拒絕這種寫法（論壇回報，不確定現在還會不會）。
- **改後**：「看書架」沒有參數就不送參數格式；「改書源的內容」列出書源有的欄位與各段規則的項目。

## 驗證

每一家的回覆格式（DeepSeek、Gemini 直連、OpenRouter、OpenAI Responses、Ollama、Anthropic）用模擬服務的測試蓋到：送出的內容、串流拼接、送回的額外資料、拒絕強制後的重送。實跑用 OpenCode Go；DeepSeek 官方、Gemini、OpenAI 要使用者給金鑰才實測。
