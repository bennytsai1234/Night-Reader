# 對照 Legado：文字書的閱讀

`docs/proposals/roadmap.md` 第 4 項的閱讀這一半：夜讀已經有的功能，一個一個對著 Legado 的實作看。結論五種：**一樣**、**結果不對**（同樣的書、同樣的操作，Legado 對、夜讀不行，之後直接修）、**少一個選項**（使用者勾了才做）、**刻意不同**（寫在 ADR 或 `DESIGN.md`）、**有更好的做法**（使用者挑）。只讀、只列，不修。

- 範圍：替換規則、文字閱讀器的目錄、閱讀進度、書籤、朗讀、選字、正文整理、閱讀器選單與設定裡會影響讀到什麼的選項、本地 TXT 與 EPUB、備份與還原和 Legado 互通。
- 不對照：正文排版、翻頁方式、介面長相與動畫、漫畫、有聲書、同步、三個 AI 功能；書源的抓取、登入、換源、下載在另一份（書源那一半）。
- 讀的版本：夜讀 `fff55f9c`（`beta`），Legado `2fe3ef80`（使用者的 fork，2026-08-24）。
- 下面的出處，夜讀寫 `lib/...`，Legado 寫 `legado:` 加 `app/src/main/java/io/legado/app/` 底下的路徑。

## 結果不對

輕重：**資料少了或錯了**、**功能結果錯**、**少數情況才碰到**。

### 替換規則

#### R3　「替換為」寫 `@js:` 的規則，夜讀把 JS 原文貼進正文（功能結果錯）

- 讀者會看到：從 Legado 匯入的淨化規則裡，「替換為」是 `@js:` 開頭的那幾條（用一段 JS 算出要換成什麼，例如把數字轉成中文），每對到一處，正文裡就多出一段 `@js:result.replace(...)` 這樣的程式碼。
- Legado：「替換為」以 `@js:` 開頭時，每個對到的地方把對到的字放進 `result` 跑那段 JS，用回傳值替換（`legado:utils/RegexExtensions.kt:26-50`）。
- 夜讀：「替換為」整段照字面處理，只認 `$0`～`$n`（`lib/core/models/replace_rule.dart:97-126`）；全 repo 的替換規則程式沒有處理 `@js:` 的地方。
- 什麼情況碰到：匯入含這種規則的規則包，且規則是正則（Legado 只在正則規則認 `@js:`）。

#### R2　規則寫了 `\p{…}` 就什麼都對不到；「替換為」少兩種寫法（功能結果錯）

- 讀者會看到：淨化規則裡常見的 `\p{P}`（任何標點）這類寫法，在 Legado 對得到、在夜讀一處都對不到，規則靜靜地沒作用。
- Legado：規則直接交給 Java 的 `Pattern`，`\p{P}`、`\p{IsHan}` 一律有效（`legado:data/entities/ReplaceRule.kt:76-78`）。
- 夜讀：規則轉成 Dart 的正則時只在規則開頭寫了 `(?u)` 才開 Unicode（`lib/core/engine/parsers/java_regexp.dart:34-40`）；沒開時 Dart 把 `\p{P}` 當成字面的「p{P}」。實測 `'你好，世界！'.replaceAll(RegExp(r'\p{P}'), '#')` 一個都沒換，加上 `unicode: true` 才換。Java 的 `\p{IsHan}`、`\p{InCJK…}` 這類寫法 Dart 開了 Unicode 也不認，要另外換成 `\p{Script=Han}` 之類。這支轉換書源規則也在用，書源那一半可能也會列到。
- 「替換為」：Java 的替換字串還認 `${名稱}`（具名群組）與 `\` 跳脫下一個字（`\$`、`\\`）；夜讀只認 `\$` 與 `$數字`（`lib/core/models/replace_rule.dart:104-118`），`${名稱}` 原樣留在正文裡。

#### R8　標題規則只改正文上方的章名，頁首頁尾、選單、目錄照舊（功能結果錯）

- 讀者會看到：寫一條作用於標題的規則把「第一章 求月票！」改成「第一章」，正文上方的章名改了，頁首頁尾的章節名稱、上方選單的章節卡、目錄、朗讀時通知欄的標題、書架上「讀到」的章名還是「第一章 求月票！」。
- Legado：章節排版時用套過標題規則的章名（`legado:model/ReadBook.kt:707-716`，頁首頁尾與選單都讀這份），存進書的「讀到」章名時也套（`legado:model/ReadBook.kt:911-915`）；目錄要打開「使用替換」才套（`legado:ui/book/toc/ChapterListAdapter.kt:85`，見 T4）。
- 夜讀：只有正文的章名套標題規則（`lib/features/reader/chapter/reader_content_transformer.dart:768-773`）；頁首頁尾、選單與目錄用 `ReaderChapterInfo.chapterTitleAt`，它只做繁簡轉換、拿的是原章名（`lib/features/reader/screen/reader_chapter_info.dart:53-71`、`lib/features/reader/chapter/reader_chapter_repository.dart:236-238`）。
- 修的時候注意：書的「讀到」章名在夜讀也拿來照章名找章（ADR 0042），存的值要留原章名，只在顯示時套規則。

#### R10　繁簡轉換在規則之後，照轉換後的字寫的規則對不到（少數情況才碰到）

- 讀者會看到：開了「簡轉繁」的人，從 Legado 帶來自己寫的規則（在 Legado 裡照畫面上的繁體字寫的），在夜讀對不到簡體原文，規則沒作用；反過來在夜讀新寫的照原文的規則搬回 Legado 也一樣。
- Legado：先去重複章名、重新分段，再繁簡轉換，最後套替換規則（`legado:help/book/ContentProcessor.kt:131-178`）；章名也是先轉再套（`legado:data/entities/BookChapter.kt:100-140`）。
- 夜讀：先套規則，整章處理完才轉（`lib/features/reader/chapter/reader_content_transformer.dart:1365-1380`）；夜讀自己的選字「隱藏」「替換」照這個順序用原文建規則（`docs/design/reader.md`「選字選單」），所以要改先後得連那邊一起改，或兩種寫法都試。

#### R6　新增的規則不一定排在最後（少數情況才碰到）

- 讀者會看到：刪過規則、或匯入過排序值不連續的規則包之後，從管理頁或替換規則面板「新增規則」，新規則排在中間、和某一條同號，先後不定；兩條規則會互相影響時結果跟著變。
- Legado：存新規則時排序值取目前最大的再加一（`legado:ui/replace/edit/ReplaceEditViewModel.kt:58-60`）。
- 夜讀：管理頁與面板用「目前有幾條」當排序值（`lib/features/reader/features/replace_rule/reader_replace_rule_page.dart:101-103`、`lib/features/reader/features/replace_rule/reader_replace_rule_sheet.dart:290-291`）；選字「隱藏」「替換」已經是最大值加一（`lib/features/reader/use_cases/reader_page_coordinator.dart:277`、`317-320`）。

### 替換規則

- [ ] **R20　調整規則的先後**：Legado 每條有置頂、置底，也能長按拖曳排序（`legado:ui/replace/ReplaceRuleActivity.kt:133-142`、`347`）。夜讀的順序只在新增時決定，之後改不了；兩條規則會互相影響時（例如一條刪廣告、一條修標點）讀者沒辦法調。要補的話：管理頁長按選單加「置頂」「置底」，拖曳排序可以不做。
- [ ] **R19　多選規則一起處理**：Legado 多選後可以一起啟用、停用、置頂、置底、匯出、刪除（`legado:ui/replace/ReplaceRuleActivity.kt:247-253`）。夜讀只能一條一條開關、刪除，匯入一包幾十條的規則之後想整包停用要點幾十次。要補的話：長按進選取，動作只放啟用、停用、刪除。
- [ ] **R16、R17　搜尋與照分組篩選**：Legado 管理頁可以搜尋名稱或分組、照分組篩選、看未分組的（`legado:data/dao/ReplaceRuleDao.kt:25-35`）。夜讀管理頁是一整條清單，規則多時找不到某一條。要補的話：頁首一個搜尋框，分組篩選可以不做。
- [ ] **R18　分組管理**：Legado 可以改分組名、刪分組（`legado:ui/replace/GroupManageDialog.kt`）。夜讀只能一條一條改分組欄。要補的話依附在 R17 之後。
- [ ] **R15　這一章被哪些規則改過**：Legado 閱讀選單「有效替換」列出改到這一章的規則（開了繁簡轉換時另列一項），點了直接編輯（`legado:ui/book/read/EffectiveReplacesDialog.kt:46-63`、`legado:help/book/ContentProcessor.kt:146-167`）。夜讀的替換規則面板只寫這本書啟用了幾條；正文被某條規則改壞時，讀者得一條條關掉試。要補的話：替換規則面板加一列「本章套用了哪些」，點了開編輯。
- [ ] **R14　新書預設套不套替換規則**：Legado 在「其他設定」有「替換淨化預設開啟」（`legado:help/config/AppConfig.kt:472`，預設開）。夜讀的值存在、會同步（`lib/features/settings/settings_provider.dart:76-80`、`lib/core/sync/settings_sync.dart:49`），但沒有任何頁面能改，永遠是開。要補的話預設照舊開，放「閱讀偏好」。
- [ ] **R22　匯入前預覽與勾選**：Legado 匯入規則先列出每一條、已有的同一條預設不勾，可以給這批統一加一個分組（`legado:ui/association/ImportReplaceRuleViewModel.kt:57-82`、`128-138`）。夜讀按下匯入就整包寫進去，同一條（同編號）直接蓋掉這台改過的（`lib/features/association/handlers/association_dialog_helper.dart:134-153`）。書源匯入已經有預覽（同檔 `102-106`），要補的話照書源那一套，已有的預設不勾。
- [ ] **R23　匯出規則**：Legado 可以把選到的規則匯出成 JSON 分享（`legado:ui/replace/ReplaceRuleActivity.kt:253`）。夜讀沒有匯出，規則只能跟著備份與同步走。要補的話：寫 Legado 讀得懂的格式，布林值寫 `true`／`false`（夜讀現在的 `ReplaceRule.toJson` 寫 `1`／`0`，`lib/core/models/replace_rule.dart:152-167`，Legado 用 Gson 讀布林值會失敗）。
- [ ] **R21　複製、貼上一條規則**：Legado 編輯頁可以把這條規則複製成 JSON、從剪貼簿貼一條進來（`legado:ui/replace/edit/ReplaceEditActivity.kt`、選單 `replace_edit.xml`）。夜讀要分享一條規則只能整份備份。要補的話併進 R23 一起做。

## 拿不準

- **R14　本地 EPUB 預設套不套替換規則**：Legado 本地 EPUB 與漫畫書預設不套（`legado:data/entities/Book.kt:200-210`），理由是 EPUB 正文是 HTML、通常也沒有廣告；夜讀只有漫畫、有聲書預設不套，EPUB 照常套（`lib/core/models/book/book_extensions.dart:105-111`）。夜讀的 EPUB 匯入時已經轉成純文字（ADR 0032），套規則不會弄壞標記，但專刪網站廣告的規則可能刪到書裡的字。卡在：這算「同一本書結果和 Legado 不同」要照 Legado 改，還是轉成純文字後本來就該一視同仁。
