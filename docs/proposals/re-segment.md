# 正文亂換行：每本書的「重新分段」與自動修補

網站給的正文亂換行（句子中間斷行、整章擠成一行）時怎麼辦。每一項標「討論中」「已定」「已做」，只動手做「已定」的。

## 現況

- 自動修（ADR 0073，`SemanticParagraphFormatter`）：只接有排版證據的換行：下一行以收尾標點開頭、上一行停在左括號或左引號、「……」「——」被拆開、固定欄寬的硬折行。
- 書的設定 `ReadConfig.reSegment` 從一開始就有（從 Legado 匯入的書會帶著），但 App 裡從來沒有開關；開著時只做一件事：整章只有一行、超過 180 字時照句末標點切開（`ReaderContentTransformer._reSegment`）。
- 這個設定已經跟著書同步（`bookshelf_sync.dart` 的 `_userFields` 有 `readConfig`）、進備份，欄位名稱和 Legado 一樣。
- 正文處理的順序（`_applyRules` → `_processContent`，在內容轉換 worker 裡）：去掉重複章名 → 去掉分頁留下的字 → **重新分段** → 替換規則 → 自動修 → 排版整理（彎引號轉「」）→ 繁簡轉換。選字「隱藏」用的原文（`ruleStageParagraphs`）走同一段，已經傳了 `reSegmentEnabled`。

## 1. 開關放哪（討論中）

**提議**：閱讀器裡加一個「重新分段」開關，存進這本書的 `reSegment`。打開或關掉後照「本書套用替換規則」的做法：存進書、`onReload` 重新載入正文（蓋紙、重排）。位置畫兩張候選給使用者選，淺色、深色各一組：

- 甲：右上角「更多」動作表，和「重新取得本章」放一起（Legado 放在右上角選單、打勾）。
- 乙：替換規則面板，「本書套用替換規則」下面一列（同樣是只管這本書的正文整理）。

| | 改前 | 改後 |
|---|---|---|
| 讀者能不能打開 | 不能 | 能，每本書各自記 |
| 打開後 | — | 這本書每一章重新排；書籤、標註、閱讀位置照新的正文對（和新增替換規則時一樣） |
| 同步、備份 | 已經帶著 | 不用改 |
| 本地書（TXT、EPUB） | — | 一樣有；漫畫、有聲書沒有正文，不適用 |

## 2. 打開後做什麼（討論中）

**提議**：照 Legado 的 `ContentHelp.reSegment`（使用者 fork 的 `app/src/main/java/io/legado/app/help/book/ContentHelp.kt`）移植，位置照舊在替換規則之前（和 Legado 一樣在去重複章名之後、替換與繁簡之前）。Legado 的步驟：

1. 上一行不是用「？。！?!~」收尾（或句末標點加收引號），就接到下一行。
2. 照對白重新切段：引號連著引號、「說道。」這類字後面、冒號引號開始的發言。
3. 引號裡的詞出現兩次以上的記成字典，列舉（“鍋”、“碗”）不切。
4. 段落太長時照句子數拆開，拆不拆用亂數決定。
5. 段落裡所有空白刪掉；照對白狀態改引號方向，缺的收引號補上。

刻意不同的（寫進新的 ADR）：

| Legado | 夜讀 | 理由 |
|---|---|---|
| 第 4 步用亂數 | 用這一段的字算出固定的亂數（明確的雜湊，例如 FNV-1a；不用 `String.hashCode`），機率照 Legado | 同一章每次開都一樣，兩台手機也一樣；否則書籤、標註、進度每次都跑掉 |
| 第 5 步刪掉所有空白 | 只去掉接縫兩邊的空白；段內的中文空白照舊交給排版整理 | 英文單字會黏在一起 |
| 跨空白行接 | 空白行與只有插圖的行仍是段落邊界（ADR 0073 已定），每段空白行之間各自跑 | 插圖與作者刻意空的行不被併掉 |
| 只認 “” 引號、簡體字（问说…道着答、和与或） | 也認「」『』與繁體（問說喊唱叫罵道著答、和與或） | 繁體網站多用「」，照原樣不會切對白；繁簡轉換在最後，這一步看到的是網站原文 |

改引號方向、補收引號照 Legado 做，但先拿「」寫的真網站正文試：方向如果被改錯，改成只照原本的方向。

## 3. 原本「整章一行照句號切」換掉（討論中）

**提議**：Legado 的做法本身就處理整章一行（沒有可接的，直接照對白與句子數切），`_reSegment` 與 `_splitSingleLineByPunctuation` 整個刪掉。

| | 改前 | 改後 |
|---|---|---|
| 整章一行 | 每一句切成一段 | 照對白切，長段照句子數拆，段落長短接近一般小說 |
| 已經開著這個設定的書（從 Legado 匯入） | 只切整章一行的 | 升級後分段變一次，書籤與標註位置照新正文對，只發生這一次 |

## 4. 自動修補上「上一行停在逗號、頓號、分號」（討論中）

**提議**：`SemanticParagraphFormatter` 加一條：上一行以「，、；,;」收尾就接下一行；冒號另外量，「他說：」換行接「「走吧。」」是常見的正常寫法。每個人都套用、不用開關。上一行停在字上、沒有標點的不接（「三天後」、狀聲詞、系統面板、詩分不出來），留給第 1、2 項的開關。

| | 改前 | 改後 |
|---|---|---|
| 「他推開門，」換行「走了進去。」 | 兩段 | 接回一段 |
| 「他說：」換行「「走吧。」」 | 兩段 | 量過再定 |
| 「他推開門走了」換行「進去，」 | 兩段 | 照舊兩段，打開重新分段才接 |

## 5. 驗證（討論中）

- 單元測試：Legado 的幾種情況（斷句接回、對白切段、列舉不切、整章一行）、同一段跑兩次結果一樣、空白行與插圖記號不跨、「」文字、英文空格留著、選字原文與畫面段落一一對應（`selection_source_text_test.dart`）。
- 真網站：照 `docs/agents/environment.md`「書源」抓正文，用 `paragraph_repair_corpus_live_test.dart` 列出每一處合併逐條看。主資料夾 `.local/` 在家裡那台；這台從源倉庫（yckceo.com）下載書源。第 4 項要誤合併很少才放進自動修；第 2 項另外列出打開後每章的段數前後，抽幾章對照 Legado 的結果。
- 長章節在 worker 裡跑多久量一次，不佔畫面執行緒（內容轉換本來就在 worker）。
