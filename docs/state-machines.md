| 階段 | 讀者看到什麼 | 可以走到 | 現在一樣嗎 |
|---|---|---|---|
| 未開始 | 頁面剛推入，推入動畫還沒播完；沒有通知 | 做著 | 一樣 |
| 做著 | 通知：標題、做到哪、「暫停」「結束」；頁面：「暫停｜結束」（校驗在書源管理的狀態列，搜尋在進度那一列） | 正在暫停、正在結束、做完 | 一樣 |
| 正在暫停 | 通知內文「正在暫停…」、按鈕拿掉；頁面「正在暫停…」灰掉，「結束」還能按 | 已暫停、正在結束（結束蓋過暫停）、做完（停不下來的那一步做完就是做完，例如正在存修好的書源） | 不一樣：修書源在這時按結束，紀錄與停在半途的 AI 修復不對（下面兩件 bug） |
| 正在結束 | 通知內文「正在結束…」、按鈕拿掉；頁面「正在結束…」灰掉 | 做完 | 一樣 |
| 已暫停 | 通知收掉、位置空出來；頁面「已暫停」與「繼續｜結束」，別件在跑時「繼續」灰掉；被系統收掉、從最近使用滑掉，下次開 App 也是這裡 | 讀回中、正在結束、做完（修書源與校驗開始新的一件時） | 一樣 |
| 讀回中 | 頁面照舊是已暫停，「繼續」灰掉 | 做著、已暫停（接不下去，例如書源不在了）、正在結束 | 一樣 |
| 做完 | 通知收掉；頁面是結果與「完成」 | 看過結果、頁面都關了才放掉（入口改成開新的一件） | 一樣 |

剪貼簿的 AI 修復另有「等貼回」：不是背景工作、沒有通知，只在修復頁上。

**暫停的回饋要不要一致**：一致，五件都照上表。ADR 0058 定的通知（按了內文變「正在暫停…」「正在結束…」、按鈕拿掉）與 `components.md`「狀態用詞」（按了還沒停好時寫「正在暫停…」「正在結束…」，不能再按、灰掉）本來就是五件共用的規則；讀程式與偵測測試確認五件的頁面與通知已經照做，「只有 AI 找書有正在暫停」是內部旗標的差別，讀者看不到。正在暫停時還能按結束、結束蓋過暫停，照放到背景的搜尋已有的規則，五件一起。

**誰記哪個階段**：工作本身（找書、單一修復、整批、校驗、搜尋）記它自己做著、正在暫停、正在結束、已暫停、做完，因為停不停得下來只有它知道（存修好的書源時停不下來）；頁面那層只記工作不知道的：未開始、讀回中、暫停中按了結束、和工作回來之後是已暫停還是做完。頁面與通知讀頁面那層算出的一個階段，不各自拼旗標。

**不收進階段的**（會和階段同時成立）：

- `_disposed`、`_isDisposed`：物件放掉了，任何階段都可能。
- `_committing`：正在存修好的書源，和做著、正在暫停、正在結束同時成立；是「這一段停不下來」的名字，不是階段。
- `_editing`：做完之後在結果頁刪書源中，只在做完時成立。
- `_seen`、開著的頁數：有沒有人看過結果，和做完同時成立。
- 放到背景的搜尋的 `_abandoned`、`_headerWritten` 與 `search_run.dart` 的旗標：屬於搜尋那個候選，這次不動。

**歷史上因此出錯的**：

- #398：按了停止到結果寫完之間重讀清單，剛做完的校驗結果被當成過期丟掉；原因是看「正在校驗」（`_isChecking`），該看「這一輪還沒做完」（`_runInProgress`）。
- #390 審查：繼續讀回期間按結束，晚到的新工作照樣換上去。
- #390 審查：開 App 讀回時只在等待前檢查，等待後沒再檢查。
- #390 審查：暫停中的修復頁，別件做完「繼續」還是灰的。
- #353：頁面返回時直接釋放還在跑的工作，改成先停止、等結束再關。

查過不算：#358 停止閃退是結束 isolate 的方式（`Isolate.immediate`），和旗標無關。

**重構時查到並修掉的**：

- 單一書源 AI 修復正在存修好的書源時先按暫停再按結束：紀錄先寫「已結束，書源沒有改」、再寫「修好了」。原因是結束看 `_paused` 走「已經暫停好」的捷徑，沒看 `_running`。
- 修復異常書源暫停後（或正在暫停時）按結束：整批收尾了，停在半途的那件 AI 修復仍是「已暫停」，點進去「結束」還能按；正在暫停時整批還在跑就先標成做完。原因同上，捷徑也沒有結束那幾件修復。
- 放到背景的搜尋按了暫停、還在等結果檔寫完時按結束：照開始等之前的判斷停成已暫停，沒寫上結束的那一行，之後還能繼續。原因是等寫檔前就決定了要暫停，等完沒再看一次。
- 校驗正在暫停時，書源管理的狀態列落回上次的摘要、「結束」灰掉，直到暫停好。原因是狀態列只看校驗服務「校驗中」，校驗服務在按暫停那一刻就不算校驗中了，這次校驗卻還沒停好。
- 校驗流程本身出錯（讀書源出錯、記錄這個錯時又讀不到）後，校驗服務一直停在「校驗中」，之後的校驗與登入後的自動校驗都直接回傳舊摘要。原因是例外跳過了收尾。

換結構時自己弄出、合併前修掉的（Codex 審查找到）：按了結束、工作本身做完、頁面那層還在刪存檔時，通知換回「暫停」「結束」；校驗流程出錯時，按了停止的那種也會卡在「停下中」（改前按了停止反而能開始下一輪）。

**改後**：

| 位置 | 改後 |
|---|---|
| 共用 `lib/core/background_work/work_phase.dart` | `WorkPhase`：還沒開始、做著、正在暫停、正在結束、已暫停、讀回中、等貼回、做完 |
| AI 找書、單一書源 AI 修復、修復異常書源 | 各一個 `WorkPhase`，只用到自己有的幾個；做著的那一步看「正在暫停或結束」收手；一段跑完照結果與按了什麼定下一個 |
| 頁面那層 | `_RunStage`：未開始、工作在跑、已暫停、讀回中、暫停中按了結束、做完；`run()` 直接回傳暫停好了還是做完；對外的 `phase` 在工作跑的時候照工作本身；通知的「正在暫停…」「正在結束…」在這裡統一換 |
| 放到背景的搜尋 | `_Settling` 換成 `WorkPhase`（做著、正在暫停、正在結束） |
| 從書源管理按的校驗 | `WorkPhase`：做著、正在暫停、正在結束，跑完記成已暫停或做完 |
| 校驗服務 | `_CheckPhase`：閒著、校驗中、停下中；開始新的一輪要閒著 |

頁面的按鈕列、狀態列與通知只讀階段。工作本身已經停好、頁面那層還在收尾時，頁面讀到它要去的那一頭（正在暫停或正在結束），通知不再更新、等收掉。讀者看得到的差別，都是照階段表把五件拉齊：

- AI 找書正在暫停時按結束：原本「暫停」那列還寫「正在暫停…」、下面又寫「正在結束…」，現在照其他四件，「暫停」灰掉、「結束」寫「正在結束…」。
- 已暫停的搜尋按結束、還在寫結束的那一行時：進度那一列原本仍寫「已暫停」，現在寫「正在結束…」。
- 上面三件修掉的 bug。

改測試的兩處（讀者看不到的舊意思）：沒開始就結束的一批，通知原本寫「正在結束…」；做完的一批原本仍算「按了結束」。現在「正在結束」只在還沒停好時成立。

`PLAN.md` 寫的 `search_provider.dart` 的 `_isSearching`、`_retrying`，#433 搬進 `SearchRun`，成了上表的 `isSearching`、`_retrying`。

「這次搜尋在哪一段」散在四個布林值：送出後還在存紀錄是 `_pending && isSearching`，照條件搜是 `_choosing` 到選好書源為止，重試是 `_retrying`，讀回還沒合併是 `_unmerged`；暫停是 `isSearching` 留著、等 `markPaused` 才放下。頁面再把搜尋頁與背景那件的旗標拼成畫面：進度那一列與頁首「結束」看 `isSearching || isBackgroundPaused`（四處），「暫停」看 `isInBackground && !isBackgroundPausing && !isBackgroundStopping`，文字照 `isBackgroundPausing`、`isBackgroundStopping`、`isBackgroundPaused` 的先後挑。

**歷史上因此出錯的**：

- #30：送出搜尋到引擎真正開始（存紀錄、讀書源清單）這段，`_isSearching` 還沒立起來，閃出「尚未加入可搜尋的書源」，也擋不住重複送出。原因是少了「送出了、還沒開始」這一段，之後補成先立 `_isSearching`。
- #433 審查（提交 `b21d73ec9b`）：還在存搜尋紀錄就放到背景、暫停或結束，存完照樣把書源全送出去。原因同上：那一段沒有名字，補了 `_pending` 與號碼。
- #433 審查（同一個提交）：正在暫停時按結束停成已暫停。原因是 `_pausing`、`_ending` 兩個布林值，收成 `_Settling`（#458 再換成 `WorkPhase`）。
- #444 審查（提交 `47c5fb74a4`）：重試讀書源那段空檔就立著 `_retrying`，這時開始的新搜尋算不到自己的書源總數（失敗那一列「共 N 個」停在上一次的）。改成只包住真正在重試的那段。

查過不算：#442（#437）接回後換類別照舊類別搜，是先組條件、才離開接回的那一次的先後問題，不是旗標組合；#444 其他幾項是條件與範圍怎麼定。

| 階段 | 讀者看到什麼 | 可以走到 | 現在一樣嗎 |
|---|---|---|---|
| 沒在搜 | 還沒搜過是搜尋紀錄；搜過是結果與結果工具列（或空狀態），頁首「搜尋」 | 搜尋中 | 一樣 |
| 搜尋中（搜尋頁自己的） | 進度那一列「正在搜尋 124/396」（剩不到三個時「還在等：…」）與「放到背景」（別的背景工作在跑時灰掉）；頁首紅字「結束」 | 沒在搜（搜完、按結束）、放到背景做著 | 一樣 |
| 放到背景做著 | 進度那一列同上，右邊「暫停」；通知欄同一句 | 正在暫停、正在結束、沒在搜（搜完） | 一樣 |

| 正在結束 | 進度那一列「正在結束…」、不放動作；頁首「結束」 | 沒在搜 | 不一樣：從做著按結束，進度那一列馬上換成結果工具列、頁首「搜尋」，通知欄卻還是「正在結束…」；從已暫停按結束，旁邊還留著灰掉的「繼續」 |

讀者看不到、收在階段裡的：

- 搜尋中、放到背景做著的「送出了、還在存搜尋紀錄」（這時按結束、暫停、開始新的一次就不送書源）、「重試失敗」（「共 N 個」照整次搜尋的書源數）、「接著搜暫停的」（進度接著數）都是一次搜尋（`SearchRun`）內部的段，畫面一樣是搜尋中。
- 放到背景按了暫停之後，搜尋本身已經停下、等結果檔寫完才算暫停好：這段是正在暫停。
- 接回放到背景的那一件、換頁還沒播完：進度那一列照那一件的階段，結果先不放、這一頁還不算看過（`_Attachment`）。讀回的結果還沒合併成卡也收在這裡。

**誰記哪一段**：一次搜尋自己記它在哪一段（還沒搜、讀回還沒合併、送出了在存紀錄、照條件搜、重試、接著搜、暫停時停下等記成已暫停），因為只有它知道每個回報屬於哪一段；暫停、結束、繼續照舊由背景那件（`RepairRun`）記；搜尋頁只記怎麼看著背景那件（還沒、接回了等進場、看著），從這兩邊算出 `SearchStage`。

**不收進階段的**（會和階段同時成立）：

- `_disposed`（三處）：物件放掉了，任何階段都可能。
- 背景那件的 `_abandoned`：接回它的搜尋頁開始了別的搜尋，和做著、已暫停、做完都能同時成立（同上一節的 `_seen`）。
- 背景那件的 `_headerWritten`：結果檔的第一行寫了沒，是檔案的事；做著時可能還沒寫（書源還沒選好），讀回的本來就有。
- 搜尋頁的 `_entered`：進場播完了沒，和每個階段都能同時成立。
- 搜尋引擎的「被整頁蓋住時暫停送出」（`SearchModel.pause`）：和搜尋中同時成立，是另一件事。
- `background`（放到背景了沒）：放到背景時設一次，之後不變，是這次搜尋的模式。

**換源跳過**：`book_detail_change_source_provider.dart` 只有一個 `isSearching`，配「第幾輪」的號碼丟掉舊一輪晚到的結果；沒有好幾個布林值互相牽動，換源面板的「正在切換來源…」（`_isSwitchingSource`）和搜尋中會同時成立。不換結構；途中查到搜尋前幾步出錯會一直轉圈，修了（見下）。

**重構時查到並修掉的**：

- 放到背景的搜尋按了暫停，通知欄換成「正在暫停…」，搜尋頁卻還是「還在等：…」與能按的「暫停」，停好才直接跳成「已暫停」。原因是暫停只停下搜尋（結果、進度都沒變，不通知）、只更新通知欄，頁面聽的兩邊都沒出聲。從 #433 起。
- 重試失敗時有書源不理會取消（網站卡住、規則跑不完），這時開始新的搜尋，新的那次失敗那一列的「共 N 個」停在上一次的。原因是重試中的 `_retrying` 要等重試那一段結束才放下，沒跟著每一次搜尋走；和 #444 審查那件同一個原因，那次只修了讀書源的空檔。
- 換源讀書源或搜尋快取出錯時，面板停在「正在初始化...」一直轉圈，原因也沒寫。出錯處理只包住送書源那一段，前面幾步的例外跳過了收尾。
- 放到背景的搜尋按了結束、還沒停好時（表上「正在結束」那一列）：從做著結束，進度那一列馬上換成結果工具列、頁首「搜尋」，通知欄卻還寫「正在結束…」；從暫停中結束，旁邊留著灰掉的「繼續」。現在兩個入口都寫「正在結束…」、不放動作，頁首「結束」，停好才換成結果工具列，和通知欄同步。

另外放寬了背景搜尋頁面測試等寫檔的時間：同一台機器上還有別的測試在跑時，約十次失敗一兩次。

**改後**：

| 位置 | 改後 |
|---|---|
| 一次搜尋 `search_run.dart` | `_Phase`：沒在搜、讀回還沒合併、存紀錄中、照條件搜、重試、接著搜、暫停時停下。`isSearching`、`isRestoring` 由它算；存完紀錄才開始、只記照條件搜選的書源、不是重試才算書源總數，都看是哪一段 |
| 放到背景的那一件 `background_search.dart` | `_resuming` 與 `_remaining` 收成一個「下一次接著搜什麼」（沒有就不是接著搜） |
| 搜尋頁 `search_provider.dart` | `_holdingResults` 與 `_attached` 收成 `_Attachment`：沒有、接回等進場、看著；頁面拼的五個組合換成 `SearchStage`，進度那一列、頁首「結束」、進度條直接讀它 |
| 換源 | 不換結構（理由見上） |

`_attached` 沒有改成從 `_background` 與 `_holdingResults` 推出來：離開背景那件時兩個都先清掉才放掉它，推出來的值會漏掉「這一頁不看了」，背景那件永遠收不掉。

改測試的五處都是把讀旗標的地方換成讀 `SearchStage`（`isBackgroundPaused` → 已暫停、`showsMoveToBackground` → 搜尋中），意思沒變。
